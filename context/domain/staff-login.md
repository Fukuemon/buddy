# 職員とログイン

職員は、職員の管理の権限を持つ職員が、メールアドレスで先に登録する。職員の身元（ID、メール、所属の事業所、上流のアカウント）は認証のブローカーが持ち、名前、役職、権限は予定の API が持つ（ADR-0017）。

職員は、ブローカーのログインの画面にメールを入れ、その事業所の上流の IdP でログインする。ブローカーは、初回のログインで上流の IdP のアカウント（`iss` と `sub`）を職員に結び付ける。access token の `sub` はブローカーの職員の ID で、予定の API の `users.sub` がこの ID を指す。

- ADR-0017: [職員の身元をブローカーが持ち、権限と業務のデータは予定の API が持つ](../../docs/adr/0017-identity-boundary.md)

## States and Transitions

ブローカーの職員の上流のアカウントの状態を示す。

| 状態 | 意味 | 移る条件 |
| --- | --- | --- |
| 未結び付け | 職員に上流のアカウントが無い | 登録した直後 |
| 結び付け済み | 職員に上流の `iss` と `sub` がある | 初回のログインで、上流の IdP のメールが確認済みで、入れたメールの職員の登録のメールと同じ |

- 結び付け済みの職員は、上流の `iss` と `sub` で照らし、メールを見ない。
- 結び付けた上流のアカウントを外す操作は無い。

予定の API は、トークンの `sub` で職員を引く。`sub` の職員がいなければ、トークンのメールが確認済みのときに限り、組織の事業所の同じメールの `sub` が空の職員に `sub` を書く。ブローカーの access token はメールを持たないので、`users.sub` にブローカーの職員の ID が入っていない職員は 403 になる。

## Invariants

- 1 人の職員は、上流のアカウントを 1 つだけ持つ。同じ `iss` と `sub` を 2 人の職員に結び付けられない。
- 予定の API の `sub` は全ての事業所を通じて一意である。1 人の職員は 1 つの事業所にだけ結び付く。
- メールは事業所の中で一意である。名前は重なってよい。
- トークンの組織に結び付いた事業所が無いか、職員が見つからないか、職員の事業所と組織の事業所が違えば 403 になる。

## Prohibitions

- 確認していないメールで結び付けない。
- 登録されていないメール、止めた職員、2 つの事業所に同じメールがある職員には、事業所を示さず、ログインの失敗と同じ文言を返す。
- 止めた職員にトークンを出さない。
