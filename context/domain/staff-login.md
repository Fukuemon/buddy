# 職員とログイン

職員の管理の権限を持つ職員が、予定の API にメールアドレスを入れて、職員を先に登録する。  
職員の身元（ID、メール、所属の事業所、有効か休職か退職か、上流のアカウント）は ID ブローカーが持ち、名前、役職、権限は予定の API が持つ。  
予定の API は、職員の管理の権限を確認してから、ブローカーの内部の API で職員を登録させる。  
ブローカーが発行した職員の ID は、予定の API が `users.sub` に入れる。  
職員を休職、復職、退職にするときも、予定の API が権限を確認してから、ブローカーの職員を書く。  
職員の名前、電話番号、部署、チームは、職員の管理の権限を持つ職員が予定の API で変える。メールはブローカーが持つので、予定の API では変えない。  
休職の職員は変えられ、退職した職員は変えられない。

職員は、ブローカーのログインの画面にメールを入れ、その事業所の上流の IdP でログインする。  
ブローカーは、初回のログインで上流の IdP のアカウント（`iss` と `sub`）を職員に結び付ける。  
access token の `sub` はブローカーの職員の ID で、予定の API の `users.sub` がこの ID を指す。

- ADR-0017: [職員の身元をブローカーが持ち、権限と業務のデータは予定の API が持つ](../../docs/adr/0017-identity-boundary.md)
- ADR-0018: [職員の停止を、戻せる休職と、戻せない退職に分ける](../../docs/adr/0018-staff-leave-and-retirement.md)

## States and Transitions

ブローカーの職員と上流のアカウントの結び付けの状態。

| 状態 | 意味 | 移る条件 |
| --- | --- | --- |
| 未結び付け | 職員に上流のアカウントが無い | 登録した直後 |
| 結び付け済み | 職員に上流の `iss` と `sub` がある | 初回のログインで、上流の IdP のメールが確認済みで、入れたメールの職員の登録のメールと同じ |

- 結び付け済みの職員は、上流の `iss` と `sub` で照合し、メールを見ない。
- 結び付けた上流のアカウントを外すのは、退職だけである。休職と復職では外さない。

職員の状態。

| 状態 | 意味 | 移る条件 |
| --- | --- | --- |
| 登録の途中 | ブローカーにだけいて、ログインできない | 予定の API がブローカーに登録させた直後 |
| 有効 | ログインでき、予定の API を使える | 予定の API が職員を書き終えた。または休職の職員を復職にした |
| 休職 | ログインできず、予定の API は 403 を返す。戻る予定の日のメモを持てる | 職員の管理の権限を持つ職員が、有効か休職の職員を休職にした |
| 退職 | ログインできず、戻せない。名前、所属、役職、権限が残り、メールと電話番号を消す | 職員の管理の権限を持つ職員が、予定と担当が残らない職員を退職にした |

- 休職は手で始め、手で戻す。戻る予定の日に自動では戻さない。
- 休職の職員を休職にし直すと、戻る予定の日のメモだけを書き換える。
- 休職と退職では、ブローカーが Hydra のログインのセッション、同意、refresh token を取り消す。
  - ログインしている職員は、web が access token を取り直すとき（5 分以内）に、ログインの画面へ戻る。
- 復職した職員は、休職の前に結び付けた上流のアカウントで、そのままログインできる。
- 休職と退職の操作は、その日（事業所の現地の日付）以降の予定、繰り返しの予定、担当の利用者を一覧で返す。予定と繰り返しの予定は、職員が予定の職員、主訪問者、同行者のどれかのもので、キャンセルした予定を含めない。
  - 担当の利用者は、利用中の利用者だけを数え、利用の終了の利用者を含めない（[利用者](patient.md)）。
  - 休職は一覧が空でなくても休職にし、一覧を警告として返す。
  - 退職は一覧が空でなければ 409 で拒み、一覧を返す。管理者は、別の職員に割り振り直してから退職にする。
  - 休職と退職を確定する前に、同じ一覧を、職員を書かずに読める。職員の管理の権限を持つ職員だけが読める。
- 退職では、予定の API は職員のメールと電話番号を消し、ブローカーは職員のメールと上流のアカウントを消す。過去の予定と照合の結果は、残した名前で主訪問者を読む。
- 予定の API は、休職と退職の職員のリクエストを、web が持つ access token の期限を待たずに 403 で拒む。
- 予定の API の職員の一覧は、休職と退職の職員も状態を付けて返す。
  - 予定のカレンダーは、休職と退職の職員を職員の列と絞り込みに出さず、その予定も出さない。
  - 予定の作成と編集の画面は、休職と退職の職員を主訪問者と予定者の候補に出さない。
- 予定の API は、休職か退職の職員を、予定の職員、主訪問者、同行者、利用者の担当に新しく指すと 400 で拒む。
  - 拒む操作は、予定の作成、予定の職員の変更、繰り返しの予定の作成と回の置き換え、利用者の登録、利用者の担当の変更、利用者の利用の再開である。
  - 既にその職員に割り振った予定は、職員を変えずに保存できる。ただし、退職した職員の予定は、今日より前の日付でだけ保存できる。
- 退職では、職員に結び付けた Google カレンダーを、カレンダーを外す操作と同じく外す。取り込み、書き出し、同期が止まり、カレンダーのレコードと予定の対応は残る。退職した職員には、カレンダーを結び付けられない。
- 休職では、Google カレンダーの結び付けを残す。取り込みは、休職の職員の新しい予定を作らず、取り込まない予定として示す。既に取り込んだか書き出した予定への Google の変更は、取り込みと同期で今と同じく当てる。復職すると、結び付け直さずに元どおり動く。

職員は、状態とは別に「訪問するか」を持つ（ADR-0022）。

- 登録したときは「訪問する」である。役職からは決めない。事務の職員を登録するときは、職員の管理の権限を持つ職員が「訪問しない」を選ぶ。
- 訪問しない職員は、予定のカレンダーの職員の列と絞り込みに出ず、その予定も出ない。予定の作成と編集の画面は、訪問しない職員を主訪問者と予定者の候補に出さない。
- 予定の API は、訪問しない職員を、予定の職員、主訪問者、同行者、利用者の担当に新しく指すと 400 で拒む。拒む操作と、既に割り振った予定を職員を変えずに保存できることは、休職の職員と同じである。
- 「訪問する」から「訪問しない」へは、職員の変更（`PUT /v1/users/{user_id}`）で変える。その日以降の予定、繰り返しの予定、担当の利用者が残れば、退職と同じ一覧を付けた 409 で拒む。過去の予定は職員を変えずに残す。
- 「訪問しない」から「訪問する」へは、確認なしで変えられる。
- ADR-0022: [照合を照合の権限で許し、事務の役職を足し、訪問しない職員を予定と担当から外す](https://github.com/Fukuemon/buddy/blob/develop/docs/adr/0022-receipt-check-policy-and-non-visiting-staff.md)

職員がログアウトすると、web のセッションと Hydra のログインのセッションが消える。  
上流の IdP のセッションは消さない。  
ログアウトの後のログインは、ブローカーのメールの入力の画面を通る。  
Hydra は、ログアウトしなければログインのセッションを 12 時間保ち、その間はブローカーの画面を出さずにログインさせる（SSO）。  
ログアウトの後や Hydra のセッションが切れた後のログインでも、上流の IdP のセッションが残っていれば、上流の IdP はパスワードを聞かない。

予定の API は、トークンの `sub` だけで職員を引き、メールで探さない。  
`users.sub` が空の職員はログインできない。

Hydra は、トークンを発行するたびにブローカーに確認する。  
有効でない職員と、上流の IdP でログインしてから 12 時間を過ぎたログインには、トークンを出さない。  
上流の IdP で止めたアカウントは、次の上流のログインで拒まれる。

## Invariants

- 1 人の職員は、上流のアカウントを 1 つだけ持つ。同じ `iss` と `sub` を 2 人の職員に結び付けられない。
- 予定の API の `sub` は全ての事業所を通じて一意である。1 人の職員は 1 つの事業所にだけ結び付く。
- メールは全ての事業所で一意である。ほかの事業所の職員と同じメールは登録できない。名前は重なってよい。
- 退職した職員はメールと上流のアカウントを持たない。同じ人を再び雇うときは、同じメールと同じ上流のアカウントで、新しい職員として登録する。
- トークンの組織に結び付いた事業所が無いか、職員が見つからないか、職員の事業所と組織の事業所が違えば 403 になる。

## Prohibitions

- 確認していないメールで結び付けない。
- 登録されていないメール、休職と退職の職員、メールに当たる有効な職員が 1 人でないときには、事業所を示さず、ログインの失敗と同じ文言を返す。
- 休職と退職の職員にトークンを出さない。
- 退職した職員を有効にも休職にも戻さない。
- 退職した職員の名前、電話番号、部署、チームを変えさせない。退職で残した名前と所属は、過去の予定と照合の結果で読む。
- 職員を、自分で休職と退職にさせない。
- 事業所で職員の管理の権限を持つ最後の有効な職員も、休職と退職にさせない。
  - 理由と、権限を外す操作の同じ規則は、[権限](permission.md) の Prohibitions にある。
- ログアウトで上流の IdP のセッションを消さない。職員の個人の Google からもログアウトさせてしまう。
- 職員の管理の権限を確認せずに、ブローカーに職員を登録しない、休職、復職、退職にしない。
