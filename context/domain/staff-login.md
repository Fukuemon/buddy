# 職員とログイン

職員は、職員の管理の権限を持つ職員が、予定の API でメールアドレスを入れて先に登録する。職員の身元（ID、メール、所属の事業所、有効か停止か、上流のアカウント）は ID ブローカーが持ち、名前、役職、権限は予定の API が持つ（ADR-0017）。  
予定の API は、職員の管理の権限を確認してから、ブローカーの内部の API で職員を登録させ、ブローカーが発行した職員の ID を `users.sub` に入れる。職員を止めるときも、予定の API が権限を確認してから、ブローカーで止める。

職員は、ブローカーのログインの画面にメールを入れ、その事業所の上流の IdP でログインする。ブローカーは、初回のログインで上流の IdP のアカウント（`iss` と `sub`）を職員に結び付ける。access token の `sub` はブローカーの職員の ID で、予定の API の `users.sub` がこの ID を指す。

- ADR-0017: [職員の身元をブローカーが持ち、権限と業務のデータは予定の API が持つ](../../docs/adr/0017-identity-boundary.md)

## States and Transitions

ブローカーの職員の上流のアカウントの状態を示す。

| 状態 | 意味 | 移る条件 |
| --- | --- | --- |
| 未結び付け | 職員に上流のアカウントが無い | 登録した直後 |
| 結び付け済み | 職員に上流の `iss` と `sub` がある | 初回のログインで、上流の IdP のメールが確認済みで、入れたメールの職員の登録のメールと同じ |

- 結び付け済みの職員は、上流の `iss` と `sub` で照らし、メールを見ない。
- 結び付けた上流のアカウントを外す操作は無い。

職員の状態を示す。止めた職員を有効に戻す操作は無い。

| 状態 | 意味 | 移る条件 |
| --- | --- | --- |
| 登録の途中 | ブローカーにだけいて、ログインできない | 予定の API がブローカーに登録させた直後 |
| 有効 | ログインでき、予定の API を使える | 予定の API が職員を書き終えた |
| 停止 | ログインできず、予定の API は 403 を返す | 職員の管理の権限を持つ職員が止めた |

- 職員は自分を止められない。

- 止めると、ブローカーは Hydra のログインのセッション、同意、refresh token を取り消す。ログインしている職員は、web が access token を取り直すとき（5 分以内）に、ログインの画面へ戻る。
- 予定の API は、止めた職員のリクエストを、web が持つ access token の期限を待たずに 403 で拒む。
- 予定の API の職員の一覧は、止めた職員も止めた時刻を付けて返す。予定のカレンダーは、止めた職員を職員の列と絞り込みに出さず、その予定も出さない。

職員がログアウトすると、web のセッションと Hydra のログインのセッションが消える。上流の IdP のセッションは消さない。ログアウトの後のログインは、ブローカーのメールの入力の画面を通る。Hydra は、ログアウトしなければログインのセッションを 12 時間保ち、その間はブローカーの画面を出さずにログインさせる（SSO）。上流の IdP のセッションが残っていれば、上流の IdP もパスワードを聞かない。

予定の API は、トークンの `sub` だけで職員を引き、メールで探さない。`users.sub` が空の職員はログインできない。

Hydra は、トークンを発行するたびにブローカーに確認する。有効でない職員と、上流の IdP でログインしてから 12 時間を過ぎたログインには、トークンを出さない。上流の IdP で止めたアカウントは、次の上流のログインで拒まれる。

## Invariants

- 1 人の職員は、上流のアカウントを 1 つだけ持つ。同じ `iss` と `sub` を 2 人の職員に結び付けられない。
- 予定の API の `sub` は全ての事業所を通じて一意である。1 人の職員は 1 つの事業所にだけ結び付く。
- メールは全ての事業所で一意である。ほかの事業所の職員と同じメールは登録できない。名前は重なってよい。
- トークンの組織に結び付いた事業所が無いか、職員が見つからないか、職員の事業所と組織の事業所が違えば 403 になる。

## Prohibitions

- 確認していないメールで結び付けない。
- 登録されていないメール、止めた職員、メールに当たる有効な職員が 1 人でないときには、事業所を示さず、ログインの失敗と同じ文言を返す。
- 止めた職員にトークンを出さない。
- ログアウトで上流の IdP のセッションを消さない。職員の個人の Google からもログアウトさせてしまう。
- 職員の管理の権限を確認せずに、ブローカーに職員を登録しない、職員を止めない。
