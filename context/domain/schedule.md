# 予定

予定は、1 人の職員の時間の枠である。  
予定は開始の日の予定として持ち、翌日に終わる予定もある。  
繰り返しの予定は [繰り返しの予定](recurring-schedule.md) にある。

## States and Transitions

| 状態 | 意味 | 移る操作 |
| --- | --- | --- |
| 有効 | キャンセルされていない | 作る（`createSchedule`）、回の置き換え（`changeOccurrence`） |
| キャンセル済み | 理由を付けて取り消した。レコードは消さずに残す | 有効な予定のキャンセル（`cancelSchedule`）、繰り返しの予定の回のキャンセル（`cancelOccurrence`） |
| 削除済み | 誤って入れた予定として消した。理由を持たない。予定の一覧、取得、照合に出さない | 有効な予定の削除 |

キャンセル済みから有効に戻す操作は無い。  
削除済みから有効に戻す操作も無い。

削除は、業務上の取り消しのキャンセルと別の操作である。

- 削除できるのは、`buddy_primary` の事業所の、開始の日が今日（Asia/Tokyo）以降の有効な予定だけである。
- 削除の可否は、キャンセルと同じく、予定の職員の予定を編集する権限で判定する（[権限](permission.md)）。
- 削除すると、誰が、いつ、どの予定を消したかを、監査の記録に残す。監査の記録は画面に出さない。
- 回を置き換えた予定を削除しても、元の回に戻さない。その日は除外する日のまま残る。
- `buddy_primary` の事業所の書き出しは、削除した予定の Google の予定を、キャンセルと同じく消す。
- 繰り返しの予定の回の削除は [繰り返しの予定](recurring-schedule.md) にある。
- ADR-0040: [誤って入れた予定を、キャンセルと別の削除で消し、開始の日が今日以降の有効な予定に限り、監査の記録だけを残す](../../docs/adr/0040-schedule-deletion.md)

有効な予定は、変更（`updateSchedule`）で枠を丸ごと置き換える。  
一部の項目だけを変える操作は無い。

## Invariants

- 日付は必須で、開始の日である。
- 終了が翌日の印が無い予定は、終了の時刻が開始の時刻より後である。
- 終了が翌日の印がある予定は、終了の時刻が開始の時刻より前で、日付の翌日のその時刻に終わる。
  - 翌日の 0:00 に終わる予定は、終了の時刻を 0:00 にして印を付ける。
  - ADR-0033: [日をまたぐ予定を、開始の日の予定に「終了が翌日か」の印を付けて持ち、取り込み、カレンダー、照合で扱う](../../docs/adr/0033-overnight-schedule.md)
- 開始と終了の時刻が同じ予定は、24 時間になるので持てない。
  - 予定の長さは 24 時間未満である。
- 種類は通常か訪問である。
  - 通常の予定はタイトルを持ち、訪問の情報を持たない。
  - 訪問の予定は訪問の情報を持つ。
- 時間外の勤務の印は、開始の時刻が 17 時以降なら付く。
  - 入力では受けず、開始の時刻から決める。
- キャンセルの理由は、空白だけにできず、255 文字以内である。
- 1 つの予定に付くキャンセルは 1 つだけである。
- 回の置き換えで作った予定は、元の繰り返しの予定を指し、変更しても指したままである。
- 事業所の予定の正本は、事業所の正本のモードで決まり、1 つの事業所に正本は 1 つだけである。
  - `google_primary` の事業所は Google カレンダーが正本で、予定の API は buddy の予定のテーブルに予定を作れず、変えられず、キャンセルできない。
    - 予定の API は、繰り返しの予定の作成、回の置き換え、回のキャンセル、手動の取り込みを 409（code は `google_primary`）で拒む。
    - 予定の API は、単発の予定と回の削除も拒み、画面は削除の操作を出さない。キャンセルが Google の予定を消すので、一覧でキャンセルと誤入力を区別できない問題が起きないためである（ADR-0040）。
    - 単発の予定の作成は、予定の職員のカレンダーに Google の予定を作り、Google が受けたときだけ成功を返す。予定の職員に外していないカレンダーが無ければ、409（code は `calendar_not_linked`）で拒む。
    - 単発の予定の変更とキャンセルは、画面が読んだ予定の etag を付けて Google の予定を書き換えるか消し、Google が受けたときだけ成功を返す。読んだ後に Google で予定が変わっていれば、409（code は `google_event_changed`）で拒む。
    - 予定の職員を替えると、予定を新しい職員のカレンダーに移す。
    - キャンセルの理由は、Google の予定に書けないので保存しない。キャンセルした予定は一覧に出さない。
    - `open` の切り替えがある間は、単発の予定の作成、変更、キャンセルも 409（code は `cutover_open`）で拒む。
  - `google_primary` の事業所で buddy の予定のテーブルに予定を作れるのは、事業所に `open` の切り替えがあるときの、切り替えの取り込みだけである。
    - 切り替えの取り込みの期間は、切り替えの月の初日から先の全てで、終わりを持たない。
    - 切り替えの間も、予定の一覧と照合は Google カレンダーの写し（Projection）を読み、切り替えの取り込みで作った予定を出さない。
    - 切り替えの間に取り込み直すと、取り込んだ後に Google で変わったか消えた予定の写しを消し、Google の今の内容で取り込み直す。
  - Google カレンダーへ書き出すのは、`buddy_primary` の事業所の予定だけである。
    - `buddy_primary` でない事業所の書き出しの待ちは、書かずに確認が必要な待ちにして保留にする。
  - 新しい事業所のデフォルトのモードは `google_primary` である。
  - 1 つの事業所に、`open` の切り替えは 1 つまでである。
    - 切り替えは `open` から、`completed` か `canceled` に移り、戻らない。
    - 事業所の正本のモードが `google_primary` から `buddy_primary` に移るのは、切り替えを完了したときだけである。逆には移らない。
    - 完了できるのは、次の 3 つを全てのカレンダーで満たすときだけである。
      - この切り替えで取り込み、最後の取り込みの後に同期が成功している。
      - 切り替えの月の初日より後に終わる Google の予定が、全て取り込んだ予定か、取り込まないと決めた予定である。
      - 取り込んだ後に、Google で予定が変わっていない。
  - `buddy_primary` の事業所は buddy が正本で、Google カレンダーでの変更を予定に取り込まない。
  - ADR-0029: [Google カレンダーとの連携を、事業所ごとの正本のモードで分ける](../../docs/adr/0029-google-calendar-sync.md)
  - ADR-0031: [事業所の予定の正本を、期間のある切り替えの記録で Google カレンダーから buddy へ移す](../../docs/adr/0031-calendar-cutover.md)

## Prohibitions

- キャンセル済みの予定を変えない。
  - 変えようとすると 409 になる。
  - キャンセル済みの予定も削除しない。キャンセルは戻せない業務の記録で、削除で消せるとキャンセルの一覧を信用できなくなるためである。回をキャンセルした単発の予定も同じである。
- 開始の日が今日（Asia/Tokyo）より前の予定を削除しない。照合が読む過去の予定を変えないためである。
- 予定を、監査の記録を残さずに消さない。
  - 業務上の取り消しはキャンセルで、入力の誤りは削除で表す。
  - 例外として、切り替えをやめるときと、切り替えの間に取り込み直すときは、切り替えの取り込みで作った予定を消す。切り替えの間は buddy から予定を書けず、消す予定は Google カレンダーの写しだけである。
- 繰り返しの予定そのものをキャンセルしない。
  - キャンセルできるのは単発の予定だけである。
  - 繰り返しの予定の 1 回のキャンセルは、回をキャンセルした単発の予定にする（[繰り返しの予定](recurring-schedule.md)）。
