# 照合

照合は、ある月の予定と実績を対にし、4 つの区分に分ける。規則の細部と元の実装との違いは [レセプトの照合の Design Doc](../../apps/receipt-api/DesignDoc.md) にある。

## States and Transitions

| 区分 | 条件 |
| --- | --- |
| 予定のみ | 対になる実績が無い |
| 実績のみ | 対になる予定が無い |
| 整合 | 開始時間が同じ、サービス内容が対応、予定と実績の時間と提供時間が許容範囲、加算が「通常」だけ、の全てを満たす |
| 不整合 | 両方があり、整合の条件を 1 つでも外れる |

- 予定は、予定の CSV があればそれを、無くて対象の月があれば Google カレンダーから取る。どちらも無ければ誤りにする。

## Invariants

- 対のキー（訪問日、利用者名、主訪問者）が同じものだけを対にする。同じキーが複数あれば、開始時間の差が小さい組から対にする。
- 許容範囲を持たないサービス内容は、範囲の判定に通らず不整合になる。
- 不一致の印、注意の印、CSV の書き出しは画面が作る。API は判定の結果の JSON だけを返す。
- 実績がある行で加算が無いときは、加算の欄を空欄にする。「データなし」は、片側が無い行の無い側の欄にだけ出す。

## Prohibitions

- 入力の CSV と照合の結果を保存しない。
- Google カレンダーの予定のうち照合に使わなかったものを返すときに、題名を返さない（利用者名を含むため）。
