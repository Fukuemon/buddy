# 権限

権限は、職員ができる操作とその対象を表す。  
権限を持つ方式は、ADR-0041 で決めた。  
この文書は業務の規則を持つ。  
判定の仕組みは、[権限の Design Doc](../../services/schedule/internal/access/DesignDoc.md) が持つ。

- ADR-0041: [権限を役職のデフォルトと職員ごとの上書きで持ち、役職を変えても職員ごとに足した権限を残し、職員の管理と照合も権限で許す](../../docs/adr/0041-pbac-grants.md)

## States and Transitions

権限は、予定の 7 つ、職員の管理（`staff.manage`）、照合（`receipt.check`）の 9 つである。  
権限は、事業所ごとには持たない。  
事業所に属さないマスタとしての扱いは、[事業所の分離](facility.md) の Invariants にある。

予定の閲覧と編集は、職員の権限で判定する。  
規則は [権限の Design Doc](../../services/schedule/internal/access/DesignDoc.md#予定の認可) にある。  
判定は [事業所の分離](facility.md) の後に行う。

職員の権限は、権限を足し外す操作のほかに、次の 3 つの操作で変わる。

- 職員を登録したときに、役職のデフォルトの権限を職員にコピーする。
  - チームを対象にする権限は、職員の所属のチームを対象にする。
- 職員の役職を変えたときに、前の役職のデフォルトにある権限を対象ごと消し、新しい役職のデフォルトの権限をコピーする。
  - 前の役職のデフォルトに無い権限は、職員ごとに足した権限として対象ごと残す。
  - 前の役職のデフォルトにある権限は、職員ごとに対象を直していても消す。
  - 職員ごとに足した権限が新しい役職のデフォルトにもあれば、今の権限と対象を残し、デフォルトからコピーしない。
- 職員のチームを変えたときに、職員の権限のうち古いチームを指す対象を新しいチームに移す。
  - ほかのチームの対象は残す。職員ごとに足した権限の対象も、古いチームを指していれば移る。
  - 理由は [権限の Design Doc](../../services/schedule/internal/access/DesignDoc.md#権限のレコード) にある。

役職のデフォルトの権限を変える操作は無い。  
デフォルトを変えるときは、マイグレーションで、その役職の今いる職員の権限にも明示して広げる。  
事業所の管理者が別のデフォルトを使いたいときは、役職を作って職員の役職を変える。

権限の変更は、次のリクエストから判定に使われる。  
予定の API と照合の API はリクエストのたびに職員の権限を読み、web は画面を読み込むたびに読み直す。

- ADR-0041: [権限を役職のデフォルトと職員ごとの上書きで持ち、役職を変えても職員ごとに足した権限を残し、職員の管理と照合も権限で許す](../../docs/adr/0041-pbac-grants.md)

職員の管理の権限を持つ職員は、次の操作ができる。

- 職員と利用者を登録する。
- 利用者を変え、利用の終了と再開にする。
- 役職とチームを作る。
- チームの名前と色を変える。
- 職員ごとに権限を足し、外す。
- 職員の役職を変える。

職員の管理の権限を持つ職員は、自分に任意の権限を足せるので、職員の管理の権限は事実上の最上位の権限である。  
配れる権限に上限は無く、自分の権限を足し外す操作と、自分の役職を変える操作も止めない。  
誤りと乱用は事前に止めず、監査の記録で後から追う。  
操作ごとの許可と拒否の表は ADR-0041 にある。

- ADR-0041: [権限を役職のデフォルトと職員ごとの上書きで持ち、役職を変えても職員ごとに足した権限を残し、職員の管理と照合も権限で許す](../../docs/adr/0041-pbac-grants.md)

チームの作成を職員の管理の権限に含めるのは、チームがチームを対象にする権限の範囲を決めるためである。  
ADR-0041 の、権限を配れる操作を職員の管理の権限に限る判断を当てはめた。

照合の権限を持つ職員だけが、照合と照合の結果を扱える。  
照合の権限は、マネージャーと事務の役職のデフォルトにある。  
職員の管理の権限を持つ職員は、ほかの職員にも照合の権限を足せる。  
照合の権限を持つ職員は、事業所の全ての利用者の名前を含む実績と照合の結果を扱える。

- ADR-0041: [権限を役職のデフォルトと職員ごとの上書きで持ち、役職を変えても職員ごとに足した権限を残し、職員の管理と照合も権限で許す](../../docs/adr/0041-pbac-grants.md)

職員の権限を変える操作と、運営者の登録の操作は、予定の API の DB の監査の記録に残す。  
操作は、職員の登録、権限を足す、権限を外す、役職を変える、チームを変えて対象を移す、役職を作る、運営者の事業所と最初のマネージャーの登録である。  
記録は、操作した職員か運営者、対象、変更の前後の権限の全量、時刻、相関 ID を持ち、職員と利用者の名前とメールを持たない。  
記録は画面に出さず、消さず、書き換えない。

- ADR-0042: [権限の変更を、操作した職員か運営者と変更の前後の権限の全量で、予定の API の DB の監査の記録に残す](../../docs/adr/0042-permission-audit.md)

## Invariants

- 同じ職員に同じ権限は 1 つだけ付く。
- 役職のデフォルトの権限は重ならない。
- 権限の対象は、職員かチームのどちらか 1 つである。

## Prohibitions

- 判定に役職を直接使わない。
  - 判定は職員の権限（`user_policies`）だけを読む。
- 事業所で職員の管理の権限を持つ最後の有効な職員から、その権限を外させない。
  - 権限を外す操作と、変更の後に職員の管理の権限が残らない役職の変更の両方で拒む。
  - 戻す操作をする職員がいなくなると、DB を直すほかに戻せないためである。
  - 休職と退職も同じ規則で拒む。休職と退職の規則は [職員とログイン](staff-login.md) にある。
  - ADR-0004: [職員の停止を、戻せる休職と、戻せない退職に分ける](../../docs/adr/0004-staff-leave-and-retirement.md)
