# 利用者

利用者は、事業所が訪問する相手である。  
利用者は、名前、受けているサービス、希望する訪問の時間帯と担当の性別、担当の職員を持ち、連絡先は持たない。  
決定の背景は ADR-0021 にある。

- ADR-0021: [利用者を、戻せる利用の終了にでき、終了の利用者を予定の候補と職員の退職の確認から外す](../../docs/adr/0021-patient-service-end.md)

## States and Transitions

| 状態 | 意味 | 遷移を起こす操作 |
| --- | --- | --- |
| 利用中 | 予定の利用者に指せ、担当の職員の退職の確認で数える | 利用者の登録か、利用の終了の利用者の利用の再開 |
| 利用の終了 | 予定の利用者に新しく指せず、担当の職員の退職の確認で数えない | 職員の管理の権限を持つ職員が、その日以降の予定が残らない利用者を利用の終了にした |

利用の終了は手で始め、利用の再開で手で戻す。日付で自動では切り替えない。  
利用の終了の利用者を利用の終了にし直しても成功し、最初に利用の終了にした時刻を残す。

利用の終了の操作は、その日以降の予定か、その日以降に終わる繰り返しの予定が残ると、409 で拒み、残る一覧を返す。  
その日は、事業所の現地の日付で決める。  
数える予定は、訪問の情報の利用者がその利用者の予定で、キャンセルした予定を含めない。  
管理者は、残る予定をキャンセルするか、繰り返しを終えてから、利用の終了にする。

利用の再開では、担当の職員を必ず指定する。  
利用の終了の間に、担当の職員が退職していることがあるためである。

## Invariants

- 利用の終了でも、利用者のレコードを消さず、名前、受けているサービス、担当の職員を残す。
  - 過去の予定、Google カレンダーへの書き出し、照合の結果では、残した名前で利用者を読む。
- 利用の終了の利用者を、利用の再開の前と後で同じ利用者として扱い、過去の予定とつなぐ。
- 利用者の一覧は、デフォルトで利用中の利用者だけを返す。
  - `include_ended=true` を付けると、利用の終了の利用者も、利用の終了にした時刻を付けて返す。
  - web の予定の画面は、利用の終了の利用者も含めて取り、過去の予定の利用者名を出す。
  - 予定の作成と編集の画面は、利用の終了の利用者を利用者の候補に出さない。
- 職員の退職の確認と、休職と退職の操作が返す一覧は、担当の利用者のうち利用の終了の利用者を数えない。
  - 職員の側の規則は、[職員とログイン](staff-login.md) にある。
- 利用の終了の利用者も、利用者の変更で変えられる。変えても、利用の終了のままである。
- 利用者の登録、変更、利用の終了、利用の再開は、職員の管理の権限を持つ職員だけができる。
  - 権限の規則は、[権限](permission.md) にある。

## Prohibitions

- 利用の終了の利用者を、予定の利用者に新しく指さない。
  - 予定の API は、予定の作成、予定の利用者の変更、繰り返しの予定の作成と回の置き換えを、400 で拒む。
  - 既にその利用者に作った予定は、利用者を変えずに保存できる。ただし、今日以降の日付にする変更は拒む。利用の終了の利用者に、誰も行かない今日以降の予定を残さないためである。
- 担当の職員を別の職員に変えるときと、利用の再開で担当を指定するときに、休職か退職の職員と、訪問しない職員を指さない。
  - ADR-0022: [照合を照合の権限で許し、事務の役職を足し、訪問しない職員を予定と担当から外す](../../docs/adr/0022-receipt-check-policy-and-non-visiting-staff.md)
  - 予定の API は 400 で拒む。
  - 変更で担当を変えないときは、今の担当が休職か退職か訪問しない職員でも拒まない。予定に既に割り振った職員を、職員を変えずに保存できるのと同じ扱いである。
- 利用の終了の利用者の名前を消す操作は持たない。
