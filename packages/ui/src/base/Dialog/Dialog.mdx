# Dialog

画面の上に重ねて出す、小さい確認と入力のダイアログ。`<dialog>` の `showModal()` で開き、後ろの画面を操作できなくする。中身は `DialogHeader`、`DialogBody`、`DialogFooter` で組む。

## 使う場面

- 理由のような短い入力を 1 つ受けて、元の画面に戻る
- どちらの内容に合わせるかのような、少ない選択肢から操作を 1 つ選ぶ
- 入力のダイアログと確認のダイアログのパターン（`InputDialog`、`ConfirmDialog`）の中身

## 使わない場面

- 予定の作成と編集のような、項目の多い入力（`Modal` を使う）
- 完了の通知
- ナビゲーション

## Do

- 入力と確認のダイアログは、まずパターンの `InputDialog` と `ConfirmDialog` を使い、合わないときだけ `Dialog` で組む
- `DialogHeader` の `titleId` と、`Dialog` の `labelledBy` に同じ値を渡す
- フッターのボタンは、「キャンセル」、確定のボタンの順に渡す
- 送っている間は、`Dialog` に `canClose={false}`、`DialogHeader` に `isCloseDisabled` を渡し、どの操作でも閉じないようにする
- 送れなかったときは、`DialogFooter` の `error` に文を渡す
- 選ぶ操作だけを並べるときは、どれも副のボタンにし、閉じるのは × に任せる

## Don't

- ダイアログの中から別のダイアログを開く
- 確認のダイアログ（`role="alertdialog"`）に × を置く
- 主のボタンを 2 つ並べる

## キーボードの操作

- 開くと、ダイアログの中の最初の押せる要素にフォーカスが移る
- Tab と Shift+Tab はダイアログの中の要素に移る
- Esc で `onClose` を呼ぶ。`canClose` が false の間は呼ばない
- 閉じる（外す）と、開く前にフォーカスがあった要素へ戻る
