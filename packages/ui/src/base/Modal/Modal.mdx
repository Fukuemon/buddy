# Modal

今の画面の上に重ねて出すモーダルのダイアログ。`<dialog>` の `showModal()` で開き、後ろの画面を操作できなくする。

## 使う場面

- 今の画面の上で、予定の詳細や入力を行い、閉じて元の画面に戻る

## 使わない場面

- 完了の通知
- ナビゲーション

## Do

- `title` を渡し、ダイアログの名前にする
- 「キャンセル」と送信のボタンは、この順に `stickyFooter` に置く。入力の無いダイアログでは、「キャンセル」の代わりに「閉じる」を置く
- データを失う操作の起点のボタン（`variant="destructive"`）は、1 つだけフッターの左端に置き、「閉じる」と編集のような安全な操作を右にまとめる
- `stickyFooter` を渡すと、右上の閉じるボタン（×）は出ない。フッターのボタンで閉じる。フッターの無いモーダル（読み込み中、読み込みの失敗）だけに × が出る
- 種類の切り替えのような、ヘッダーに足す要素は `headerContent` に置く。タイトルの右に、右に寄せて置く
- 入力の途中で閉じると変更が消えるときは `isDirty` を渡す

## Don't

- ダイアログの中から別のダイアログを開く
- フッターに操作のボタンを置いたモーダルに、× を足す
- フッターの無いモーダルで、閉じるボタン（×）を消す
- データを失う操作の起点のボタンを、「閉じる」と編集のボタンの間に並べる

DADS はモーダルのダイアログをフォームに使わないとしているが、buddy は予定の作成と編集に使う。理由は packages/ui/design/components.md の「コンポーネントごとの規則」にある。

## キーボードの操作

- 開くとタイトルにフォーカスが移る。タイトルが無ければ、× に移る
- Tab と Shift+Tab はダイアログの中だけを回る
- Esc で閉じる要求（`onCloseRequest`）を出す。閉じるかは呼び出す側が決める
- 閉じると、開いたボタンにフォーカスが戻る
