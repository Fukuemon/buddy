# Button

操作を 1 つ実行するボタン。`variant` で主、副、削除、確定の削除を、`size` で S、M、L を選ぶ。

## 使う場面

- フォームを送る、ダイアログを開くなど、操作を 1 つ実行する

## 使わない場面

- 画面を移る。`Link` に `buttonClassName` を渡してボタンの見た目にする

## Do

- 主のボタン（`variant="primary"`）は、1 つの画面かダイアログに 1 つまでにする
- 入力が条件を満たさない間に押せなくするときは `disabled` にし、押せるようにする条件の文をボタンのすぐ近くに出して、`aria-describedby` でボタンに結び付ける。ダイアログの確定のボタンは、`InputDialog` と `ConfirmDialog` の `submitHint` に条件の文を渡す
- 送っている間と、選択肢やデータを読み込む間は、条件の文を出さずに押せなくし、待ちを `isLoading` か、次の項目の `BusyLabel` で示す
- データを失う操作は、`variant="destructive"` のボタンで確認のダイアログを開き、確認のダイアログの確定のボタンを `variant="danger"` にする。文言は操作の動詞（「外す」「書き直す」）にする
- 文字を読ませたまま待たせるときは、子に `BusyLabel` を渡し、文字の前に回転の印を出す

## Don't

- 主のボタンを並べて、どれが主の操作か分からなくする
- 削除のような取り消せない操作に `variant="primary"` を使う
- 確認のダイアログの外で `variant="danger"` を使う。赤い面は、データを失う操作を確定する 1 か所だけにする
- データを失う操作の起点のボタンを `variant="secondary"` にして、「閉じる」や「編集」の隣に並べる。同じ見た目で隣に並ぶと押し間違える
- `className` で色や角丸を変える

## キーボードの操作

- Tab でボタンに移る
- Enter と Space で押す
- 無効の間は `aria-disabled="true"` にし、フォーカスは受けるが押しても何もしない
- 読み込みの間は `aria-busy="true"` にし、押しても何もしない
