# buddy のデザインシステム

buddy の画面を作る人が、画面を作る前に読むカタログ。
デジタル庁デザインシステム（DADS）のトークンとコンポーネントの指針に基づき、packages/ui のトークンとコンポーネントの使い方を示す。
規則の正本は packages/ui の DESIGN.md にあり、このカタログはその見本である。

- 出典: [デジタル庁デザインシステム](https://design.digital.go.jp/dads/)

## カタログのページ

- **はじめに**: 原則とアクセシビリティの基準
- **トークン**: 色、文字、余白と角丸と影
- **コンポーネント**: packages/ui の Base と Case のコンポーネント。使う場面、使わない場面、Do と Don't、状態、キーボードの操作
- **画面**: apps/web のドメインのコンポーネント

## 画面を作るときの原則

- 色、文字、角丸、影は、`theme.css` のユーティリティだけで書く。色の値と、DADS の変数の名前を、画面のコードに直に書かない。
- 状態を色だけで伝えない。エラー、不一致、注意には、文と印を色と一緒に出す。
- 14px より小さい文字を使わない。本文と操作の文字は 16px にし、14px は補足だけに使う。
- 主のボタン（`variant="primary"`）は、1 つの画面かダイアログに 1 つまでにする。
- フォーカスの表示は `focus-ring` だけを使い、コンポーネントごとに色や太さを変えない。
- 押せる領域は 44×44 CSS px 以上にする。見た目を小さくするときは、見た目の外に押せる領域を広げる。
- 余白は Tailwind の段（1 段 4px）で書く。ブロックの間は 8px の倍数（`gap-2`、`gap-4`、`gap-6`）にする。

## カタログに載せてよいもの

カタログは GitHub Pages に公開し、URL を知る人は誰でも開ける。
story と MDX には、コンポーネントとダミーデータだけを載せる。

- 利用者と職員の名前、事業所、予定は、`青木 一郎` のようなダミーの値にする。
- API を呼ぶ story を作らない。
- URL、ホスト名、シークレットを書かない。
