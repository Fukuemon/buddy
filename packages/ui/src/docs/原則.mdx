# buddy のデザインシステム

buddy の画面を作る人が、画面を作る前に読むカタログ。
packages/ui のトークンとコンポーネントの使い方を、story で示す。規則はデジタル庁デザインシステム（DADS）を元にした。
規則の正本は、packages/ui の DESIGN.md と、design/ のトークン、コンポーネント、カタログの 3 つの文書である。このカタログはその見本である。

- 出典: [デジタル庁デザインシステム](https://design.digital.go.jp/dads/)

## カタログのページ

- **はじめに**: 原則とアクセシビリティの基準
- **トークン**: 色、文字、余白と角丸と影
- **コンポーネント**: packages/ui の Base と Case のコンポーネント。使う場面、使わない場面、Do と Don't、状態、キーボードの操作
- **パターン**: コンポーネントを組み合わせた形。入力のダイアログと確認のダイアログ
- **画面**: apps/web のドメインのコンポーネント

## 画面を作るときの原則

原則の本文と確認の方法は、DESIGN.md の「画面を作るときの原則」にある。
`pnpm check:design` とレビューの指摘は、次の ID で原則を指す。

- `COLOR-TOKEN`
- `STATE-NOT-COLOR-ONLY`
- `TEXT-MIN-SIZE`
- `PRIMARY-ACTION-ONE`
- `FOCUS-ONE`
- `TARGET-SIZE`
- `SPACING-SCALE`
- `LAYOUT-OVERFLOW`
- `MOTION-TOKEN`
- `MOTION-REDUCE`

## カタログに載せてよいもの

カタログは、ドキュメントサイトと同じ場所に公開する。
story と MDX には、コンポーネントとダミーデータだけを載せる。

- 利用者と職員の名前、事業所、予定は、`青木 一郎` のようなダミーの値にする。
- API を呼ぶ story を作らない。
- URL、ホスト名、シークレットを書かない。
