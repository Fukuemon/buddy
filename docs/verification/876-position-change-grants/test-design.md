# 役職を変えても職員ごとに足した権限が残ることの検証の設計

[#876](https://github.com/Fukuemon/buddy/issues/876) の受け入れの条件を、画面と予定の API の判定から確認する検証の設計。  
検証の issue は [#996](https://github.com/Fukuemon/buddy/issues/996) である。  
シナリオは [scenarios.md](scenarios.md) に、エビデンスの一覧は [README.md](README.md) にある。

## 対象範囲

## 処理の流れ

行番号は `01ec0dae` のもの。`-` は変更の前にあって消えた節、`+` は変更の後で足した節。

```diff
  services/schedule/internal/features/staff/change_position.go  ChangePosition.Do
  ├── 職員の管理の権限の確認（guard）                                      :42
  ├── 事業所のロックと職員の読み直し
+ ├── 今と同じ役職なら、何も書かずに今の職員を返す                         :51
  ├── 新しい役職を読み、同じ事業所かを確かめる
+ ├── 前の役職を読む。見つからなければ内部のエラー
+ ├── replaceGrants                                                      :71, :92
+ │   ├── 消す権限 = 前の役職のデフォルトの権限
+ │   ├── 残す権限 = 職員の権限のうち、消す権限に無いもの
+ │   ├── コピーする権限 = 新しい役職のデフォルトのうち、残す権限に無いもの（チームの対象は所属のチーム）
+ │   └── 変更の後に職員の管理の権限が残るか
- ├── 新しい役職のデフォルトに職員の管理の権限が無ければ lastManager
+ ├── 変更の後に職員の管理の権限が残らなければ lastManager                :73
- ├── 職員の権限を全て消し、新しい役職のデフォルトをコピーする
+ ├── 消す権限だけを対象ごと消し、コピーする権限を足す
- ├── 変更の前後の権限が同じなら記録を書かない
  └── 監査の記録を書く                                                   :84
  呼び出し元
  ├── PUT /v1/users/{user_id}/position  services/schedule/internal/httpapi/staff_handler.go  [影響]
  └── 職員の詳細の「役職を変える」  apps/web/src/features/staff/components/StaffPositionDialog.tsx  [影響]
```

### 職員ごとに足した権限かを、前の役職のデフォルトにあるかで決める

`user_policies` は、デフォルトからコピーした権限か、職員ごとに足した権限かを持たない。  
前の役職のデフォルトにある権限は、職員ごとに対象を直していても消える。前の役職のデフォルトに無い権限は、対象ごと残る。

### 残す権限が新しい役職のデフォルトにもあれば、コピーしない

同じ職員に同じ権限は 1 つだけ付く。職員ごとに足した権限の対象（例: チーム B）が残り、所属のチームを対象にするデフォルトの行は作らない。

### 最後の有効な管理者を、変更の後の権限で判定する

職員ごとに足した職員の管理の権限が残るなら、職員の管理の権限を持たない役職にも変えられる。役職のデフォルトだけで持つなら、409 で拒む。

### 権限の変更は次のリクエストから判定に使われる

予定の API はリクエストごとに `user_policies` を読む。役職の変更と権限の足し外しの直後に画面を読み込むと、変わった権限で予定の列と操作が出し分けられる。

| 観点 | 受け入れの条件 | 対応する分岐・仕様 | 検出する不具合 | シナリオ |
| --- | --- | --- | --- | --- |

## テストケース

### 役職の変更

- **REQ-1**: WHEN 個別に権限を足した職員の役職を、職員の詳細の「役職を変える」で変えるとき、the 役職を変えるダイアログ SHALL 個別に足した権限の名前を挙げ、その権限が残る旨の注意を出す。
  - 個別に足した権限は役職を変えても残る
- **REQ-2**: WHEN 個別に権限を足した職員の役職を変えたとき、the 権限のタブ SHALL 新しい役職のデフォルトの権限を「役職で付く権限」に、個別に足した権限を対象ごと「個別に足した権限」に出す。
  - 個別に足した権限は役職を変えても残る
- **REQ-3**: WHERE 個別に足した権限が新しい役職のデフォルトにもある場合、WHEN 役職を変えたとき、the 予定の API SHALL 個別に足した権限の対象を残し、所属のチームを対象にするデフォルトの行をコピーしない。
  - 新しい役職のデフォルトにもある個別の権限は対象が残り、判定もその対象で行う

### 予定の判定

- **REQ-4**: WHEN 役職を変えた職員が予定のカレンダーを開いたとき、THEN 日の表示 SHALL 残った個別の権限と新しい役職のデフォルトの権限で見てよい職員の列だけを出す。
  - 残った権限が予定の判定に使われ、外すと使われない
- **REQ-5**: WHEN 個別に足した権限を外した後に画面を読み込み直したとき、THEN 日の表示 SHALL その権限で見えていた職員の列を出さない。
  - 残った権限が予定の判定に使われ、外すと使われない
- **REQ-6**: WHEN 閲覧だけを許すチームの職員の予定の詳細を開いたとき、the 予定の詳細 SHALL 「編集」を出さず、編集を許すチームの職員の予定には「編集」を出す。
  - 新しい役職のデフォルトにもある個別の権限は対象が残り、判定もその対象で行う

### 最後の有効な管理者

- **REQ-7**: WHERE 事業所で唯一の有効な管理者が職員の管理の権限を個別に足して持つ場合、WHEN 職員の管理の権限の無い役職に変えたとき、the 予定の API SHALL 役職を変え、職員の管理の権限を残す。
  - 個別に足した職員の管理の権限だけを持つ最後の管理者は、その権限の無い役職に変えられる
