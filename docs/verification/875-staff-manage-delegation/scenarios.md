# 職員の管理の権限の委譲範囲と、権限の変更の監査の記録の検証のシナリオ

[#875](https://github.com/Fukuemon/buddy/issues/875) の受け入れの条件を確認するシナリオ。  
観点の選び方は [test-design.md](test-design.md) に、spec との対応は [README.md](README.md) にある。

## 共通の前提

- アクターは、シードのサンプル訪問看護ステーションの職員である。
  - 青木 陽菜は、役職が管理者で、職員の管理の権限を持つ。事業所で職員の管理の権限を持つ有効な職員は、シードでは青木だけである。
  - 森 健太は、役職がチームリーダーで、職員の管理の権限を持たない。チームを対象にする権限の対象はチーム B である。
- 2 人目の管理者と、操作の対象にする職員は、録画の前に青木のトークンで予定の API から登録する。
- 画面から起こせない操作（拒まれる操作の多く、役職の作成）は、API の参照のページから送る。
- 監査の記録とログは画面に出さない（ADR-0042）。シナリオの「記録」の行は、撮った後に予定の API の DB とログで確認する。

## 権限を足す

- `@scenario-id`: `875-grant-add`

```text
前提 青木 陽菜 でログインし、録画の前に登録したメンバーの「見本 委譲先」がいる
もし 自分の権限の変更で「指定した職員の予定の閲覧」を対象「見本 委譲先」で足して保存する
ならば 自分の権限のタブに「指定した職員の予定の閲覧」が出る
もし 「見本 委譲先」の権限の変更で「職員の管理」を足して保存する
ならば 「見本 委譲先」の権限のタブに「職員の管理」が出る
もし API の参照のページから、「見本 委譲先」に同じ「職員の管理」を足すリクエストを 青木 陽菜 のトークン（伏せ字）で送る
ならば 409 が返る
もし 別の事業所のチームを対象にして「指定したチームの職員の予定の閲覧」を「見本 委譲先」に足すリクエストを送る
ならば 400 が返る
```

- 記録: 操作した職員が青木の `grant.add` が 2 行（対象は青木と見本 委譲先）残る。409 と 400 のリクエストの記録は残らない。

## 権限を外す

- `@scenario-id`: `875-grant-remove`

```text
前提 青木 陽菜 と、録画の前に職員の管理の権限を足した「見本 管理者二」の 2 人が、職員の管理の権限を持つ有効な職員である
もし 自分の権限の変更で、録画の前に足した「指定した職員の予定の閲覧」を外して保存する
ならば 自分の権限のタブから「指定した職員の予定の閲覧」が消える
もし 「見本 管理者二」の権限の変更で「職員の管理」を外して保存する
ならば 「見本 管理者二」の権限のタブから「職員の管理」が消える
もし 自分の権限の変更で「職員の管理」を外して保存する
ならば 「職員の管理の権限を持つ最後の有効な職員から、その権限は外せません。」が出る
かつ 自分の権限のタブに「職員の管理」が残る
```

- 記録: `grant.remove` が 2 行残る。409 のリクエストの記録は残らない。

## 役職を変える

- `@scenario-id`: `875-position-change`

```text
前提 青木 陽菜 と「見本 管理者三」（役職 管理者）の 2 人が管理者で、録画の前に職員の管理の権限を持つ役職「E2E 管理者 <時刻>」を作ってある
もし 「見本 管理者三」の役職をリーダーに変えて保存する
ならば 「見本 管理者三」の役職がリーダーになり、「職員の管理」が消える
もし 自分の役職を「E2E 管理者 <時刻>」に変えて保存する
ならば 自分の役職が「E2E 管理者 <時刻>」になり、「職員の管理」が残る
もし 自分の役職をリーダーに変えて保存する
ならば 「職員の管理の権限を持つ最後の有効な職員は、その権限を持たない役職に変えられません。」が出る
かつ 自分の役職は「E2E 管理者 <時刻>」のままで、「職員の管理」が残る
```

- 記録: `position.change` が 2 行残る。409 のリクエストの記録は残らない。

## チームを変える

- `@scenario-id`: `875-team-change`

```text
前提 チームを対象にする権限を持つ 森 健太（チーム B）がいる
もし 森 健太 のプロフィールでチームを A に変えて保存する
ならば 森 健太 のチームが A になる
かつ チームの予定の閲覧と編集の対象が A になる
もし 自分のプロフィールでチームを B に変えて保存する
ならば 自分のチームが B になる
```

- 記録: 森の `team.change` が 1 行残る。青木はチームを対象にする権限を持たず、権限の対象が変わらないので、青木の変更の記録は残らない。

## 役職を作る

- `@scenario-id`: `875-position-create`

```text
前提 青木 陽菜 のトークン（伏せ字）で、API の参照のページの「役職を作る」を開いている
もし 名前「E2E 委譲 <時刻>」と権限「職員の管理」「自分の予定の編集」の役職を作るリクエストを送る
ならば 201 が返り、名前と 2 つの権限が出る
もし 同じ名前で役職を作るリクエストを送る
ならば 409 が返る
```

- 記録: `position.create` が 1 行残る。409 のリクエストの記録は残らない。

## 職員を登録する

- `@scenario-id`: `875-staff-create`

```text

もし API の参照のページから、別の事業所の役職で職員を登録するリクエストを 青木 陽菜 のトークン（伏せ字）で送る

```

## 休職と退職

- `@scenario-id`: `875-leave-retire`

```text
前提 青木 陽菜 のトークン（伏せ字）で、API の参照のページを開いている。録画の前に「見本 退職」と「見本 休職」を登録してある
もし 自分を休職にするリクエストを送る
ならば 409 が返り、自分を休職にできないことの文が出る
もし 自分を退職にするリクエストを送る
ならば 409 が返る
もし 「見本 退職」を退職にするリクエストを送る
ならば 200 が返る
もし 「見本 休職」の職員の詳細の「…」から休職にする
ならば 「見本 休職」が休職になる
```

- 記録: 休職と退職は記録しない（ADR-0042）。この録画のリクエストの記録は残らない。
- 自分の職員の詳細は「…」のメニューを出さないので、自分を休職と退職にするリクエストは API の参照のページから送る。

## 職員の管理の権限を持たない職員

- `@scenario-id`: `875-forbidden`

```text
前提 森 健太（チームリーダー、職員の管理の権限なし）のトークン（伏せ字）を API の参照のページに入れる。対象は録画の前に登録した「見本 権限なしの対象」と 林 さくら
もし 1. 「見本 権限なしの対象」に「職員の管理」を足すリクエストを送る
ならば 1. 403 が返る
もし 2. 林 さくら の「指定した職員の予定の閲覧」を外すリクエストを送る
ならば 2. 403 が返る
もし 3. 「見本 権限なしの対象」の役職を管理者に変えるリクエストを送る
ならば 3. 403 が返る
もし 4. 「見本 権限なしの対象」のチームを B に変えるリクエストを送る
ならば 4. 403 が返る
もし 5. 職員の管理をデフォルトに付けた役職を作るリクエストを送る
ならば 5. 403 が返る
もし 6. 役職を管理者にして職員を登録するリクエストを送る
ならば 6. 403 が返る
もし 7. 「見本 権限なしの対象」を休職にするリクエストを送る
ならば 7. 403 が返る
```

- 記録: 7 つのリクエストの記録は残らない。
