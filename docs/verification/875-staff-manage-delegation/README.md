# #875 職員の管理の権限の委譲範囲と、権限の変更の監査の記録のエビデンスの一覧

[#875](https://github.com/Fukuemon/buddy/issues/875) の受け入れの条件の、検証のシナリオとエビデンスの spec の対応。  
検証の issue は [#995](https://github.com/Fukuemon/buddy/issues/995) である。

- [検証の設計](test-design.md)
- [検証のシナリオ](scenarios.md)

## 撮るシナリオ

spec は `packages/e2e/tests/evidence/staff/staff-manage-acceptance.e2e.ts` である。  
検証環境ができるまで、pull request のエビデンスと同じ撮影の config で、ローカル環境の compose で撮る。  
入れる先は `issue-995` である。test の名前は、`name` と次の文を空白でつないだものである。

| シナリオ | `name` | test の名前の `name` の後の文 |
| --- | --- | --- |
| 権限を足す | `s1-grant-add` | 職員の管理の権限を持つ職員が自分とほかの職員に権限を足した場合、両方に権限が付き、同じ権限と別の事業所の対象は拒まれること |
| 権限を外す | `s2-grant-remove` | 職員の管理の権限を持つ職員が自分とほかの管理者から権限を外した場合、外せて、最後の管理者の職員の管理は外せないこと |
| 役職を変える | `s3-position-change` | 職員の管理の権限を持つ職員がほかの管理者と自分の役職を変えた場合、変えられて、最後の管理者を職員の管理の無い役職には変えられないこと |
| チームを変える | `s4-team-change` | 職員の管理の権限を持つ職員がほかの職員と自分のチームを変えた場合、チームが変わり、ほかの職員の権限の対象が新しいチームに移ること |
| 役職を作る | `s5-position-create` | 職員の管理の権限を持つ職員が職員の管理をデフォルトに付けた役職を作った場合、作れて、同じ名前の役職は拒まれること |
| 職員を登録する | `s6-staff-create` | 職員の管理の権限を持つ職員が役職を付けて職員を登録した場合、役職の権限が付き、別の事業所の役職は拒まれること |
| 休職と退職 | `s7-leave-retire` | 職員の管理の権限を持つ職員が自分とほかの職員を休職と退職にしようとした場合、自分は拒まれ、ほかの職員は休職と退職にできること |
| 職員の管理の権限を持たない職員 | `s8-forbidden` | 職員の管理の権限を持たない職員が職員の管理の 8 つの操作のリクエストを送った場合、どれも 403 が返ること |

- spec は、DB を作り直してから単独で流す。役職の作成は戻せないためである。
- 監査の記録とログは画面に出ないので、撮った後に、予定の API の DB の `permission_audits` と、予定の API のログの request の行を、撮った時刻の範囲で取り出す。取り出した値は、検証の pull request のスレッドに置く。
  - シナリオの「記録」の数は、録画の中のリクエストの `request_id` で絞って数える。撮った時刻の範囲には、録画の外の前準備と片付けのリクエストの記録も入るためである。
  - 4xx のリクエストは、ログの `request_id` で記録の行の数を数える。

## spec を置かないシナリオ

なし。対象外の観点は [検証の設計](test-design.md#対象外) にある。

## 撮影のための操作

- 対象にする職員（見本 委譲先、見本 管理者二、見本 管理者三、見本 退職、見本 休職、見本 権限なしの対象）は、録画の外で青木 陽菜のトークンで予定の API から登録する。
- 権限を外すシナリオの前提の権限（見本 管理者二の職員の管理、青木の指定した職員の予定の閲覧）と、役職を変えるシナリオの役職「E2E 管理者 <時刻>」は、録画の外で予定の API で足す。
- 職員の管理の権限を持たない職員のシナリオの森 健太のトークンは、録画の外で取る。
- 拒まれた操作のダイアログは、「キャンセル」で閉じてから、残った権限と役職を見る。権限は権限のタブに、役職と「役職を変える」はプロフィールのタブにあるので、判定の前にタブを開く。
- 同じリクエストを続けて送る場面では、API の参照のページを読み直してからクライアントを開く。クライアントが前のレスポンスを持ったまま開くためである。
- 撮った後に、ほかの撮影の前提に戻す。職員の管理の権限を持つ有効な職員を青木だけに戻し、青木の役職を管理者に、森と青木のチームを元に戻し、青木に足した権限を外す。
