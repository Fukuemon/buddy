# 職員の管理の権限の委譲範囲と、権限の変更の監査の記録の検証の設計

[#875](https://github.com/Fukuemon/buddy/issues/875) の受け入れの条件を、予定の API と画面から確認する検証の設計。  
検証の issue は [#995](https://github.com/Fukuemon/buddy/issues/995) である。  
シナリオは [scenarios.md](scenarios.md) に、エビデンスの一覧は [README.md](README.md) にある。

## 対象範囲

### 対象

- 確認する受け入れの条件（#875）
  1. `staff.manage` による権限委譲の許可・拒否ケースが表に整理されている。
  2. 自分自身と他者に対する権限昇格の方針が決まっている。
  3. 監査イベントの内容・保存先・閲覧者・保存期間が決まっている。
  4. 採用方針を ADR と権限の Design Doc に反映し、実装・テスト用の後続タスクを特定できている。
  5. #279 の最後の管理者保護を維持する検証条件がある。
- 条件 1〜3 で決めた方針（ADR-0041 の職員の管理の権限、ADR-0042）が、予定の API の動きになっていること。
  - ADR-0041 の、職員の管理の権限を持つ職員の操作の表の各行
  - 職員の権限を変える 6 つの操作の監査の記録と、拒んだ操作で記録が残らないこと
  - 最後の有効な管理者の保護（#279 の検証の観点 1〜4）が、記録を足した後も保たれること

### 対象外

| 観点 | 理由 |
| --- | --- |
| マイグレーションの始まりの行（`grant.migrate`） | 画面から起こせない。[#997](https://github.com/Fukuemon/buddy/pull/997) のスレッドの 3-1 と `TestMigratePermissionAudits` で確認した |
| 記録を書けないときに操作も戻ること | 画面から起こせない。`TestPermissionAudit` で確認した |
| 2 人の管理者から同時に職員の管理の権限を外すこと（#279 の観点 4） | 画面と API の参照のページでは、同時のリクエストを撮れない。`TestStaffConcurrentRemovalKeepsManager` で確認した |
| 役職を変えても、職員ごとに足した `staff.manage` が残ること | 役職の変更の規則は、[#996](https://github.com/Fukuemon/buddy/issues/996) の検証で扱う |
| 最後の有効な管理者を、ほかの職員が休職か退職にすること | 操作する職員は職員の管理の権限を持つので、対象が最後の有効な管理者になるのは、自分を対象にするときだけである。自分を対象にする操作は「休職と退職」のシナリオで確認する |
| 今と同じ役職に変えたときと、名前だけを変えたときに記録が残らないこと | #997 の `audit-position-same` と `audit-name-only` で確認した |
| 運営者の操作の記録（`facility.create`、`staff.create_forced` など） | 運営用の CLI の #986 が書く |

## 根拠

| 種別 | 参照先 | 確認した内容 |

## テスト観点

| 観点 | 受け入れの条件 | 対応する分岐・仕様 | 検出する不具合 | シナリオ |
| --- | --- | --- | --- | --- |
| 自分とほかの職員に権限を足す | 1、2、3 | `AddGrant`、`grant.add` | 自分への付与かほかの職員への `staff.manage` の付与が拒まれる。記録が残らない | 権限を足す |
| 同じ権限と別の事業所の対象 | 1、3 | 409、400 | 重複か別の事業所の対象が通る。拒んだ操作の記録が残る | 権限を足す |
| 自分とほかの管理者から権限を外す | 1、2、3、5 | `RemoveGrant`、最後の管理者の確認 | ほかの管理者から外せない。最後の管理者から外れる（#279 の 1、3） | 権限を外す |
| ほかの管理者と自分の役職を変える | 1、2、3、5 | `ChangePosition`、変更の後の権限での判定 | 自分の役職を変えられない。最後の管理者が職員の管理を失う（#279 の 2） | 役職を変える |

## テストケース

### 職員の管理の権限を持つ職員の操作

- **REQ-1**: WHEN 職員の管理の権限を持つ職員が、自分かほかの職員に `staff.manage` を含む権限を足したとき、the 予定の API SHALL 権限を足し、`grant.add` を 1 行残す。
  - 記録は、操作した職員、対象、変更の前後の全量を持つ。
  - 権限を足す
  - 権限を足す
- **REQ-2**: IF 足す権限が対象の職員に既にあるか、対象のチームが別の事業所のものならば、the 予定の API SHALL 409 か 400 を返し、記録を残さない。
  - 権限を足す
- **REQ-3**: WHEN 職員の管理の権限を持つ職員が、自分かほかの管理者から権限を外したとき、the 予定の API SHALL 権限を外し、`grant.remove` を 1 行残す。
  - 権限を外す
- **REQ-4**: WHEN 職員の管理の権限を持つ職員が、ほかの管理者か自分の役職を変えたとき、the 予定の API SHALL 役職と権限を変え、`position.change` を 1 行残す。
  - 役職を変える
- **REQ-5**: WHEN 職員の管理の権限を持つ職員が、ほかの職員か自分のチームを変えたとき、the 予定の API SHALL チームを変えてチームの権限の対象を移し、対象が移った職員にだけ `team.change` を 1 行残す。
  - チームを変える
- **REQ-6**: WHEN 職員の管理の権限を持つ職員が、職員の管理をデフォルトに付けた役職を作ったとき、the 予定の API SHALL 役職を作り、`position.create` を 1 行残す。IF 同じ名前の役職があれば、409 を返し、記録を残さない。
  - 役職を作る
- **REQ-7**: WHEN 職員の管理の権限を持つ職員が、役職を付けて職員を登録したとき、the 予定の API SHALL 役職のデフォルトの権限を付けて登録し、`staff.create` を 1 行残す。IF 役職が別の事業所のものならば、400 を返し、記録を残さない。
  - 職員を登録する
- **REQ-8**: IF 職員の管理の権限を持つ職員が、自分を休職か退職にしようとしたならば、the 予定の API SHALL 409 を返す。WHEN ほかの職員を休職か退職にしたとき、the 予定の API SHALL 状態を変え、監査の記録を残さない。
  - 休職と退職

### 最後の有効な管理者

- **REQ-9**: IF 外すか役職を変えると、事業所で `staff.manage` を持つ有効な職員がいなくなるならば、the 予定の API SHALL 409 を返し、権限と役職を変えず、記録を残さない。
  - 権限を外す、役職を変える

### 職員の管理の権限を持たない職員

- **REQ-10**: IF 職員の管理の権限を持たない職員が、職員の権限を変える 7 つの操作のどれかを予定の API に送ったならば、the 予定の API SHALL 403 を返し、記録を残さない。
  - 7 つの操作は、権限を足す、権限を外す、役職を変える、チームを変える、役職を作る、職員を登録する、休職にするである。
  - 職員の管理の権限を持たない職員
