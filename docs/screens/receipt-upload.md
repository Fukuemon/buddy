# 照合

照合する職員が、予定の取り方を選び、電子カルテから書き出した実績の CSV を上げて、照合を始める画面。  
照合が終わると、照合の結果の画面へ移る。

| 項目 | 値 |
| --- | --- |
| 画面の ID | `receipt-upload` |
| URL | `/receipt` |
| 使う人 | 全ての職員 |
| 実装 | `apps/web/src/routes/receipt.index.tsx`、`ReceiptCheckFormContainer`、`ReceiptCheckForm` |

## UI

上端のヘッダーの下に、題、説明の文、照合の入力のフォームを縦に並べる。  
フォームは、予定の取り方、対象の月か予定の CSV、実績の CSV、失敗の文、照合のボタンの順に並ぶ。

## 状態ごとの UI

| 状態 | 条件 | 見えるもの |
| --- | --- | --- |
| 初期表示 | 開いた直後 | 予定の取り方は「Google カレンダー」、対象の月は前の月。照合のボタンは押せない |
| 予定の CSV | 予定の取り方で「予定の CSV」を選んだ | 対象の月の代わりに、予定の CSV の欄 |
| 入力がそろった | 実績の CSV と、対象の月か予定の CSV がそろい、合計が 10 MB 以下 | 照合のボタンを押せる |
| 送信中 | 照合の API の応答を待っている | 照合のボタンに回転するインジケーターを重ね、押しても送らない |
| 行の誤り（422） | 入力の CSV の行に誤りがある | 「入力の CSV に誤りがあります。次の行を直して、もう一度照合してください。」と、行ごとの誤り（`role="alert"`） |
| ファイルの誤り（422、413、400） | 列が無いなど、ファイル全体の誤り。ファイルが大きすぎる。本文を読めない | 422 は「入力の CSV に誤りがあります。」の後に API の文。413 は「ファイルが大きすぎます。10 MB までのファイルにしてください。」。400 は「入力を読めませんでした。ファイルを選び直して、もう一度照合してください。」 |
| カレンダーの失敗（502、503、403） | Google カレンダーから予定を取れない、事業所のカレンダーの設定が無い、またはアカウントに事業所が結び付いていない | 502 は時間をおいてやり直す案内、503 と 403 は予定の CSV で照合する案内 |
| 照合の失敗 | そのほかの失敗、または API に届かない | 「照合できませんでした。時間をおいて、もう一度照合してください。」 |
| 未認証（401） | セッションが切れている | ログインの画面へ移り、ログインの後にこの画面へ戻る |

- 選んだファイルの合計が上限を超えたときは、送らずに、状態の表の 413 と同じ文を出す。上限は、照合の API の `MAX_UPLOAD_BYTES` の既定（10 MiB）から multipart の分の 64 KiB を引いた値にする。
- 予定の取り方、対象の月、ファイルを変えたら、前の失敗の文と行の誤りを消す。

## 構成要素

API の列は、`createCheck`（`POST /v1/checks`）の本文と応答で書く。

| 番号 | 構成要素 | 表示する値 | web の型の項目 | OpenAPI の項目 | `data-testid` |
| --- | --- | --- | --- | --- | --- |
| 1 | `SiteHeader` | 「buddy」 | なし | なし | なし |
| 1-1 | `SiteNav` | 「予定」と「照合」のリンク。今の画面に `aria-current="page"` | なし | なし | `site-nav` |
| 1-2 | `ViewerMenu` | ログインした職員の名前とログアウトのボタン。幅 768px 未満では名前を出さない | `Viewer.staffName` | `getMe` の `username` | `viewer-menu`、ログアウトのボタンは `viewer-logout` |
| 2 | 説明の文 | 照合で何をするかの文 | なし | なし | なし |
| 3 | `ReceiptCheckForm` | 照合の入力のフォーム | なし | なし | `receipt-check-form` |
| 3-1 | 予定の取り方の `SegmentedControl` | 「Google カレンダー」と「予定の CSV」 | なし | なし | `receipt-source` |
| 3-2 | 対象の月 | `YYYY-MM` の月の入力と、取る範囲の補足 | `ReceiptCheckInput.month` | `month` | `receipt-month` |
| 3-3 | 予定の CSV の `CsvFileField` | ファイルの選択 | `ReceiptCheckInput.schedules` | `schedules` | `receipt-schedules-file` |
| 3-4 | 実績の CSV の `CsvFileField` | ファイルの選択と、文字コードと上限の補足 | `ReceiptCheckInput.visits` | `visits` | `receipt-visits-file` |
| 3-5 | 失敗の文 | 状態ごとの UI の文と、行ごとの誤り | `ApiError.rowErrors` | `Error.errors` | `receipt-check-error` |
| 3-6 | 照合のボタン | 「照合する」 | なし | なし | `receipt-check-submit` |

- 行ごとの誤りは、「実績の CSV の 3 行目の「訪問日」: 暦にない日付: 2024-13-01」の形で、ファイル、行、列、API の文を並べる。列の無い誤りは列を省く。

## 構成要素ごとの活性条件と表示条件

| 番号 | 構成要素 | 表示する条件 | 押せる（入力できる）条件 |
| --- | --- | --- | --- |
| 1-2 | `ViewerMenu` | 常に表示する。ログアウトのボタンは、BFF で動くときだけ出す | 常に押せる |
| 3-2 | 対象の月 | 予定の取り方が「Google カレンダー」 | 常に入力できる |
| 3-3 | 予定の CSV | 予定の取り方が「予定の CSV」 | 常に入力できる |
| 3-5 | 失敗の文 | 照合が失敗したか、ファイルが 10 MB を超えた | なし |
| 3-6 | 照合のボタン | 常に表示する | 実績の CSV と、対象の月か予定の CSV がそろい、合計が 10 MB 以下。送信中は押しても送らない |

## インタラクション

| 番号 | 操作 | 前提 | 結果 |
| --- | --- | --- | --- |
| 1-1 | リンクを押す | なし | リンクの画面を読み込む |
| 3-1 | 予定の取り方を選ぶ | なし | 対象の月と予定の CSV の欄を入れ替える。選んでいた予定の CSV は捨てる |
| 3-6 | 照合のボタンを押す | 入力がそろった | BFF の server function を通して `createCheck` を送る。成功すると結果を画面に置き、照合の結果（`/receipt/result`）へ移る。失敗すると失敗の文を出す |

## 初期状態でのインタラクション

- 対象の月の既定は、職員の端末の日付の前の月にする。照合は、月が終わった後に前の月を対象にするためである。端末の日付で決めるので、サーバーで描画しない。
- フォーカスは `body` にある。search params は読まない。

## 未決

- Google カレンダーの照合の対象のカレンダーは、照合の API の設定ファイルで決まる。画面で職員やカレンダーを選ぶかは決めていない。
- 照合の権限は、PRD では全ての職員である。権限（policies）による判定は未実装である。
