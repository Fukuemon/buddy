# schedule-cutover 予定の正本の切り替え

Google カレンダーで予定を管理している事業所で、予定を buddy に取り込み、事業所の予定の正本を buddy に切り替える画面。  
マネージャーが、切り替えを始め、職員ごとの取り込みの状況を見て、完了するかやめる。

| 項目 | 値 |
| --- | --- |
| URL | `/schedule/link/cutover` |
| 使う人 | 職員の管理の権限を持つ職員（デフォルトはマネージャー） |
| 実装 | `apps/web/src/routes/schedule_.link_.cutover.tsx`、`apps/web/src/features/calendar/components/CalendarCutoverContainer.tsx` |

画面の項目と、web の型、OpenAPI の項目の対応は [API との対応](api.md) にある。

画面を描くコンポーネントのうち、実装の行のほかのものは次のとおり。

- `apps/web/src/features/calendar/components/CalendarCutoverView.tsx`
- `apps/web/src/features/calendar/components/CalendarCutoverUnmetTable.tsx`
- `apps/web/src/features/calendar/components/CalendarCutoverCancelDialog.tsx`

## 説明の文

**概要**: 切り替えで何が変わるかを伝えるラベル。

**値のソース**: 次の文言。

| 文言 |
| --- |
| 「Google カレンダーで管理している予定を buddy に取り込み、この事業所の予定の正本を buddy に切り替えます。切り替えた後は、予定を buddy で作成、変更し、Google カレンダーには buddy の予定を書き出します。」 |

## 切り替えの手順

**概要**: 切り替えの 3 つの段階を、番号付きで示す領域。

**値のソース**: 見出し「切り替えの手順」と、次の 3 つの手順。

| 手順 | 文言 |
| --- | --- |
| 1 | 「切り替えを始めます。始めた月の初日から先の全ての予定が、取り込みの対象になります。」 |
| 2 | 「職員ごとに、予定を取り込みます。取り込みの間も、予定のカレンダーには Google カレンダーの予定が出ます。」 |
| 3 | 「全ての職員を取り込み、同期が終わったら、完了します。」 |

## Google カレンダーを変えない案内

**概要**: 切り替えの間に、職員に Google カレンダーで予定を変えないよう頼むことを、マネージャーに伝えるメッセージ。

**値のソース**: 見出しは「切り替えの間は、Google カレンダーで予定を変えない」。  
本文は「職員に、切り替えが終わるまで Google カレンダーで予定を作成、変更しないよう頼んでください。取り込んだ後に変えた予定は、完了するときに見つかり、取り込み直すまで完了できません。」。

## カレンダーの一覧

**概要**: Google カレンダーを結び付けた職員ごとの、最後の同期の時刻と、この切り替えの最後の取り込みの時刻を示す表。

**値のソース**: 状態ごとに、次の見出し、説明、カラムで出す。

| 状態 | 見出し | 説明 | カラム |
| --- | --- | --- | --- |
| 切り替えの前、始められない | 「カレンダーの同期」 | 「全てのカレンダーの最後の同期が成功していると、始められます。」 | 「職員」「最後の同期」 |
| 切り替え中、完了できない | 「職員ごとの取り込み」 | 「全ての職員を取り込み、最後の取り込みの後に同期が成功すると、完了できます。」 | 「職員」「この切り替えの最後の取り込み」「最後の同期」と、[取り込む](#取り込む) の列 |

職員のカラムには、職員の名前を出す。  
最後の同期は、最後に同期できた時刻（「2026/11/05 08:59」の形）で出し、同期していなければ「まだ同期していない」と出す。  
最後の同期が失敗していれば、時刻の後に「（最後の同期は失敗）」を付ける。  
この切り替えの最後の取り込みは、この切り替えで最後に取り込んだ時刻を出し、取り込んでいなければ「まだ取り込んでいない」と出す。

## 切り替えを始める

**概要**: 切り替えを始めるボタン。  
画面の主ボタンである。

**値のソース**: 次の文言。

| 状態 | 文言 |
| --- | --- |
| 押す前 | 「切り替えを始める」 |
| 始めている間 | 「始めています」 |

**活性**: 次の全てに当てはまるとき。

- 職員が、切り替えの開始を送っている途中でない

**操作**: 押すと、切り替えを始める。

1. 始められたら、「切り替え中」の状態にする。取り込みの期間は、今の月の初日から先の全てになる。
2. 始められなければ、「始められない」の状態にし、始めるの失敗の文を出す。

## 始めるの失敗の文

**概要**: 切り替えを始められなかった理由と、次にすることを示すメッセージ。  
読み上げでは警告として扱う。

**値のソース**: 理由ごとに、次の文言を出す。

| 理由 | 文言 |
| --- | --- |
| 最後の同期が成功していない職員がいる | 「最後の同期が成功していないカレンダーがあります（石川 二葉）。同期が成功してから始めてください」 |
| ほかの画面で切り替えを始めた | 「この事業所では、ほかの画面で切り替えを始めています。画面を読み直してください。」 |

ほかの理由の文言は、[API との対応](api.md#状態と失敗の要因) にある。

## 切り替え中の表示

**概要**: 切り替え中であることと、始めた時刻と、取り込みの期間を示すメッセージ。

**値のソース**: 次の文言。

| 文言 |
| --- |
| 「切り替え中です（2026/11/05 09:00 に開始）。取り込みの期間: 2026/11/01〜」 |

## 取り込む

**概要**: 職員の予定の取り込みの画面を、その職員を選んで開くリンク。  
カレンダーの一覧の行ごとに、右端に出す。

**値のソース**: この切り替えで取り込んでいなければ「取り込む」、取り込んでいれば「取り込み直す」。

**操作**: 押すと、[予定の取り込み](../schedule-import_予定の取り込み/index.md) の画面へ、その職員を選んで移る。

1. 取り込みの画面は、切り替えの期間で取り込む。

## 完了できない一覧

**概要**: 完了の条件を満たさない職員と予定を、日時と理由と次にすることで並べる表。  
予定のタイトルは利用者名を含むので出さない。

**値のソース**: 見出しは「完了できません（2 件）」。  
説明は「次のカレンダーと予定が、完了の条件を満たしていません。直してから、もう一度完了してください。」。  
行ごとに、職員の名前、日時、理由、次にすることを出す。  
日時は「2026/11/10（火）10:00〜10:30」の形で出し、職員ごとの理由と、Google で消えた予定は空にする。  
理由と次にすることの組は、次のとおり。

| 理由 | すること |
| --- | --- |
| 「この切り替えで、まだ取り込んでいない」 | 「取り込んでください」 |
| 「最後の取り込みの後に、同期が成功していない」 | 「同期が終わるまで待ってから、もう一度完了してください」 |
| 「取り込んでいない予定がある」 | 「取り込み直してください」 |
| 「確認が必要な予定の取り込み方を決めていない」 | 「取り込み直して、取り込み方を選んでください」 |
| 「取り込んだ後に Google で変わった」 | 「取り込み直すと、Google の内容で上書きします」 |
| 「取り込んだ後に Google で消えた」 | 「取り込み直すと、buddy の写しを消します」 |

## 完了する

**概要**: Google カレンダーを読み直して完了の条件を確認し、満たせば事業所の予定の正本を buddy にするボタン。  
画面の主ボタンである。

**値のソース**: 次の文言。

| 状態 | 文言 |
| --- | --- |
| 押す前 | 「完了する」 |
| 確認している間 | 「確認しています」 |

**活性**: 次の全てに当てはまるとき。

- 職員が、完了を送っている途中でない

**操作**: 押すと、Google カレンダーを切り替えの期間の初めから読み直し、完了の条件を確認する。

1. 次の 6 つを全て満たせば、事業所の予定の正本を buddy にし、「完了した」の状態にする。
   - 全ての職員を、この切り替えで取り込んでいる。
   - 職員ごとに、最後の取り込みの後に同期が成功している。
   - 取り込みの期間の Google の予定を、全て取り込んだか、取り込まないと決めている。
   - 確認が必要な予定の取り込み方を、全て決めている。buddy の繰り返しの規則に写せない繰り返しの予定も、ここに当たる。
   - 取り込んだ後に、Google で予定が変わっていない。
   - 取り込んだ後に、Google で予定が消えていない。
   - 条件は [ADR-0031](../../adr/0031-calendar-cutover.md) にある。
2. 満たさなければ、「完了できない」の状態にし、満たさない職員と予定を [完了できない一覧](#完了できない一覧) に出す。正本は変えない。
3. 完了の操作が失敗したときは、ボタンの上に、理由ごとに次の完了の失敗の文を出す。読み上げでは警告として扱う。

| 理由 | 文言 |
| --- | --- |
| 画面を開いた後に権限を外された | 「この操作をする権限がありません。」 |
| ほかの画面で完了したか、やめた | 「この切り替えは、ほかの画面で完了したか、やめています。画面を読み直してください。」 |
| Google に届かない | 「Google カレンダーから予定を読めませんでした。時間をおいて、もう一度完了してください。」 |
| Google カレンダーを読めない職員がいる | 「Google カレンダーを読めない職員がいます。カレンダーの共有が外れていないかを、職員に確認してください。」 |
| 事業所の Google カレンダーの準備ができていない | 「この事業所では、まだ Google カレンダーを使う準備ができていません。事業所の管理者に、設定を頼んでください。」 |
| そのほか | 「操作できませんでした。時間をおいて、もう一度試してください。」 |

文と、その要因の対応は [API との対応の状態と失敗の要因](api.md#状態と失敗の要因) にある。

## 全体動作

### 使う場面

事業所が Google カレンダーでの予定の管理に慣れ、buddy で予定を管理すると決めたときに、マネージャーが 1 度だけ使う。  
切り替えの間は、職員に Google カレンダーで予定を変えないよう頼み、職員ごとに取り込んでから完了する。  
手順と確認の条件は [ADR-0031](https://github.com/Fukuemon/buddy/blob/develop/docs/adr/0031-calendar-cutover.md) にある。

### 初期処理

開くと「読み込み中」の状態にし、事業所の予定の正本と切り替えの状況を読む。  
読み終えたら、切り替え中なら「切り替え中」、事業所が buddy で予定を管理していれば「正本が buddy」、ほかは「切り替えの前」の状態にする。  
読み終えた後に、ウィンドウに戻ったときなどに読み直して読めなかったときは、「最新の情報の読み込みの失敗」の状態にする。決まりは、規約の [エラーの見せ方](../rules.md#エラーの見せ方) にある。  
URL の search params は読まない。

### 変えた後の表示

- 始めると、予定のカレンダーの上に、切り替え中であることと、Google カレンダーで予定を変えないよう頼む文が出る。
- 切り替えの間も、予定のカレンダーと照合は Google カレンダーの予定を出す。取り込んだ予定は、完了するまで出ない。
- 完了すると、予定のカレンダーで予定を作れるようになり、Google カレンダーの予定の同期をやめる。
- やめると、切り替え中の表示が消え、事業所の予定は Google カレンダーで管理したままになる。

### 権限の確認

職員の管理の権限が無い職員には、画面を出さずに、権限が無いことを出す。  
形は目次の [全ての画面に共通する状態](../index.md#全ての画面に共通する状態) にある。
