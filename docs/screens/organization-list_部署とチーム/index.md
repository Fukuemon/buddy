# organization-list 部署とチーム

職員の管理の権限を持つ職員が、事業所の部署とチームを一覧し、作り、名前とチームの色を変える画面。  
部署とチームの削除は扱わない。

| 項目 | 値 |
| --- | --- |
| URL | `/organization` |
| 使う人 | 職員の管理の権限を持つ職員。デフォルトはマネージャー |
| 実装 | `apps/web/src/routes/organization.tsx`、`apps/web/src/features/organization/components/OrganizationListContainer.tsx` |

画面の項目と、web の型、OpenAPI の項目の対応は [API との対応](api.md) にある。

画面を描くコンポーネントのうち、実装の行のほかのものは次のとおり。

- `apps/web/src/features/organization/components/OrganizationListView.tsx`
- `apps/web/src/features/organization/components/OrganizationUnitDialog.tsx`

## 構成

ヘッダーとナビゲーションは、[職員の一覧](../staff-list_職員の一覧/index.md) と同じ形にする。  
ナビゲーションの今の画面の印は、部署とチームに付ける。  
ナビゲーションの印は、幅 768px 未満ではドロワーを開くと出る。

ヘッダーの下の、ナビゲーションの右に、ページのタイトルとヘルプ、部署のまとまり、チームのまとまりを縦に並べる。  
部署とチームのまとまりは、それぞれ、見出しと作るボタンの行と、一覧を持つ。  
ヘルプの説明の印は、ヘルプを開くと出る。

一覧は詳細の無い一覧なので、[画面仕様書の規約の行の操作](../rules.md#行の操作) のとおり、行の右端に「編集」のボタンを 1 つだけ置き、「›」は置かない。  
幅 768px 未満でも、どの行も 1 行に名前と「編集」を並べる。

作成と編集は、URL を持たないダイアログで、この画面の上に重ねて開く。

## メニュー

**概要**: ナビゲーションの形を切り替える。  
幅 768px 未満では、ナビゲーションのドロワーを開く。

**値のソース**: 3 本の横線のアイコン。  
読み上げる名前は「メニュー」。

**活性条件**: 常に活性

**表示条件**: 常に、ヘッダーの左端に出す。

**カタログ**: [SiteLayoutContainer の Mobile](https://buddy-docs.emon-apps.workers.dev/storybook/?path=/story/画面-common-sitelayoutcontainer--mobile)

### インタラクション

#### 1. 幅 768px 以上で押す

1. ナビゲーションを、開いた形からレールに切り替える。
2. もう一度押すと開いた形に戻る。

#### 2. 幅 768px 未満で押す

1. 左端からナビゲーションのドロワーが開く。

## ナビゲーション

**概要**: 予定、照合、職員、利用者の画面の間を移る。

**値のソース**: 見出しと項目、出す職員は、[職員の一覧のナビゲーション](../staff-list_職員の一覧/index.md#ナビゲーション) にある。  
この画面では「部署とチーム」に今の画面の印を付ける。

**活性条件**: 常に活性

**表示条件**: 常に、ヘッダーの下の左端に出す。  
幅 768px 以上では、この画面では開いた形で始める。  
幅 768px 未満では、メニューのボタンで開いたドロワーの中に出す。

**カタログ**: [SiteNav の Manager](https://buddy-docs.emon-apps.workers.dev/storybook/?path=/story/画面-common-sitenav--manager)

### インタラクション

#### 1. 「カレンダー」「取り込み」「要確認」「連携」「照合」を押す

1. 予定のカレンダー、予定の取り込み、確認が必要な予定、カレンダーの連携、照合の画面へ移る。

#### 2. 「職員」を押す

1. [職員の一覧](../staff-list_職員の一覧/index.md) へ移る。

#### 3. 「部署とチーム」を押す

1. この画面を開き直す。

#### 4. 「利用者」を押す

1. [利用者の一覧](../patient-list_利用者の一覧/index.md) へ移る。

#### 5. 幅 768px 未満で、閉じるボタンか覆いを押すか、Escape キーを押す

1. ナビゲーションのドロワーが閉じ、フォーカスがメニューのボタンに戻る。

## アカウント

**概要**: ログインしている職員を示し、名前、自分の情報、ログアウトを入れたメニューを開く。

**値のソース**: [職員の一覧のアカウント](../staff-list_職員の一覧/index.md#アカウント) と同じ。

**活性条件**: 常に活性

**表示条件**: ログインしているとき

**カタログ**: [ViewerMenu の Default](https://buddy-docs.emon-apps.workers.dev/storybook/?path=/story/画面-common-viewermenu--default)

### インタラクション

#### 1. 押す

1. 職員の名前、自分の情報のリンク、ログアウトのボタンを入れたメニューを、ボタンの下に開く。
2. もう一度押すか、メニューの外を押すか、Escape キーを押すと閉じる。

#### 2. メニューの「自分の情報」を押す

1. メニューを閉じ、[自分の情報](../account-profile_自分の情報/index.md) へ移る。

## ログアウト

**値のソース**: 「ログアウト」

**活性条件**: 常に活性

**表示条件**: アカウントのメニューを開いている間。  
ログインしているとき

**カタログ**: [ViewerMenu の Default](https://buddy-docs.emon-apps.workers.dev/storybook/?path=/story/画面-common-viewermenu--default)

1. ログアウトし、`/` へ移る。
2. ログインしていないので、`/` からそのままログインの画面へ移る。

## ヘルプ

**概要**: 部署とチームをどこで使うかを、見たいときに示す。  
形は、[画面仕様書の規約の補足とヘルプ](../rules.md#補足とヘルプ) の ? のヘルプにする。

**値のソース**: 「?」のボタン。  
読み上げる名前は「ヘルプ」。

## 色

**概要**: チームの色を 8 色から 1 つ選ぶ。

**値のソース**: ラベル「色」の下に、次の 8 つのラジオボタンを、この順に並べる。  
どの選択肢も、直径 8px の色の点と色の名前を並べ、色だけで区別させない。  
幅 768px 以上では 4 つずつ 2 行に、幅 768px 未満では 2 つずつ 4 行に並べる。  
欄の下に、次の補足を出す。

| 補足 |
| --- |
| 「職員の一覧とカレンダーで、チームの名前の前の点に使います。」 |

色の名前と、塗るチームの色は次のとおり。

| 色の名前 | チームの色 |
| --- | --- |
| 「青」 | `team-blue` |
| 「オレンジ」 | `team-orange` |
| 「赤紫」 | `team-magenta` |
| 「青緑」 | `team-cyan` |
| 「黄」 | `team-yellow` |
| 「紫」 | `team-purple` |
| 「緑」 | `team-green` |
| 「黄緑」 | `team-lime` |

作成では、事業所のチームが使っている数が最も少ない色を選んで始め、同じ数なら表の上の色にする。  
事業所でまだ使っていない色があれば、その先頭の色になる。  
作成の初期値の規則は、[予定の管理の Design Doc のチームの色](https://github.com/Fukuemon/buddy/blob/develop/services/schedule/DesignDoc.md#チームの色) の、色を省いてチームを作るときに選ぶ色と同じにする。

編集ではそのチームの今の色を選んで始める。  
ほかのチームが使っている色も選べる。

**活性条件**: 常に活性

**表示条件**: チームの作成と編集のダイアログを開いている間

### インタラクション

## 全体動作

### 決めたこと

- 部署とチームを 1 つの画面にまとめた。
  - どちらも職員の所属で、事業所ごとに数件しかなく、作る頻度も変える頻度も低いためである。
- ナビゲーションは、見出し「職員」の下の「職員」の次に置いた。
  - 部署とチームを使うのは職員の登録と詳細で、職員の管理の権限を持つ職員だけが開く点も職員の画面と同じだからである。
  - 見出し「設定」を作ると、ほかに入れる画面が無いまとまりが 1 つ増える。
- 一覧に詳細を作らず、行の右端に「編集」を 1 つだけ置いた。
  - 行でする操作が、名前と色を変えることだけだからである。
- チームの一覧に、所属する職員の人数を出さない。
  - 人数を見る場面は [職員の一覧](../staff-list_職員の一覧/index.md) のチームの絞り込みで足りる。
- 色の選択肢は、8 色を点と名前で並べ、事業所のほかのチームが使っている色も選べるようにした。
  - チームの色は事業所の中で重なってよく、9 個目のチームからは重なるためである。

### 初期処理

- 職員の管理の権限を持たない職員には、部署とチームを読まずに「権限が無い」の状態を出す。
- 権限を持つ職員には、事業所の部署とチームの両方を読み終えるまで、「読み込み中」の状態を出す。
  - どちらかを読めなかったときは、「読み込みの失敗」の状態にする。
- URL の search params は読まない。

### 権限の確認

職員の管理の権限を持たない職員には、「権限が無い」の状態を出す。  
画面を開いた後に職員の管理の権限を外された職員が「作る」か「保存」を押すと、[保存の失敗の文](#保存の失敗の文) に「この操作をする権限がありません。」を出す。  
権限で許す操作は、[権限の Design Doc の予定の認可](https://github.com/Fukuemon/buddy/blob/develop/services/schedule/internal/access/DesignDoc.md#予定の認可) にある。

## 未決

### 決まっていないこと

- 部署とチームを消せるようにするか。
  - 今の動き: 消せない。この画面は作成と名前と色の変更だけを扱う。
  - 決める人: 開発者
    - 職員が属している部署とチームを消すときの扱いを、先に決める。
  - 期限: 部署とチームの削除を足す issue を作るとき
- 役職の名前とデフォルトの権限を変える画面を作るか。
  - 今の動き: 役職を変える画面は無い。作るときは、この画面に「役職」のまとまりを足せる。
  - 決める人: 開発者
  - 期限: 役職の管理を足すとき
- 「青」「赤紫」「青緑」のような色の名前を、デザインシステムの文書のチームの色に足すか。
  - 今の動き: この画面で仮に決めた名前を出す。デザインシステムの文書のチームの色には、色の名前が無い。
  - 決める人: 開発者
  - 期限: デザインシステムの文書のチームの色を次に直すとき
- 職員の一覧のような、ほかの画面のモックのナビゲーションに、「部署とチーム」の項目を足すか。
  - 今の動き: 画面のナビゲーションには「部署とチーム」が出るが、ほかの画面のモックには無い。
  - 決める人: 開発者
  - 期限: ほかの画面のモックのナビゲーションを次に直すとき
