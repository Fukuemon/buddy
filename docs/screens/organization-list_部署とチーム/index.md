# organization-list 部署とチーム

職員の管理の権限を持つ職員が、事業所の部署とチームを一覧し、作り、名前とチームの色を変える画面。  
部署とチームの削除は扱わない。

| 項目 | 値 |
| --- | --- |
| URL | `/organization` |
| 使う人 | 職員の管理の権限を持つ職員（デフォルトはマネージャー） |
| 実装 | 未実装 |

画面の項目と、web の型、OpenAPI の項目の対応は [API との対応](api.md) にある。

## 構成

ヘッダーとナビゲーションは、[職員の一覧](../staff-list_職員の一覧/index.md) と同じ形にする。  
ナビゲーションは、見出し「職員」の下に「職員」と「部署とチーム」を並べ、今の画面の「部署とチーム」に印を付ける。  
ナビゲーションの印は、幅 768px 未満ではドロワーを開くと出る。

ヘッダーの下の、ナビゲーションの右に、ページのタイトルとヘルプ、部署のまとまり、チームのまとまりを縦に並べる。  
部署とチームのまとまりは、それぞれ、見出しと作るボタンの行と、一覧を持つ。  
一覧は詳細の無い一覧なので、[画面仕様書の規約の行の操作](../rules.md#行の操作) のとおり、行の右端に「編集」のボタンを 1 つだけ置き、「›」は置かない。  
幅 768px 未満でも、どの行も 1 行に名前と「編集」を並べる。  
作成と編集は、URL を持たないダイアログで、この画面の上に重ねて開く。  
ヘルプの説明の印は、ヘルプを開くと出る。

## メニュー

**概要**: ナビゲーションの形を切り替える。  
幅 768px 未満では、ナビゲーションのドロワーを開く。

**値のソース**: 3 本の横線のアイコン。  
読み上げる名前は「メニュー」。

**活性条件**: 常に活性

**表示条件**: 常に、ヘッダーの左端に出す。

**カタログ**: [SiteLayoutContainer の Mobile](https://buddy-docs.emon-apps.workers.dev/storybook/?path=/story/画面-common-sitelayoutcontainer--mobile)

### インタラクション

#### 1. 幅 768px 以上で押す

1. ナビゲーションを、開いた形からレールに切り替える。もう一度押すと開いた形に戻る。

#### 2. 幅 768px 未満で押す

1. 左端からナビゲーションのドロワーが開く。

## ナビゲーション

**概要**: 予定、照合、職員の画面の間を移る。

**値のソース**: [職員の一覧のナビゲーション](../staff-list_職員の一覧/index.md#ナビゲーション) に、次を足す。  
見出し「職員」の下の「職員」の次に、組織の図のアイコンと「部署とチーム」を置く。  
この画面では「部署とチーム」に今の画面の印を付ける。

**活性条件**: 常に活性

**表示条件**: 常に、ヘッダーの下の左端に出す。  
幅 768px 以上では、この画面では開いた形で始める。  
幅 768px 未満では、メニューのボタンで開いたドロワーの中に出す。  
「取り込み」「要確認」「連携」と、見出し「職員」のまとまりは、職員の管理の権限を持つ職員にだけ出す。

**カタログ**: [SiteNav の Manager](https://buddy-docs.emon-apps.workers.dev/storybook/?path=/story/画面-common-sitenav--manager)

### インタラクション

#### 1. 「カレンダー」「取り込み」「要確認」「連携」「照合」を押す

1. 予定のカレンダー、予定の取り込み、確認が必要な予定、カレンダーの連携、照合の画面へ移る。

#### 2. 「職員」を押す

1. [職員の一覧](../staff-list_職員の一覧/index.md) へ移る。

#### 3. 「部署とチーム」を押す

1. この画面を開き直す。

#### 4. 幅 768px 未満で、閉じるボタンか背景を押すか、Escape キーを押す

1. ナビゲーションのドロワーが閉じ、フォーカスがメニューのボタンに戻る。

## アカウント

**概要**: ログインしている職員を示し、名前とログアウトを入れたメニューを開く。

**値のソース**: [職員の一覧のアカウント](../staff-list_職員の一覧/index.md#アカウント) と同じ。

**活性条件**: 常に活性

**表示条件**: ログインしているとき

**カタログ**: [ViewerMenu の Default](https://buddy-docs.emon-apps.workers.dev/storybook/?path=/story/画面-common-viewermenu--default)

### インタラクション

#### 1. 押す

1. 職員の名前とログアウトのボタンを入れたメニューを、ボタンの下に開く。
2. もう一度押すか、メニューの外を押すか、Escape キーを押すと閉じる。

## ログアウト

**概要**: ログアウトする。

**値のソース**: 「ログアウト」

**活性条件**: 常に活性

**表示条件**: アカウントのメニューを開いている間。  
BFF を通して API を呼ぶ構成で、ログインしているとき

**カタログ**: [ViewerMenu の Default](https://buddy-docs.emon-apps.workers.dev/storybook/?path=/story/画面-common-viewermenu--default)

### インタラクション

#### 1. 押す

1. ログアウトし、`/` へ移る。ログインしていないので、`/` からそのままログインの画面へ移る。

## ヘルプ

**概要**: 部署とチームをどこで使うかを、見たいときに示す。  
形は [画面仕様書の規約の補足とヘルプ](../rules.md#補足とヘルプ) の ? のヘルプである。

**値のソース**: 「?」のボタン。読み上げる名前は「ヘルプ」。  
押すと、ページのタイトルの下に次の説明を出す。

| 説明 |
| --- |
| 「部署とチームは、職員の登録と詳細で職員に付けます。チームの色は、職員の一覧とカレンダーで、チームの名前の前の点に使います。」 |

## 全体動作

### 決めたこと

- 部署とチームを 1 つの画面にまとめた。どちらも職員の所属で、事業所ごとに数件しかなく、作る頻度も変える頻度も低いためである。
- ナビゲーションは、見出し「職員」の下の「職員」の次に置いた。
  - 部署とチームを使うのは職員の登録と詳細で、職員の管理の権限を持つ職員だけが開く点も職員の画面と同じだからである。
  - 見出し「設定」を作ると、ほかに入れる画面が無いまとまりが 1 つ増える。
- 一覧に詳細を作らず、行の右端に「編集」を 1 つだけ置いた。行でする操作が、名前と色を変えることだけだからである。
- チームの一覧に、所属する職員の人数を出さない。人数を見る場面は [職員の一覧](../staff-list_職員の一覧/index.md) のチームの絞り込みで足りる。
- 色の選択肢は、8 色を点と名前で並べ、事業所のほかのチームが使っている色も選べるようにした。チームの色は事業所の中で重なってよく、9 個目のチームからは重なるためである。

### 初期処理

- 開くと、ログインした職員の権限を読む。職員の管理の権限が無ければ、ほかの API を呼ばず、「権限が無い」の状態にする。
- 権限があれば、事業所の部署とチームを読み、両方を読み終えるまで「読み込み中」の状態にする。
  - どちらかを読めなかったときは、「読み込みの失敗」の状態にする。
- URL の search params は読まない。

### 色の初期値

チームの作成で最初に選ぶ色は、事業所のチームが使っている数が最も少ない色にし、同じ数なら [色](#色) の表の上の色にする。  
事業所でまだ使っていない色があれば、その先頭の色になる。  
予定の API が、色を省いてチームを作るときに選ぶ色と同じ規則である。  
画面は、読んだチームの色からこの色を決め、選んだ色を送る。

### 権限の確認

画面の判定は表示のためだけにする。  
予定の API も、職員の管理の権限が無い職員のリクエストを 403 で拒む。

## 未決

- 部署とチームの削除は扱わない。職員が属している部署とチームを消すときの扱いを決めてから、別の issue で足す。
- 役職の管理を足すときは、この画面に「役職」のまとまりを足せる。役職の名前とデフォルトの権限を変える画面が要るかは、決めていない。
- 色の名前（「青」「赤紫」「青緑」など）は、この画面で仮に決めた。デザインシステムの文書のチームの色には、色の名前が無い。
- ほかの画面のモック（職員の一覧など）のナビゲーションには、「部署とチーム」の項目をまだ足していない。
