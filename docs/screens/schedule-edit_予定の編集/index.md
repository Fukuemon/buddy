# schedule-edit 予定の編集

職員が、予定 1 件の日時、主訪問者か予定者、訪問の内容、メモを直す画面。  
予定の詳細にある編集のボタンから開き、予定のカレンダーの上にモーダルで重ねて出す。  
保存すると予定の詳細に戻る。

| 項目 | 値 |
| --- | --- |
| URL | `/schedule/$scheduleId/edit`。`/schedule` の子で、カレンダーの search params を引き継ぐ |
| 使う人 | 予定の職員の予定を編集できる職員 |
| 実装 | `apps/web/src/routes/schedule.$scheduleId.edit.tsx`、`apps/web/src/features/schedule/components/ScheduleEditModalContainer.tsx` |

画面の項目と、web の型、OpenAPI の項目の対応は [API との対応](api.md) にある。

画面を描くコンポーネントのうち、実装の行のほかのものは次のとおり。

- `apps/web/src/features/schedule/components/ScheduleFormModal.tsx`
- `apps/web/src/features/schedule/components/ScheduleForm.tsx`

## 構成

モーダルの上端には、左にタイトル、右上に閉じるボタンを置く。  
左に項目の一覧、右に一覧で選んだ項目の入力を置く。  
下端の右には、キャンセルと保存のボタンをこの順に置く。  
読み込み中、読み込みの失敗、権限が無いとき、Google カレンダーで管理している事業所では、下端を出さず、閉じるボタンだけで閉じる。  
幅 768px 未満では、モーダルを画面いっぱいに出し、項目の一覧の下に入力を置く。  
予定の作成と違い、上端に予定の種類のタブを出さない。  
予定の種類は、通常と訪問である。  
予定の種類は編集で変えられない。

## 覆い

**概要**: モーダルの後ろの予定のカレンダーを暗くぼかして覆い、操作できなくする。  
押すとモーダルを閉じる。

**値のソース**: 文言は無い。  
後ろには予定のカレンダーを、`/schedule` の画面として描いたまま残す。

**活性条件**: 常に活性

**表示条件**: 常に表示

**カタログ**: [ScheduleEditModalContainer の Visit](https://buddy-docs.emon-apps.workers.dev/storybook/?path=/story/画面-schedule-scheduleeditmodalcontainer--visit)、[ScheduleEditModalContainer の Loading](https://buddy-docs.emon-apps.workers.dev/storybook/?path=/story/画面-schedule-scheduleeditmodalcontainer--loading)、[ScheduleEditModalContainer の Failed](https://buddy-docs.emon-apps.workers.dev/storybook/?path=/story/画面-schedule-scheduleeditmodalcontainer--failed)

### インタラクション

#### 1. 押す

1. [閉じる](#閉じる) を押したときと同じ結果になる。
   - 押し始めがモーダルの中で、覆いで離したときは閉じない。

## 閉じる

**概要**: 編集をやめてモーダルを閉じる。

**値のソース**: ×のアイコン。  
読み上げの名前は「閉じる」。  
閉じるときに出す確認の文は次のとおり。

## 項目の一覧

**概要**: フォームの項目を、今の値の要約とともに並べる。  
押した項目の入力を右に出す。

**値のソース**: 項目の名前、今の値の要約、入力エラーの文。  
項目と要約は次のとおり。

- 訪問の予定は「訪問日時」「利用者」「主訪問者」「訪問の区分」「メモ」の 5 つ。
- 通常の予定は「タイトル」「予定日時」「予定者」「メモ」の 4 つ。
- 「訪問日時」の要約は「2026-10-20 09:00 - 09:29（29 分、訪看I2）」の形で、日付、開始時間、終了時間、提供時間、サービスコードを並べる。
  - 終了が翌日なら「2026-10-20 23:00 - 翌 00:30（90 分、医）」の形にする。
  - 提供時間が数でなければ、終了時間と提供時間を「-」にする。
- 「予定日時」の要約は「2026-10-20 13:00 - 14:00」の形。
  - 終了は翌日を選んでいれば「2026-10-20 22:00 - 翌 01:00」の形にする。
- 「タイトル」は、空なら何も出さない。
- 「利用者」「主訪問者」「予定者」は、選んだ人の名前。
  - 選んでいなければ、薄い色で「選んでください」と出す。
  - 予定の職員が休職か退職の職員か、訪問しない職員でも、その名前を出す。
- 「訪問の区分」は、選んだ区分を「、」でつなぐ。
  - 何も選んでいなければ「通常」。
- 「メモ」は、空なら何も出さない。
- 値を入れていない項目は、読み上げで、項目の名前と「未入力」を読ませる。

入力エラーの示し方は次のとおり。

- 入力エラーがある項目は、枠を赤く太くし、要約の下にエラーの文を出す。
  - 日付と時間のエラーは「訪問日時」か「予定日時」の 1 つの枠にまとめ、日付、開始時間、終了時間、提供時間の順で最初の 1 つの文を出す。
- 日時とタイトルの入力では、右の入力の欄ごとに、その欄の枠を危険の色で太くし、エラーの文を欄の外の下に出す。
  - 文を入力の欄の中に値の代わりに出さない。
  - 入力の欄には `aria-invalid` と、エラーの文を指す `aria-describedby` を付ける。
- 利用者、主訪問者、予定者は、項目の一覧の枠と文だけで示す。
- エラーの文は次のとおり。

| 項目 | 条件 | 文 |
| --- | --- | --- |
| タイトル（通常） | 空白だけか空 | 「タイトルを入力してください」 |
| 日付 | 日付として読めない | 「日付を入力してください」 |
| 開始時間 | `HH:mm` でない | 「開始時間を入力してください」 |
| 終了時間（通常） | `HH:mm` でない | 「終了時間を入力してください」 |
| 終了時間（通常） | 終了は翌日を選ばず、開始時間より後でない | 「終了時間は開始時間より後にしてください」 |
| 終了時間（通常） | 終了は翌日を選び、開始時間より前でない。24 時間以上になる | 「翌日に終わる予定は、終了時間を開始時間より前にしてください」 |
| 利用者（訪問） | 選んでいない | 「利用者を選んでください」 |
| 主訪問者（訪問） | 選んでいない | 「主訪問者を選んでください」 |
| 予定者（通常） | 選んでいない | 「予定者を選んでください」 |
| 提供時間（訪問） | 数でないか、整数でない | 「提供時間を入力してください」 |
| 提供時間（訪問） | サービスコードの提供時間の範囲の外 | 「訪看I2 の提供時間は 20 分から 29 分です」の形。サービスコード、下限、上限を入れる。下限と上限は、事業所のサービスコードの一覧の値 |

- タイトルとメモの長さは、画面で確認しない。
  - タイトルは 255 文字、メモは 2000 文字まで保存できる。
  - 超えると保存の失敗の文が出る。

**活性条件**: 常に活性

**表示条件**: フォームを出しているとき。  
開いた直後は「訪問日時」か「予定日時」を選んだ状態にする

**値のソース**: 「メモ」の複数行の入力。  
初期値は予定のメモ。

**活性条件**: 常に活性

**表示条件**: 項目の一覧の「メモ」を選んでいるとき

**カタログ**: [TextareaField の Default](https://buddy-docs.emon-apps.workers.dev/storybook/?path=/story/コンポーネント-base-textareafield--default)

## タイトル

**概要**: 通常の予定のタイトルを入力する。

**値のソース**: 「タイトル」の複数行の入力。  
初期値は予定のタイトル。  
訪問の予定のタイトルは画面で入力せず、保存しても今の値のまま変えない。

**活性条件**: 常に活性

**表示条件**: 通常の予定で、項目の一覧の「タイトル」を選んでいるとき

**カタログ**: [TextareaField の Default](https://buddy-docs.emon-apps.workers.dev/storybook/?path=/story/コンポーネント-base-textareafield--default)

## 保存の失敗の文

**概要**: 保存できなかったことと、職員が次にすることを伝える。  
入力は残す。

**値のソース**: 失敗ごとに次の文を出す。  
読み上げでは警告として扱う。

| 失敗 | 文 |
| --- | --- |
| 画面を開いた後に、予定を編集する権限を外された | 「この操作をする権限がありません。」 |
| 入力が保存の規則に合わない | 「入力の内容では予定を更新できません。内容を直してください。」 |
| 画面を開いた後に、事業所が予定を Google カレンダーで管理するようになった | 「この事業所の予定は Google カレンダーで管理しています。予定は Google カレンダーで作成、変更してください。」 |
| ほかの失敗と、つながらない | 「予定を更新できませんでした。」 |

- 保存の規則に合わない項目は、項目の一覧に示さない。

**活性条件**: 常に活性

**表示条件**: 最後の保存が失敗したとき

**カタログ**: [ScheduleFormModal の EditSubmitError](https://buddy-docs.emon-apps.workers.dev/storybook/?path=/story/画面-schedule-scheduleformmodal--edit-submit-error)

## キャンセル

**概要**: 編集をやめてモーダルを閉じる。  
[閉じる](#閉じる) と同じく働く。

**値のソース**: 「キャンセル」

**活性条件**: 常に活性

**表示条件**: フォームを出しているとき

### インタラクション

#### 1. 押す

1. [閉じる](#閉じる) を、フォームを出しているときに押したのと同じ。
   - 入力を変えていなければ、予定の詳細に戻る。
   - 入力を変えていれば、変更を破棄するかの確認を出す。

## 保存

**概要**: 入力を検証し、予定を直す。

**値のソース**: 「保存」。  
送信中は、文字の代わりに回転するインジケーターを出す。

**活性条件**: 送信中でないとき。  
入力を変えていなくても押せる

**表示条件**: フォームを出しているとき

**カタログ**: [ScheduleEditModalContainer の Visit](https://buddy-docs.emon-apps.workers.dev/storybook/?path=/story/画面-schedule-scheduleeditmodalcontainer--visit)

### インタラクション

#### 1. 押す（検証に通らない）

1. 「入力エラー」の状態を出す。
   - 保存はしない。
2. この後は、入力を変えるたびに検証し直す。

#### 2. 押す（検証に通る）

1. 予定を保存し、「送信中」の状態にする。
2. 成功したら、予定の詳細（`/schedule/{予定の id}`）に戻る。
   - `view`、`date`、`staff`、`cancelled` を引き継ぎ、履歴に積む。
   - 成功の文は出さない。
   - 繰り返しの予定の 1 回を保存すると、その回だけを直し、ほかの回は変えない。その回は単発の予定に替わり、詳細の URL の予定の id も替わる。
3. 失敗したら、「保存の失敗」の状態にし、モーダルを開いたままにする。

## 全体動作

### 初期処理

事業所と、職員、利用者、サービスコードの一覧を同時に読み、予定を buddy で管理する事業所と分かってから予定を読む。  
事業所を読めなかったときも、予定を読む。  
全てを読み終えるまでは「読み込み中」の状態を出し、どれかを読めなかったら「読み込みの失敗」の状態を出す。  
事業所が予定を Google カレンダーで管理していると分かったら、予定を読まずに「Google カレンダーで管理している」の状態を出す。  
Google カレンダーの予定は 1 件ずつ読めず、読むと見つからない失敗になるためである。  
読む順と失敗の扱いは、[予定の管理の Design Doc の予定の画面の読み込みと保存](https://github.com/Fukuemon/buddy/blob/develop/services/schedule/DesignDoc.md#予定の画面の読み込みと保存) にある。

読み終えたら、予定の職員の予定を編集できるかを決める。  
編集できなければ、「権限が無い」の状態を出す。  
読んだ予定がキャンセルした予定なら、フォームを出さず、「キャンセルした予定は編集できません。」を出す。  
閉じると、予定のカレンダーに戻る。

フォームの初期値は、読んだ予定の値から作る。  
訪問の予定の提供時間は、開始の時刻から終了の時刻までの分にする。  
予定の種類は、編集で変えられない。

職員の一覧は、休職と退職の職員と、訪問しない職員も含めて読む。  
休職と退職の職員と、訪問しない職員は主訪問者と予定者の候補から除き、項目の一覧の要約で名前を引くのには使う。  
訪問しない職員の扱いは [ADR-0021](../../adr/0021-receipt-check-policy-and-non-visiting-staff.md) にある。

開いた直後のフォーカスは、ダイアログのタイトルに置く。  
Tab キーのフォーカスは、モーダルの中だけを回る。  
閉じると、開く前にフォーカスがあった要素に戻す。

背後の予定のカレンダーは、`/schedule` の画面として描いたまま残す。

時点ごとにできる操作は、次のとおり。

| 時点 | できる操作 | できない操作 |
| --- | --- | --- |
| 読み終える前 | ブラウザの戻る | 閉じる、入力、保存 |
| 読み終え、フォームを出した後 | 全ての操作 | 予定の種類の切り替え |
| 読めなかった後と、権限が無いとき | 閉じる | 入力、保存 |
| Google カレンダーで管理しているとき | 閉じる | 入力、保存 |

### URL の search params からの復元

search params の `view`、`date`、`staff`、`cancelled` は、閉じたときと保存した後に引き継ぐ。  
読めない値は、予定のカレンダーと同じ規則でデフォルト値に置き換える。

### 入力の確認と送信

- 保存を押したときに入力を検証する。
  - 押した後は、入力を変えるたびに検証し直す。
- 予定の職員か利用者が一覧に無いときは、「選んでください」と出したまま検証に通し、その値のまま保存する。
  - 保存を拒まれれば、「保存の失敗」の状態になる。
- 保存を拒まれたときと、つながらないときは、「保存の失敗」の状態にし、[保存の失敗の文](#保存の失敗の文) を出す。
  - 権限を外されたときと、入力が保存の規則に合わないときは、読み直さずにすぐ文を出す。

### 変えた後の表示

保存に成功すると、予定のカレンダーの予定を読み直した結果を出す。  
予定の日付を変えたときも、カレンダーの `date` は変えない。

### 権限の確認

画面は、ログインした職員の予定の権限から、職員ごとに予定を見られるかと編集できるかを決める。  
規則は [画面仕様書の規約の権限の出し分け](../rules.md#権限の出し分け) にある。

- 予定の職員の予定を編集できないときは、フォームを出さず、「権限が無い」の状態を出す。
  - 予定の詳細は「編集」を出さないので、編集の URL を直に開いたときにだけ起きる。
- 見る権限の無い予定を開くと、「読み込みの失敗」の状態にし、「この予定を見る権限がありません。」を出す。
- 主訪問者と予定者の候補には、ログインした職員が予定を編集できる職員だけを出す。
  - 休職と退職の職員と、訪問しない職員は、権限によらず除く。
- 利用者の候補は、権限で絞らない。
- 画面を開いた後に予定を編集する権限を外された職員が保存を押すと、「保存の失敗」の状態にし、「この操作をする権限がありません。」を出す。
