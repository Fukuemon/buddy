# schedule-edit 予定の編集

職員が、予定 1 件の日時、担当者、訪問の内容、メモを直す画面。  
予定の詳細にある編集のボタンから開き、予定のカレンダーの上にモーダルで重ねて出す。  
保存すると予定の詳細に戻る。

| 項目 | 値 |
| --- | --- |
| URL | `/schedule/$scheduleId/edit`。`/schedule` の子で、カレンダーの search params を引き継ぐ |
| 使う人 | 予定を編集する権限を持つ職員 |
| 実装 | `apps/web/src/routes/schedule.$scheduleId.edit.tsx`、`apps/web/src/features/schedule/components/ScheduleEditModalContainer.tsx`、`apps/web/src/features/schedule/components/ScheduleFormModal.tsx`、`apps/web/src/features/schedule/components/ScheduleForm.tsx` |

画面の項目と、web の型、OpenAPI の項目の対応は [API との対応](api.md) にある。

## 構成

モーダルの上端には、左にタイトル、右上に閉じるボタンを置く。  
左に項目の一覧、右に一覧で選んだ項目の入力を置く。  
下端の右には、キャンセルと保存のボタンをこの順に置く。  
読み込み中と読み込みの失敗では、下端を出さず、閉じるボタンだけで閉じる。  
幅 768px 未満では、モーダルを画面いっぱいに出し、項目の一覧の下に入力を置く。  
予定の作成と違い、上端に予定の種類（通常と訪問）のタブを出さない。  
予定の種類は編集で変えられない。

## 覆い

**概要**: モーダルの後ろの予定のカレンダーを暗くぼかして覆い、操作できなくする。押すとモーダルを閉じる。

**値のソース**: 文言は無い。後ろには予定のカレンダーを、`/schedule` の画面として描いたまま残す。

**活性条件**: 常に活性

**表示条件**: 常に表示

**カタログ**: [ScheduleEditModalContainer の Visit](https://buddy-docs.emon-apps.workers.dev/storybook/?path=/story/画面-schedule-scheduleeditmodalcontainer--visit)、[ScheduleEditModalContainer の Loading](https://buddy-docs.emon-apps.workers.dev/storybook/?path=/story/画面-schedule-scheduleeditmodalcontainer--loading)、[ScheduleEditModalContainer の Failed](https://buddy-docs.emon-apps.workers.dev/storybook/?path=/story/画面-schedule-scheduleeditmodalcontainer--failed)

### インタラクション

#### 1. 押す

1. [閉じる](#閉じる) を押したときと同じ結果になる。押し始めがモーダルの中で、覆いで離したときは閉じない。

## 閉じる

**概要**: 編集をやめてモーダルを閉じる。

**値のソース**: ×のアイコン。読み上げの名前は「閉じる」。閉じるときに出す確認の文は次のとおり。

| 条件 | 文 |
| --- | --- |
| 入力を変えた | 変更が破棄されますがよろしいですか？ |

**活性条件**: 常に押せる。読み込み中は、押しても何も起きない

**表示条件**: 常に表示

**カタログ**: [ScheduleEditModalContainer の Visit](https://buddy-docs.emon-apps.workers.dev/storybook/?path=/story/画面-schedule-scheduleeditmodalcontainer--visit)、[ScheduleEditModalContainer の Loading](https://buddy-docs.emon-apps.workers.dev/storybook/?path=/story/画面-schedule-scheduleeditmodalcontainer--loading)、[ScheduleEditModalContainer の Failed](https://buddy-docs.emon-apps.workers.dev/storybook/?path=/story/画面-schedule-scheduleeditmodalcontainer--failed)

### インタラクション

#### 1. 押すか、Escape キーを押す（フォームを出している）

1. 入力を変えていなければ、予定の詳細に戻る。カレンダーの search params の `view`、`date`、`staff`、`cancelled` を引き継ぐ。
2. 入力を変えていれば、変更を破棄するかの確認を出す。OK なら予定の詳細に戻り、キャンセルならモーダルに留まる。

#### 2. 押すか、Escape キーを押す（読み込みの失敗）

1. 予定の詳細ではなく、予定のカレンダー（`/schedule`）に戻る。`view`、`date`、`staff`、`cancelled` を引き継ぐ。

#### 3. 押すか、Escape キーを押す（読み込み中）

1. 何も起きない。

**概要**: 予定、職員、利用者を取っている間であることを示す。

**値のソース**: 回転するインジケーターだけ。文は出さない。

**活性条件**: 常に活性

## 読み込みの失敗の文

**概要**: 予定を開けなかったことを伝える。

**値のソース**: 「予定を取得できませんでした。」。読み上げでは警告として扱う。予定の詳細と違い、予定が見つからないときも「予定が見つかりません。」に分けない。

**活性条件**: 常に活性

**表示条件**: 3 つのどれかを読めなかったとき。何度か読み直してから出すので、その間は読み込み中の表示が続く

## 項目の一覧

**概要**: フォームの項目を、今の値の要約とともに並べる。押した項目の入力を右に出す。

**値のソース**: 項目の名前、今の値の要約、入力エラーの文。項目と要約は次のとおり。

- 訪問の予定は「訪問日時」「利用者」「担当者」「訪問の種類」「メモ」の 5 つ。
- 通常の予定は「タイトル」「予定日時」「予定者」「メモ」の 4 つ。
- 「訪問日時」の要約は「2026-10-20 09:00 - 09:29（29 分、訪看I2）」の形で、日付、開始時間、終了時間、提供時間、サービスコードを並べる。提供時間が数でなければ、終了時間と提供時間を「-」にする。
- 「予定日時」の要約は「2026-10-20 13:00 - 14:00」の形。
- 「タイトル」は、空なら何も出さない。
- 「利用者」「担当者」「予定者」は、選んだ人の名前。選んでいなければ、薄い色で「選んでください」と出す。予定の職員が休職か退職の職員か、訪問しない職員でも、その名前を出す。
- 「訪問の種類」は、選んだ種類を「、」でつなぐ。何も選んでいなければ「通常」。
- 「メモ」は、空なら何も出さない。
- 値を入れていない項目は、読み上げで、項目の名前と「未入力」を読ませる。
- 入力エラーがある項目は、枠を赤く太くし、要約の下にエラーの文を出す。日付と時間のエラーは「訪問日時」か「予定日時」の 1 つの枠にまとめ、日付、開始時間、終了時間、提供時間の順で最初の 1 つの文を出す。
- 日時とタイトルの入力では、右の入力の欄ごとに、その欄の枠を危険の色で太くし、エラーの文を欄の外の下に出す。文を入力の欄の中に値の代わりに出さない。
  - 入力の欄には `aria-invalid` と、エラーの文を指す `aria-describedby` を付ける。
- 利用者と担当者は、項目の一覧の枠と文だけで示す。
- エラーの文は次のとおり。

| 項目 | 条件 | 文 |
| --- | --- | --- |
| タイトル（通常） | 空白だけか空 | タイトルを入力してください |
| 日付 | 日付として読めない | 日付を入力してください |
| 開始時間 | `HH:mm` でない | 開始時間を入力してください |
| 終了時間（通常） | `HH:mm` でない | 終了時間を入力してください |
| 終了時間（通常） | 開始時間より後でない | 終了時間は開始時間より後にしてください |
| 利用者（訪問） | 選んでいない | 利用者を選んでください |
| 担当者、予定者 | 選んでいない | 担当者を選んでください |
| 提供時間（訪問） | 数でないか、整数でない | 提供時間を入力してください |
| 提供時間（訪問） | サービスコードの範囲の外 | {サービスコード} の提供時間は {下限} 分から {上限} 分です |
| 提供時間（訪問） | 開始時間に足すと日をまたぐ | 終了が日をまたがないよう、開始時間か提供時間を変えてください |

- タイトルとメモの長さは、画面で確認しない。タイトルは 255 文字、メモは 2000 文字まで保存できる。超えると保存の失敗の文が出る。

## 全体動作

### 初期処理

- 予定と、職員と利用者の一覧を同時に読む。3 つを読み終えるまでは「読み込み中」の状態を出し、どれかを読めなかったら「読み込みの失敗」の状態を出す。
  - 読む順と失敗の扱いは、[予定の管理の Design Doc の予定の画面の読み込みと保存](https://github.com/Fukuemon/buddy/blob/develop/services/schedule/DesignDoc.md#予定の画面の読み込みと保存) にある。
- フォームの初期値は、読んだ予定の値から作る。訪問の予定の提供時間は、開始の時刻から終了の時刻までの分にする。
- 職員の一覧は、休職と退職の職員と、訪問しない職員も含めて読む。休職と退職の職員と、訪問しない職員は担当者の候補から除き、項目の一覧の要約で名前を引くのには使う。訪問しない職員の扱いは [ADR-0022](../../adr/0022-receipt-check-policy-and-non-visiting-staff.md) にある。
- 開いた直後のフォーカスは、ダイアログのタイトルに置く。Tab キーのフォーカスは、モーダルの中だけを回る。閉じると、開く前にフォーカスがあった要素に戻す。
- 背後の予定のカレンダーは、`/schedule` の画面として描いたまま残す。
- 読んだ予定がキャンセルした予定なら、フォームを出さず、「キャンセルした予定は編集できません。」を出す。閉じると、予定のカレンダーに戻る。
- 予定の種類（通常と訪問）は、編集で変えられない。

| 時点 | できる操作 | できない操作 |
| --- | --- | --- |
| 3 つを読み終える前 | ブラウザの戻る | 閉じる、入力、保存 |
| 3 つを読み終えた後 | 全ての操作 | 予定の種類の切り替え |
| 読めなかった後 | 閉じる | 入力、保存 |

### URL の search params からの復元

- search params の `view`、`date`、`staff`、`cancelled` は、閉じたときと保存した後に引き継ぐ。読めない値は、予定のカレンダーと同じ規則でデフォルト値に置き換える。

### 入力の確認と送信

- 保存を押したときに入力を検証する。押した後は、入力を変えるたびに検証し直す。
- 予定の職員か利用者が一覧に無いときは、「選んでください」と出したまま検証に通し、その値のまま保存する。保存を拒まれれば、「保存の失敗」の状態になる。

### 変えた後の表示

- 保存に成功すると、予定のカレンダーの予定を読み直した結果を出す。予定の日付を変えたときも、カレンダーの `date` は変えない。

### 権限の確認

- 編集の権限の外の予定も、開くとフォームを出す。保存を押すと、「保存の失敗」の状態になる。
- 見る権限の無い予定を開くと、「読み込みの失敗」の状態になる。

## 未決

  - 今の動き: フォームを出し、保存を押すと「保存の失敗」の状態になる。
  - 決める人: 開発者
  - 期限: #383
- 職員と利用者の一覧に、編集の権限の外の人を出すか。
  - 今の動き: 事業所の全ての職員と利用者を出す（休職と退職の職員と、訪問しない職員を除く）。
  - 決める人: 開発者
  - 期限: #383

  - 今の動き: どれも「予定を更新できませんでした。」を出し、項目には示さない。
  - 決める人: 開発者

### PRD と実装の食い違い

- PRD は、訪問の予定に同行者を持たせ、毎週と毎月の繰り返しの予定を作れるとしている。この画面は、予定の作成と同じく、同行者と繰り返しを編集できない。
  - 決める人: 開発者が、事業所の責任者に確認して決める
  - 期限: 同行者と繰り返しの予定を画面で扱うとき
- PRD と Design Doc は、サービスコードを「訪看I２」のように全角の数字で書き、画面は半角の数字で書く。
  - 決める人: 開発者
  - 期限: 画面の語を PRD にそろえるとき
- PRD は、訪問の予定の職員を「主訪問者」、夜勤、緊急、入院を「訪問の区分」と呼ぶ。画面は「担当者」「訪問の種類」と出す。
  - 決める人: 開発者が、事業所の責任者に確認して決める
  - 期限: 画面の語を PRD にそろえるとき
