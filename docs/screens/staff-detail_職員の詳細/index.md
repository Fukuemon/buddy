# staff-detail 職員の詳細

職員の管理の権限を持つ職員が、1 人の職員の基本の情報、役職、権限、在籍の状態を見て変える画面。  
休職、復職、退職もこの画面で行う。

| 項目 | 値 |
| --- | --- |
| URL | `/staff/$staffId` |
| 使う人 | 職員の管理の権限を持つ職員（デフォルトはマネージャー） |
| 実装 | 未実装 |

画面の項目と、web の型、OpenAPI の項目の対応は [API との対応](api.md) にある。

## 構成

ヘッダーとナビゲーションは、[職員の一覧](../staff-list_職員の一覧/index.md) と同じである。  
ナビゲーションの今の画面の印は、職員に付ける。

ヘッダーの下の、ナビゲーションの右に、職員の一覧へのリンク、職員の名前と状態の印、基本の情報、役職、権限、在籍の 4 つの枠を縦に並べる。  
役職を変える、権限を足す、休職、退職の確認は、URL を持たないダイアログを詳細の上に重ねて出す。  
基本の情報の編集は、ダイアログにせず、基本の情報の枠を入力の欄に替える。  
幅 768px 未満では、基本の情報の項目の名前と値を縦に積み、権限の一覧の行を、見出しと値の組を縦に積んだ箱にする。

ADR-0018: [職員の停止を、戻せる休職と、戻せない退職に分ける](../../adr/0018-staff-leave-and-retirement.md)

## メニュー

**概要**: ナビゲーションの形を切り替える。  
幅 768px 未満では、ナビゲーションのドロワーを開く。

**値のソース**: 3 本の横線のアイコン。  
読み上げる名前は「メニュー」。

**活性条件**: 常に活性

**表示条件**: 常に、ヘッダーの左端に出す。

**カタログ**: [SiteLayoutContainer の Mobile](https://buddy-docs.emon-apps.workers.dev/storybook/?path=/story/画面-common-sitelayoutcontainer--mobile)

### インタラクション

#### 1. 幅 768px 以上で押す

1. ナビゲーションを、開いた形からレールに切り替える。もう一度押すと開いた形に戻る。

#### 2. 幅 768px 未満で押す

1. 左端からナビゲーションのドロワーが開く。

## ナビゲーション

**概要**: 予定、照合、職員の画面の間を移る。

**値のソース**: [職員の一覧のナビゲーション](../staff-list_職員の一覧/index.md#ナビゲーション) と同じ。  
この画面でも「職員」に今の画面の印を付ける。

**活性条件**: 常に活性

**表示条件**: 常に、ヘッダーの下の左端に出す。  
幅 768px 未満では、メニューのボタンで開いたドロワーの中に出す。

**カタログ**: [SiteNav の Manager](https://buddy-docs.emon-apps.workers.dev/storybook/?path=/story/画面-common-sitenav--manager)

### インタラクション

#### 1. 項目を押す

1. 押した項目の画面へ移る。「職員」を押すと、職員の一覧へ移る。

#### 2. 幅 768px 未満で、閉じるボタンか背景を押すか、Escape キーを押す

1. ナビゲーションのドロワーが閉じ、フォーカスがメニューのボタンに戻る。

## アカウント

**概要**: ログインしている職員を示し、名前とログアウトを入れたメニューを開く。

**値のソース**: 職員の名前の先頭の 1 文字を入れた丸と、職員の名前を並べたボタン。  
幅 768px 未満では、丸だけを出す。  
読み上げる名前は「アカウント（<職員の名前>）」にし、幅 768px 未満で名前を隠しても変えない。

**活性条件**: 常に活性

**表示条件**: ログインしているとき

**カタログ**: [ViewerMenu の Default](https://buddy-docs.emon-apps.workers.dev/storybook/?path=/story/画面-common-viewermenu--default)

### インタラクション

## 残る予定と担当の一覧

**概要**: 休職か退職にする職員に、今日（事業所の現地の日付）以降に残る予定、繰り返しの予定、担当の利用者を示す。  
予定と繰り返しの予定は、職員が予定の職員、主訪問者、同行者のどれかのもので、キャンセルした予定を含めない。  
休職では割り振り直すかを決める材料にし、退職では割り振り直すまで退職にできないことを示す。

**値のソース**: 注意の面の色の枠の中に、次の見出しの文と、「予定（<件数> 件）」「繰り返しの予定（<件数> 件）」「担当の利用者（<人数> 人）」の 3 つのまとまりを出す。  
件数が 0 のまとまりは省く。

| ダイアログ | 見出しの文 |
| --- | --- |
| 休職 | 「今日以降の予定と担当の利用者が残っています。休職の間は誰も行かないので、必要なら別の職員に割り振り直してください。」 |
| 退職 | 「今日以降の予定と担当の利用者が残っています。別の職員に割り振り直してから、退職にしてください。」 |

3 つとも 0 件のときは、枠を出さずに「今日以降の予定と担当の利用者は残っていません。」を出す。

**活性条件**: 常に活性

**表示条件**: 休職と退職のダイアログで、残る予定と担当の利用者を読み終えたとき

3. 自分か、事業所で職員の管理の権限を持つ最後の有効な職員を休職にしようとして拒まれたら、ダイアログを閉じずに、ボタンの左に「自分と、職員の管理の権限を持つ最後の有効な職員は、休職にできません。」を出す。

## 復職にする

**概要**: 休職の職員を有効に戻す。

**値のソース**: 次の文言。

| 状態 | 文言 |
| --- | --- |
| 送る前 | 「復職にする」 |
| 送っている間 | 「復職にしています」 |

**活性条件**: 送っていない間

**表示条件**: 休職の職員のとき

### インタラクション

#### 1. 押す

1. 確認のダイアログを出さずに、職員を復職にする。休職は、もう一度休職にすれば戻せる。
2. 復職にできたら、返った職員で「詳細」の状態にする。職員は、休職の前に結び付けた上流のアカウントで、そのままログインできる。

## 退職にする

**概要**: 職員を退職にする。

**値のソース**: 「退職にする」。危険な操作の色で出す。

**活性条件**: 常に活性

**表示条件**: 有効か休職の職員で、ログインした職員と違う職員のとき。  
自分の詳細では出さない。

### インタラクション

#### 1. 押す

1. 退職のダイアログを開き、その職員の今日以降の予定と担当の利用者を読む。
2. 読んでいる間は、残る予定と担当の一覧の位置に、[読み込み中の表示](#読み込み中の表示) と同じ回転の印と文言を出し、ダイアログの退職にするを押せなくする。
3. 一覧が空なら「退職の確認」の状態に、空でなければ「退職を拒む」の状態にする。

## 退職のダイアログ

**概要**: 退職にする前に、戻せないことと、残る予定と担当の利用者を示す。

**値のソース**: 残る予定と担当の利用者があるかで、次のタイトルにする。

| 残る予定と担当の利用者 | タイトル |
| --- | --- |
| 無い | 「<職員の名前> を退職にしますか」 |
| ある | 「<職員の名前> を退職にできません」 |

**活性条件**: 常に活性

**表示条件**: 退職にするを押してから、閉じるまで

## 退職の注意

**概要**: 退職は戻せないことと、退職で消えるものと残るものを示す。

**値のソース**: 次の文言。

| 文言 |
| --- |
| 「退職は戻せません。メールアドレスと電話番号を消し、<職員の名前> はログインできなくなります。名前、所属、役職は、過去の予定と照合の結果のために残ります。同じ人を再び雇うときは、新しい職員として登録します。」 |

**活性条件**: 常に活性

**表示条件**: 退職のダイアログを開いている間

## ダイアログの退職にする

**概要**: 職員を退職にする。

**値のソース**: 次の文言。危険な操作の色で出す。

| 状態 | 文言 |
| --- | --- |
| 送る前 | 「退職にする」 |
| 送っている間 | 「退職にしています」 |

**活性条件**: 残る予定と担当の利用者を読み終え、一覧が空で、送っていない間

**表示条件**: 退職のダイアログを開いている間

### インタラクション

#### 1. 押す

1. 職員を退職にする。
2. 退職にできたら、ダイアログを閉じ、返った職員で「退職した職員」の状態にする。
3. ダイアログを開いた後に予定か担当の利用者が増え、予定の API が拒んだら、返った一覧で「退職を拒む」の状態にする。

## 全体動作

### 初期処理

- 開くと、ログインした職員の権限を読む。職員の管理の権限が無ければ、ほかの API を呼ばず、[職員の一覧](../staff-list_職員の一覧/index.md) の「権限が無い」の状態と同じ表示にする。
- 権限があれば、URL の職員を読み、読み終えるまで「読み込み中」の状態にする。
  - 職員の状態に合わせて、「詳細」「休職の職員」「退職した職員」のどれかの状態にする。
  - 権限の対象の名前を出すために、事業所の職員とチームも読む。
- 基本の情報の編集、役職、権限の選択肢は、それぞれを開いたときに読む。
- URL の search params は読まない。

### 自分の詳細

ログインした職員が自分の詳細を開いたときは、休職にすると退職にするを出さない。  
基本の情報、役職、権限は変えられる。  
自分の職員の管理の権限を外すか、その権限を持たない役職に変えると、画面を開き直したときに「権限が無い」の表示になる。

### 変えた後の表示

職員を変える操作は、どれも返った職員でこの画面を出し直す。  
職員の一覧には、一覧へ戻ったときに読み直して出す。  
休職か退職にされた職員がログインしていれば、5 分以内に使えなくなる。

### 権限の確認

画面の判定は表示のためだけにする。  
予定の API も、職員の管理の権限が無い職員のリクエストを 403 で拒む。  
画面を開いた後に権限を外された職員が操作したときは、ダイアログの中か理由の文の位置に「この操作をする権限がありません。」を出す。

## 未決

- 休職の職員の戻る予定の日を、復職にせずに変える操作は描いていない。予定の API は、休職の職員を休職にし直すと、戻る予定の日だけを書き換える。戻し忘れが問題になったら、在籍の枠に「戻る予定の日を変える」を足すかを決める。
- 残る予定と担当の利用者を、その場で別の職員に割り振り直す操作は無い。予定は予定の詳細から 1 件ずつ編集する。繰り返しの予定と担当の利用者を割り振り直す画面は、利用者の画面を作るときに決める。
- 権限を外す操作に確認のダイアログを出さない。外した権限は足し直せるためである。職員の管理の権限を外す操作だけは確認を出すかを、実装のときに決める。
- 退職した職員の権限と役職を変えられるかは、予定の API の役職と権限の操作では決まっていない。この画面は、退職した職員の変える操作を全て出さない。
