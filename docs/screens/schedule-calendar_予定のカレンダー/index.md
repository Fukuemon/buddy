# schedule-calendar 予定のカレンダー

職員が、事業所の職員の予定を月、週、日の表示で見て、予定の作成と詳細を開く画面。表示する職員を、チームと職員のチェックボックスで絞り込む。

| 項目 | 値 |
| --- | --- |
| URL | `/schedule`。`/` を開くと `/schedule` へ転送する |
| 使う人 | 全ての職員。表示する予定は、閲覧の権限の範囲で決まる |
| 実装 | `apps/web/src/routes/schedule.tsx`、`ScheduleCalendarContainer`、`StaffFilterSidebarContainer`、`SiteHeaderContainer` |

画面の項目と、web の型、OpenAPI の項目の対応は [API との対応](api.md) にある。

## 構成

画面は、上端のヘッダー、左の職員の絞り込み、右のカレンダーの 3 つに分かれる。カレンダーの上に、表示する期間と表示の単位を変えるツールバーを置く。カレンダーの領域は、予定の一覧と職員の一覧の 2 つの取得の結果で表示を変える。

## ナビゲーション

**概要**: 予定と照合の画面を行き来する。

**値のソース**: 「予定」と「照合」のリンク。この画面では「予定」を今の画面として示す。

**活性条件**: 常に活性

**表示条件**: 常に表示

### インタラクション

#### 1. 「予定」を押す

1. `/schedule` を読み込み直す。search params は消え、今日の月の表示に戻る。

#### 2. 「照合」を押す

1. 照合の画面へ移る。

## ログインした職員

**概要**: ログインしている職員を示す。

**値のソース**: 職員の名前。

**活性条件**: 常に活性

**表示条件**: ログインしているとき。幅 768px 未満では出さない

## ログアウト

**概要**: ログアウトする。

**値のソース**: 「ログアウト」

**活性条件**: 常に活性

**表示条件**: BFF を通して API を呼ぶ動かし方で、ログインしているとき

### インタラクション

#### 1. 押す

1. ログアウトし、ログインの画面へ移る。

## 職員の絞り込み

**概要**: 予定を出す職員を、チームと職員のチェックボックスで絞り込む。

**値のソース**: 見出し「職員」と、チームごとのチェックボックスの組。チームの下に、そのチームの職員を字下げして並べる。

**活性条件**: 常に活性

**表示条件**: 常に表示。取得の結果によらず、取れた分だけを出す。チームと職員の取得が終わるまでは、見出しと「全員を表示」だけを出す。幅 768px 未満では、カレンダーの上に高さ 160px までで置き、超えた分は中で縦に送る

## 全員を表示

**概要**: 絞り込みを解き、全ての職員の予定を出す。

**値のソース**: 「全員を表示」

**活性条件**: URL の `staff` が空でない（絞り込んでいる）とき

**表示条件**: 常に表示

### インタラクション

#### 1. 押す

1. URL から `staff` を消し、全ての職員を出す。

## チームのチェックボックス

**概要**: チームの職員をまとめて選ぶ、外す。

**値のソース**: チームの名前。チームの職員が全員選ばれていれば印が付き、一部なら中間の印が付く。絞り込んでいないときは全て付く。

**活性条件**: 常に活性。ただし、外すと表示する職員が 0 人になる操作は受け付けない

**表示条件**: チームの取得が成功したとき。チームの下の職員は、職員の取得が成功した後に出る。API につないだ後に閲覧の権限の外の職員を出すかは未決

### インタラクション

#### 1. 外す、付ける

1. 外すときは、チームの外に選ばれた職員がいることを前提にする。
2. チームの職員をまとめて外す、付ける。URL の変わり方は職員のチェックボックスと同じ。

## 職員のチェックボックス

**概要**: 予定を出す職員を 1 人ずつ選ぶ。

**値のソース**: 職員の名前。絞り込んでいないときは全て付く。

**活性条件**: 常に活性。ただし、最後の 1 人を外す操作は受け付けない

**表示条件**: 職員の取得が成功し、職員がチームに属するとき。閲覧の権限の外の職員を出すかは未決

### インタラクション

#### 1. 外す、付ける

1. 外すときは、ほかに選ばれた職員がいることを前提にする。
2. URL の `staff` を、選んだ職員の id の並びにする。全員を選ぶと `staff` を消す。

## 前へ

**概要**: 表示する期間を前に戻す。

**値のソース**: 左向きの矢印。読み上げの名前は「前へ」。

**活性条件**: 常に活性（読み込み中も押せる）

**表示条件**: 常に表示

### インタラクション

#### 1. 押す

1. 表示の基準の日付を、月の表示なら前の月の 1 日、週なら 7 日前、日なら 1 日前にする。
2. URL の `date` が変わり、その期間の予定を取る。

## 今日

**概要**: 今日を含む期間に戻る。

**値のソース**: 「今日」

**活性条件**: 常に活性（読み込み中も押せる）

**表示条件**: 常に表示

### インタラクション

#### 1. 押す

1. URL から `date` を消し、今日を含む期間を出す。

## 次へ

**概要**: 表示する期間を先に進める。

**値のソース**: 右向きの矢印。読み上げの名前は「次へ」。

**活性条件**: 常に活性（読み込み中も押せる）

**表示条件**: 常に表示

### インタラクション

#### 1. 押す

1. 表示の基準の日付を、月の表示なら次の月の 1 日、週なら 7 日後、日なら 1 日後にする。
2. URL の `date` が変わり、その期間の予定を取る。

## 表示する日付

**概要**: 表示の基準の日付を選ぶ。

**値のソース**: 表示の基準の日付。URL の `date` が無ければ今日。

**活性条件**: 常に活性（読み込み中も入力できる）

**表示条件**: 常に表示

### インタラクション

#### 1. 日付を選ぶ

1. URL の `date` を選んだ日にする。
2. 入力を空にしたときは何もしない。

## 表示の単位

**概要**: カレンダーを月、週、日のどれで出すかを選ぶ。

**値のソース**: 「月」「週」「日」。URL の `view` の値を選んだ状態で出す。

**活性条件**: 常に活性（読み込み中も押せる）

**表示条件**: 常に表示。幅 768px 未満では幅いっぱいにする

### インタラクション

#### 1. 押す

1. URL の `view` を変える。`month` は既定の値なので URL から消える。

## 予定を作成

## カレンダー

**概要**: 月と週の表示で、予定を日と時刻の枠に置く。

**値のソース**: 月の表示は、月の初日を含む週の日曜から 6 週分の日付。週は日曜に始まる。週の表示は、日曜から 7 日分の日付と、6 時から 22 時の時刻。

**活性条件**: 常に活性

**表示条件**: 表示の単位が月か週で、予定と職員の取得が成功したとき

## 予定

**概要**: 1 件の予定を示し、詳細を開く。

**値のソース**: 月と週の表示は、開始の時刻と題。日の表示は、開始と終了の時刻と題。

- 題は、訪問の予定なら「<利用者の名前> 訪問」、通常の予定なら予定のタイトルにする。利用者の一覧を取り終える前と、取得に失敗したときは「利用者不明 訪問」になる。
- 色は、職員の一覧の並びの位置で、区別の色の 10 色から決める。11 人目からは色が重なる。職員の一覧に無い職員の予定は灰色にする。
- 週と日の表示では、予定の長さで高さが決まる。日の表示の高さは 20px 以上にする。30 分未満の予定は、押せる領域が 44px に届かない。

**活性条件**: 常に活性

**表示条件**: 予定が表示の期間に重なり、URL の `staff` が空か、`staff` に担当の職員を含むとき。API につないだ後は、自分の予定を常に出す。ほかの職員の予定は、全ての予定の閲覧、指定した職員の予定の閲覧、指定したチームの職員の予定の閲覧のどれかで対象のときだけ出す。権限の名前は、PRD の役職ごとの権限にある 7 つの権限を指す。編集の権限は同じ範囲の閲覧を含む。閲覧の権限が無い職員の予定は API が一覧から除き、画面は案内の文を出さない

### インタラクション

#### 1. 押す

1. 予定の詳細をこの画面の上に開く。URL は `/schedule/<予定の id>` にし、`view`、`date`、`staff` を引き継ぐ。

## 全体動作

### 初期処理

- 予定はブラウザだけで描き、サーバーは予定を描かない。
- 開いた直後のフォーカスは `body` にある。フォーカスを特定の要素へ移す処理は無い。
- 予定、職員、チーム、利用者の一覧を取る。取得が終わる前は、ツールバーの全ての操作と、絞り込んでいるときの「全員を表示」を受け付ける。カレンダーを出していないので、予定、空いた日、空いた時間、時間の枠は押せない。取得が終わった後は、全ての操作を受け付ける。
- 取得の失敗は、3 回まで取り直してから出す。
- BFF を通すときに API が 401 を返したら、今の画面に戻るログインの画面へ移る。偽物の API は 401 を返さない。

### 履歴と、予定のモーダル

- URL を変える操作は、どれも履歴に積む。ブラウザの戻るで前の表示に戻る。
- 予定の作成、詳細、編集は、この画面の上にモーダルで重ねて出す。モーダルの URL は `/schedule` の子で、カレンダーの search params を引き継ぐ。

### 幅による配置

- 職員の絞り込みのチェックボックス、「全員を表示」、予定、空いた時間の枠の押せる領域は 44px 以上にする。

幅 768px 未満では、配置を次のように変える。ページは幅 320px でも横に送らない。

- 職員の絞り込みを、カレンダーの上に置く。
- ツールバーを折り返し、表示の単位を幅いっぱいにする。
- カレンダーの左右の余白を 8px にする。
- 日の表示の職員の列は、職員ごとの日の表の中で横に送る。

### URL の search params からの復元

読めない値は既定の値に置き換え、既定の値は URL から消す。

| search param | 値 | 省いたときと読めないとき |
| --- | --- | --- |
| `view` | `month`、`week`、`day` | `month` |
| `date` | `YYYY-MM-DD` | 今日 |
| `staff` | 職員の id の配列。`staff=a&staff=b` の形 | 空の配列（全ての職員） |

## 未決

PRD と実装が食い違うところ。

- PRD は、表示する職員を「全体、自分、チーム」のチェックボックスで切り替えるとしている。実装は、チームと職員のチェックボックスと「全員を表示」のボタンを持ち、「自分」の切り替えを持たない。
- PRD は、初めて開いたときに見る権限がある職員の全部を出すとしている。実装は、偽物の API の事業所の全ての職員を出す。職員の絞り込みに閲覧の権限の外の職員を出すかが決まっていない。
- PRD の時間外の勤務の印を、カレンダーに出していない。

決まっていないところ。

- 予定が 0 件のときに、案内の文を出すか。
- 403 と 404 も、取得の失敗として 3 回取り直してから出している。4xx を取り直さないかが決まっていない。
- 403 を、ほかの取得の失敗と同じ文で出すか、権限が無いことを示す文に分けるか。
- 週と日の表示は 6 時から 22 時だけを出す。夜勤のようにその外の時刻にかかる予定を、どう見せるか。
- 予定の一覧の期間と職員の絞り込みを、API で絞るか画面で絞るか。OpenAPI の予定の一覧は日付の範囲だけを受ける。
- 編集の権限が自分の予定だけの職員に、「予定を作成」と、ほかの職員の列の時間の枠を出すか。
