# schedule-link カレンダーの連携

職員の管理の権限を持つ職員が、職員ごとに Google カレンダーを buddy に結び付け、読めるかを確認し、外す画面。  
結び付けたカレンダーの予定は、[予定の取り込み](../schedule-import_予定の取り込み/index.md) で buddy に取り込む。

| 項目 | 値 |
| --- | --- |
| URL | `/schedule/link` |
| 使う人 | 職員の管理の権限を持つ職員。デフォルトはマネージャー |
| 実装 | `apps/web/src/routes/schedule_.link.tsx`、`apps/web/src/features/calendar/components/CalendarLinkContainer.tsx` |

画面の項目と、web の型、OpenAPI の項目の対応は [API との対応](api.md) にある。

画面を描くコンポーネントのうち、実装の行のほかのものは次のとおり。

- `apps/web/src/features/calendar/components/CalendarLinkView.tsx`
- `apps/web/src/features/calendar/components/CalendarShareGuide.tsx`
- `apps/web/src/features/calendar/components/CalendarLinkTable.tsx`
- `apps/web/src/features/calendar/components/CalendarLinkDialog.tsx`
- `apps/web/src/features/calendar/components/CalendarUnlinkDialog.tsx`
- `apps/web/src/components/page/PageForbiddenMessage.tsx`

## 構成

ヘッダーの左に、メニューのボタンと buddy を置く。  
ヘッダーの右には、アカウントのボタンを置く。  
ヘッダーの下の左端には、画面の間を移るナビゲーションを置く。  
ナビゲーションの見出しと項目、出す職員は、[職員の一覧のナビゲーション](../staff-list_職員の一覧/index.md#ナビゲーション) にある。  
今の画面の連携に印を付ける。  
幅 768px 以上では、ナビゲーションを幅 224px の開いた形で始め、メニューのボタンで幅 80px のレールと切り替える。  
幅 768px 未満では、ナビゲーションをドロワーにし、閉じた状態で始める。  
ナビゲーション、要確認、取り込みの印は、幅 768px 未満ではドロワーを開くと出る。

ヘッダーの下の、ナビゲーションの右に、ページのタイトル、説明の文、カレンダーの共有の枠、職員の一覧を縦に並べる。  
結び付けると外すは、URL を持たないダイアログを一覧の上に重ねて出す。

カレンダーの共有の枠は、見出し「カレンダーの共有」の下に、共有する相手のメールアドレスとコピーのボタンを置き、その下に 1 文の説明と「詳しく」のボタンを置く。  
メールアドレスは、結び付けるたびに使うので常に出す。  
共有の手順は、1 度覚えれば要らないので、「詳しく」で開く欄に入れる。  
手順を長いツールチップに入れると、読まれずに操作を誤るためである。  
共有の手順は、結び付けた職員が 1 人でもいれば閉じた状態で始め、1 人もいなければ開いた状態で始める。

職員の一覧は、詳細の画面を持たないので、行を押せる形にしない。  
行の右端に、結び付けていない職員の行は「結び付ける」のボタンを 1 つだけ置き、結び付けた職員の行は「…」のメニューを置く。  
メニューには、取り込むと外すをこの順に入れる。  
幅 768px 未満では、職員の一覧の行を、1 行目に職員の名前と行の操作、2 行目にカレンダーの ID と最後の取り込みを「・」でつなげた 2 行のリストの行にする。

## メニュー

**概要**: ナビゲーションの形を切り替える。  
幅 768px 未満では、ナビゲーションのドロワーを開く。

**値のソース**: 3 本の横線のアイコン。  
読み上げる名前は「メニュー」。

**活性条件**: 常に活性

**表示条件**: 常に、ヘッダーの左端に出す。

**カタログ**: [SiteLayoutContainer の Mobile](https://buddy-docs.emon-apps.workers.dev/storybook/?path=/story/画面-common-sitelayoutcontainer--mobile)

### インタラクション

#### 1. 幅 768px 以上で押す

1. ナビゲーションを、開いた形からレールに切り替える。
  - もう一度押すと開いた形に戻る。

#### 2. 幅 768px 未満で押す

1. 左端からナビゲーションのドロワーが開く。

## ナビゲーション

**概要**: 予定、照合、職員、利用者の画面の間を移る。

**値のソース**: 見出しと項目、出す職員は、[職員の一覧のナビゲーション](../staff-list_職員の一覧/index.md#ナビゲーション) にある。  
この画面では「連携」に今の画面の印を付ける。

**活性条件**: 常に活性

**表示条件**: 常に、ヘッダーの下の左端に出す。  
幅 768px 以上では、この画面では開いた形で始める。  
幅 768px 未満では、メニューのボタンで開いたドロワーの中に出す。  
モックは、職員の管理の権限を持つ職員の画面を描く。

**カタログ**: [SiteNav の Manager](https://buddy-docs.emon-apps.workers.dev/storybook/?path=/story/画面-common-sitenav--manager)

### インタラクション

#### 1. 「カレンダー」を押す

1. 予定のカレンダーへ移る。

#### 2. 「連携」を押す

1. この画面を開き直す。

#### 3. 「照合」を押す

1. 照合の画面へ移る。

#### 4. 「職員」「部署とチーム」「利用者」を押す

1. 職員の一覧、部署とチーム、利用者の一覧へ移る。

#### 5. 幅 768px 未満で、閉じるボタンか覆いを押すか、Escape キーを押す

1. ナビゲーションのドロワーが閉じ、フォーカスがメニューのボタンに戻る。

## 共有の手順

**概要**: buddy がカレンダーを読み、予定を書き出せるように、職員がカレンダーをサービスアカウントに共有する手順を示す。  
共有の権限は、[基盤と運用の事業所を足す手順](https://github.com/Fukuemon/buddy/blob/develop/context/operations.md#adding-a-facility) にある「予定の変更」である。

**値のソース**: 「カレンダーの共有」の見出し、[共有する相手のメールアドレス](#共有する相手のメールアドレス)、常に出す 1 文、次の 3 つの手順。  
手順は、[共有の手順の詳しく](#共有の手順の詳しく) で開く欄に入れる。  
手順の文言は、Google カレンダーの今の画面の言葉で書く。  
Google が画面の言葉を変えたら直す。

| 手順 | 文言 |
| --- | --- |
| 常に出す 1 文 | 「職員に、自分の Google カレンダーをこのメールアドレスに共有してもらいます。」 |
| 1 | 「職員が、Google カレンダーの「設定と共有」で、自分のカレンダーの「特定のユーザーまたはグループと共有する」に、上のメールアドレスを足します。」 |
| 2 | 「権限は「予定の変更」を選びます。buddy の予定を、このカレンダーに書き出すためです。」 |
| 3 | 「この画面で、職員の行の「結び付ける」を押し、カレンダーの ID を入れます。カレンダーの ID は、「カレンダーの統合」にあります。個人のカレンダーでは、職員の Google のメールアドレスです。」 |

**活性条件**: 常に活性

**表示条件**: この事業所に Google カレンダーのサービスアカウントを設定してあるときに、枠を出す。  
手順は、詳しくで開いている間だけ出す。

**カタログ**: [CalendarLinkView の List](https://buddy-docs.emon-apps.workers.dev/storybook/?path=/story/画面-calendar-calendarlinkview--list)、[CalendarLinkView の NoLinks](https://buddy-docs.emon-apps.workers.dev/storybook/?path=/story/画面-calendar-calendarlinkview--no-links)

**活性条件**: 常に活性

**表示条件**: この事業所に Google カレンダーのサービスアカウントを設定してあるとき。  
常に出す 1 文の下に出す。  
結び付けた職員が 1 人でもいれば手順を閉じた状態で始め、1 人もいなければ開いた状態で始める。

**カタログ**: [CalendarLinkView の List](https://buddy-docs.emon-apps.workers.dev/storybook/?path=/story/画面-calendar-calendarlinkview--list)、[CalendarLinkView の NoLinks](https://buddy-docs.emon-apps.workers.dev/storybook/?path=/story/画面-calendar-calendarlinkview--no-links)

### インタラクション

  - 開いていれば閉じる。
2. 画面の中で開閉した状態は、職員の一覧を読み直しても変えない。

## 共有する相手のメールアドレス

**概要**: 職員がカレンダーを共有する相手の、この事業所のサービスアカウントのメールアドレスを示す。

**表示条件**: この事業所に Google カレンダーのサービスアカウントを設定してあるとき

## 職員の一覧

**概要**: 事業所の職員ごとに、結び付けた Google カレンダーと最後の取り込みを示す。  
行の右端から、結び付け、取り込みへ移り、外す。

**値のソース**: 「職員」「Google カレンダー」「最後の取り込み」のカラムと、行の操作の列。  
行は職員の名前の順に並べる。  
退職した職員の行は出さない。  
退職でカレンダーが外れ、退職した職員には結び付けられないためである。  
休職の職員の行は出し、結び付けたままにできる。  
行を押しても何も起きない。  
詳細の画面を持たないので、「›」は置かない。

幅 768px 未満では、1 行目に職員の名前と行の操作を、2 行目にカレンダーの ID と最後の取り込みを「・」でつなげて出す。  
値の無いセルは 2 行目に出さない。

**活性条件**: 常に活性

**表示条件**: 職員とカレンダーを読み終えたとき

**カタログ**: [CalendarLinkView の List](https://buddy-docs.emon-apps.workers.dev/storybook/?path=/story/画面-calendar-calendarlinkview--list)

## 読めるか確認する

**活性条件**: カレンダーの ID が空でなく、確認しているか結び付けを送っている間でないとき

**表示条件**: 結び付けるダイアログを開いているとき

**カタログ**: [CalendarLinkDialog の Default](https://buddy-docs.emon-apps.workers.dev/storybook/?path=/story/画面-calendar-calendarlinkdialog--default)、[CalendarLinkDialog の Checking](https://buddy-docs.emon-apps.workers.dev/storybook/?path=/story/画面-calendar-calendarlinkdialog--checking)

  - 確認の仕方は、[Google カレンダーとの連携の Design Doc のカレンダーの結び付け](https://github.com/Fukuemon/buddy/blob/develop/services/schedule/internal/features/calendar/DesignDoc.md#カレンダーの結び付け) にある。

## 確認の結果

**概要**: 読めるかを確認した結果と、結び付けられなかった理由を示す。  
読めないときは、読み上げでは警告として扱う。

**値のソース**: 次の文。

| 結果 | 文 |
| --- | --- |
| 読めた | 「読めました。結び付けると、予定の取り込みでこのカレンダーを選べます。」 |
| 共有されていないか、カレンダーが無い | 「このカレンダーを読めません。カレンダーが、上に出ている buddy のメールアドレスに共有されているかと、カレンダーの ID が合っているかを確認してください。」 |
| ほかの職員に結び付いている | 「このカレンダーは、ほかの職員に結び付いています。」 |
| この職員にほかのカレンダーが結び付いている | 「この職員には、ほかのカレンダーが結び付いています。一覧を読み直してください。」 |
| このカレンダーがこの職員にすでに結び付いている | 「このカレンダーは、この職員にすでに結び付いています。一覧を読み直してください。」 |
| Google に届かない | 「Google カレンダーに届きませんでした。時間をおいて、もう一度確認してください。」 |
| そのほかの失敗 | 「確認できませんでした。時間をおいて、もう一度確認してください。」 |

**活性条件**: 常に活性

**表示条件**: 読めるかを確認した後か、ダイアログの結び付けるが失敗した後。

**カタログ**: [CalendarLinkDialog の Readable](https://buddy-docs.emon-apps.workers.dev/storybook/?path=/story/画面-calendar-calendarlinkdialog--readable)、[CalendarLinkDialog の Unreadable](https://buddy-docs.emon-apps.workers.dev/storybook/?path=/story/画面-calendar-calendarlinkdialog--unreadable)

## 全体動作

### 初期処理

- ログインした職員が職員の管理の権限を持たなければ、「権限が無い」の状態にする。
- 権限があれば、職員、結び付けたカレンダー、共有する相手のメールアドレスを読み終えるまで、「読み込み中」の状態にする。
  - この事業所で Google カレンダーを使う準備ができていなければ、「準備ができていない」の状態にする。
  - 職員、カレンダーの一覧、共有する相手のメールアドレスのどれかを読めなかったときは、「読み込みの失敗」の状態にする。
- URL の search params は読まない。

### 権限の確認

職員の管理の権限を持たない職員には、「権限が無い」の状態を出し、職員とカレンダーを出さない。  
画面を開いた後に権限を外された職員が操作したときは、ダイアログの中か読み込みの失敗の文の位置に、「この操作をする権限がありません。」を出す。

## 未決

### 決まっていないこと

- 職員が Google のアカウントを事業所の外で持っていて、カレンダーを共有できないときに、どう案内するか。
  - 今の動き: 案内を出さない。
    - 職員のアカウントが Workspace か個人かは、PRD の [Open Questions](https://github.com/Fukuemon/buddy/blob/develop/docs/PRD.md#open-questions) にある。
  - 決める人: 開発者が、事業所の責任者に確認して決める
  - 期限: 事業所で予定の取り込みを使い始めるまで
- この画面に、Google カレンダーへの書き出しの状態を出すか。
  - 今の動き: 出さない。
    - Google カレンダーで直された予定と、書き出せなかった予定は、[確認が必要な予定](../schedule-review_確認が必要な予定/index.md) で確認する。
  - 決める人: 開発者
  - 期限: 本番で Google カレンダーへの書き出しを有効にするまで
