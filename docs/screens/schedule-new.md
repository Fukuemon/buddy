# 予定の作成

職員が、通常の予定か訪問の予定を 1 件作る画面。  
予定のカレンダーの上にモーダルで重ねて出し、作ると作った予定の日のカレンダーに戻る。

| 項目 | 値 |
| --- | --- |
| 画面の ID | `schedule-new` |
| URL | `/schedule/new`。`/schedule` の子で、カレンダーの search params を引き継ぐ |
| 使う人 | 全ての職員。予定を作れる職員の範囲は、編集の権限で決まる |
| 実装 | `apps/web/src/routes/schedule.new.tsx`、`ScheduleCreateModalContainer`、`ScheduleFormModal`、`ScheduleForm` |

## UI

モーダルは、上端に閉じるボタンと種類のタブと題、左に項目の要約の一覧、右に選んだ項目の入力、下端に送信のボタンを置く。  
幅 768px 未満では、モーダルを画面いっぱいに出し、要約の一覧の下に入力を置く。

<iframe class="wireframe-viewer" src="wireframes/viewer.html?screen=schedule-new" title="予定の作成のワイヤーフレーム" width="100%" height="720" loading="lazy"></iframe>

GitHub の画面では iframe を表示しないため、ワイヤーフレームは文書のサイトで見る。  
ワイヤーフレームの HTML は [wireframes/schedule-new.html](wireframes/schedule-new.html) にある。  
通常と訪問の切り替えと、右に出す入力の切り替えは、ワイヤーフレームの中の種類のタブと要約の一覧で行う。

## 状態ごとの UI

| 状態 | 条件 | 見えるもの |
| --- | --- | --- |
| 初期表示 | 開いた直後 | search params を初期値にしたフォーム。右の入力は「訪問日時」か「予定日時」 |
| 職員と利用者の読み込み中 | 職員か利用者の取得が終わっていない | フォームは出す。担当者か利用者の入力を開くと、一覧は空で「該当する名前がありません。」を出す |
| 職員と利用者の取得の失敗 | 職員か利用者の取得が失敗した | 読み込み中と同じ。失敗の文は出さない |
| 入力の誤り | 作成を押し、検証に通らない | 誤りのある項目の要約の枠を赤くし、文を出す。右の入力にも同じ文を出す。送信しない |
| 送信中 | 検証に通り、API の応答を待っている | 作成のボタンに回転するインジケーターを出し、押しても無視する |
| 成功 | API が予定を返した | モーダルを閉じ、作った予定の日のカレンダーに戻る。成功の文は出さない |
| 送信の失敗 | API が失敗を返した、または届かない | 下端に「予定を作成できませんでした。」（`role="alert"`）。入力は残す |
| 未認証（401） | API が 401 を返す | 未実装。送信の失敗と同じ文になる |
| 権限なし（403） | 編集の権限の外の職員の予定を作ろうとした | 未実装。送信の失敗と同じ文になる |
| 入力の誤り（400） | API が `invalid_input` を返す | 未実装。送信の失敗と同じ文になり、項目には出さない |

入力の誤りの文は、次のとおり。

| 項目 | 条件 | 文 |
| --- | --- | --- |
| タイトル（通常） | 空白だけか空 | タイトルを入力してください |
| 日付 | 日付として読めない | 日付を入力してください |
| 開始時間 | `HH:mm` でない | 開始時間を入力してください |
| 終了時間（通常） | `HH:mm` でない | 終了時間を入力してください |
| 終了時間（通常） | 開始時間より後でない | 終了時間は開始時間より後にしてください |
| 利用者（訪問） | 選んでいない | 利用者を選んでください |
| 担当者、予定者 | 選んでいない | 担当者を選んでください |
| 提供時間（訪問） | 数でない | 提供時間を入力してください |
| 提供時間（訪問） | サービスコードの範囲の外 | {サービスコード} の提供時間は {下限} 分から {上限} 分です |

- 日付と時間の誤りは、要約の一覧の「訪問日時」か「予定日時」の 1 つの枠にまとめて、最初の 1 つの文を出す。
- 作成を押したときに入力を検証する。押した後は、入力を変えるたびに検証し直す。

## 構成要素

API の列は、`createSchedule`（`POST /v1/facilities/{facility_id}/schedules`）の `SlotRequest` の項目で書く。

| 番号 | 構成要素 | 表示する値 | web の型の項目 | OpenAPI の項目 | `data-testid` |
| --- | --- | --- | --- | --- | --- |
| 1 | `Modal` | 題「予定の作成」 | なし | なし | `schedule-form-modal` |
| 1-1 | 閉じるボタン | ×（`aria-label="閉じる"`） | なし | なし | `modal-close` |
| 1-2 | 種類の `SegmentedControl` | 「通常」「訪問」 | `ScheduleInput.kind` | `schedule_type_id` | `schedule-kind-tab`、タブは `schedule-kind-tab-normal`、`schedule-kind-tab-visit` |
| 1-3 | 送信の失敗の文 | 「予定を作成できませんでした。」 | なし | なし | なし |
| 1-4 | 作成のボタン | 「作成」 | なし | なし | `schedule-create-submit` |
| 2 | モーダルの背景 | 暗くぼかした背景 | なし | なし | `modal-overlay` |
| 3 | `ScheduleFieldSummaryList` の項目 | 項目の名前、今の値の要約、誤りの文 | なし | なし | `schedule-field-{title、dateTime、patient、staff、category、description}` |
| 4 | 右の入力 | 要約の一覧で選んだ項目の入力 | なし | なし | なし |
| 4-1 | タイトルの `TextareaField` | 入力したタイトル | `title` | `title` | `schedule-form-title` |
| 4-2 | 日付の `DatePicker` | 「日付」か「訪問日」 | `startsAt` の日付 | `date` | `schedule-form-date` |
| 4-3 | 開始時間の `TimePicker` | 開始時間 | `startsAt` の時刻 | `start_time` | `schedule-form-start-time` |
| 4-4 | 終了時間の `TimePicker`（通常） | 終了時間 | `endsAt` の時刻 | `end_time` | `schedule-form-end-time` |
| 4-5 | 終了時間の文（訪問） | 「終了時間 {開始時間 + 提供時間}」 | `endsAt` の時刻 | `end_time` | `schedule-form-end-time` |
| 4-6 | 提供時間の `NumberPicker`（訪問） | 提供時間（分） | なし（`endsAt` に換算する） | なし | `schedule-form-service-time` |
| 4-7 | `ServiceCodeRadioGroup`（訪問） | 11 のサービスコード | `visit.serviceCode` | `visit_info.service_code_id` | `service-code-{コード}` |
| 4-8 | `PatientSelectList`（訪問） | 名前で絞れる利用者の一覧 | `visit.patientId` | `visit_info.patient_id` | `patient-select-search`、`patient-select-option-{利用者の id}` |
| 4-9 | `StaffSelectList` | 名前で絞れる職員の一覧 | `staffId` | `staff_id`、`visit_info.assigned_staff_id` | `staff-select-search`、`staff-select-option-{職員の id}` |
| 4-10 | `ScheduleCategoryCheckboxGroup`（訪問） | 夜勤、緊急、入院 | `visit.categories` | `visit_info.visit_category_ids` | `schedule-category-{night、emergency、hospitalization}` |
| 4-11 | メモの `TextareaField` | 入力したメモ | `description` | `description` | `schedule-form-description` |
| 4-12 | 「該当する名前がありません。」 | 利用者と職員の選択肢が 0 件のときの文 | なし | なし | なし |

- 訪問の予定のタイトルは、画面で入力せず「訪問」を送る。
- 要約の一覧の値は、未選択の項目を「未選択」、メモが空なら「なし」、訪問の種類が空なら「通常」と出す。
- 職員と利用者の一覧は、`listUsers` と `listPatients` から取る。サービスコードの一覧と提供時間の範囲は、画面が持つ定数で、API の `listServiceCodes` を使っていない。

## インタラクション

| 番号 | 操作 | 前提 | 結果 |
| --- | --- | --- | --- |
| 1-2 | 種類のタブを押す | なし | フォームを選んだ種類の初期値に戻す。日付、開始時間、担当者は残し、タイトル、利用者、提供時間、訪問の種類、メモは初期値に戻る。URL の `kind` を置き換える（履歴に積まない） |
| 3 | 要約の一覧の項目を押す | なし | 右の入力をその項目に替える。URL は変わらない |
| 4-7 | サービスコードを選ぶ | 種類が訪問 | 提供時間を、そのコードの上限にして、検証し直す |
| 4-3、4-6 | 開始時間か提供時間を変える | 種類が訪問 | 終了時間の文を、開始時間に提供時間を足した時刻にする |
| 4-8、4-9 | 利用者か職員の検索の欄に入力する | なし | 名前に入力の語を含む選択肢だけを出す。API は呼ばない |
| 1-4 | 作成を押す | 検証に通らない | 入力の誤りを出す。API は呼ばない |
| 1-4 | 作成を押す | 検証に通る | `createSchedule` を呼ぶ。成功したら予定の一覧の取得の結果を捨てて取り直し、`/schedule` に `view`、`staff` を引き継ぎ、`date` を作った予定の日にして戻る（履歴に積む） |
| 1-4 | 作成を押す | 送信が失敗する | 送信の失敗の文を出し、モーダルを開いたままにする |
| 1-1、2 | 閉じるボタン、背景、Escape キー | 入力を変えていない | `/schedule` に `view`、`date`、`staff` を引き継いで戻る |
| 1-1、2 | 閉じるボタン、背景、Escape キー | 入力を変えた | 「変更が破棄されますがよろしいですか？」の確認を出す。OK なら戻り、キャンセルならモーダルに留まる |

## 初期状態でのインタラクション

- 開いた直後から、全ての操作ができる。職員と利用者の取得を待たずにフォームを出すため、取得が終わるまでは担当者と利用者を選べない。
- 開いた直後のフォーカスは `body` にあり、モーダルの中へ移さない。モーダルの外へのフォーカスの移動も止めない。
- 背後のカレンダーは、`/schedule` の画面として描いたまま残る。
- search params は次のとおり復元する。読めない値は既定の値に置き換える。

| search param | 意味 | 省いたときと読めないとき |
| --- | --- | --- |
| `kind` | 種類のタブ。`normal`、`visit` | `visit`。既定の値は URL から消す |
| `start` | 日付の初期値。`YYYY-MM-DD` | カレンダーの `date`。それも無ければ今日 |
| `time` | 開始時間の初期値。`HH:mm` | 9:00 |
| `staffId` | 担当者の初期値 | 未選択 |
| `view`、`date`、`staff` | カレンダーの search params。閉じたときに戻す | カレンダーの既定の値 |

- 開始時間以外の初期値は、通常の予定なら終了時間が開始時間の 1 時間後、訪問の予定ならサービスコードが訪看I2、提供時間がその上限の 29 分。

## 未決

PRD と実装の食い違い

- PRD は、訪問の予定に同行者を持たせる。実装のフォームは同行者を持たない。OpenAPI は `visit_info.companion_id` を持つ。
- PRD は、毎週と毎月の繰り返しの予定を作れるとしている。実装は単発の予定だけを作る。OpenAPI は `createRecurringSchedule` を持つ。
- サービスコードの表記と提供時間の範囲を、画面が定数で持つ。PRD と Design Doc は「訪看I２」のように全角の数字で書き、実装は半角の数字で書く。範囲を `listServiceCodes` から取るかが決まっていない。

決まっていないこと

- 担当者の一覧に、編集の権限の外の職員を出すか。出さないなら、画面が権限をどこから読むか（`StaffDetail.policies` か、別の API か）。
- 予定を作成のボタンから開いたときに、担当者の初期値をログインした職員にするか。今は未選択。
- 種類を切り替えたときに、入力したタイトル、利用者、メモを確認なしで捨ててよいか。
- 職員と利用者の取得の読み込み中と失敗を、フォームの中でどう見せるか。
- 401、403、400 の応答を、送信の失敗と分けて見せるか。400 の誤りを項目に結び付けるか。
- 作成に成功したときに、成功の文を出すか。
- 開いたときのフォーカスの位置と、モーダルの中にフォーカスを閉じ込めるか。
- 担当者を `staff_id` と `visit_info.assigned_staff_id` のどちらに送るか。OpenAPI は両方を必須にしている。
