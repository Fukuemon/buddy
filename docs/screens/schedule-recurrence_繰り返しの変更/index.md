# schedule-recurrence 繰り返しの変更

職員が、繰り返しの予定の 1 回を開き、その回の日以降の回の繰り返しの規則（毎週か毎月か、毎週の間隔と曜日か毎月の日、終了日）を変える画面。  
予定の詳細の「編集」のメニューの「繰り返しを変更」から開き、予定のカレンダーの上にモーダルで重ねて出す。  
保存すると予定のカレンダーに戻る。

| 項目 | 値 |
| --- | --- |
| URL | `/schedule/$scheduleId/recurrence`。`/schedule` の子で、カレンダーの search params を引き継ぐ |
| 使う人 | 予定の職員の予定を編集できる職員 |
| 実装 | `apps/web/src/routes/schedule.$scheduleId.recurrence.tsx`、`apps/web/src/features/schedule/components/ScheduleRecurrenceModalContainer.tsx` |

画面の項目と、web の型、OpenAPI の項目の対応は [API との対応](api.md) にある。

画面を描くコンポーネントのうち、実装の行のほかのものは次のとおり。

- `apps/web/src/features/schedule/components/RecurringRuleFields.tsx`
- `packages/ui/src/base/Modal/Modal.tsx`
- `packages/ui/src/base/DatePicker/DatePicker.tsx`

## 構成

モーダルの上端には、左にタイトルを置く。  
欄を出す状態では、右上に閉じるボタン（×）を置かず、下端のキャンセルで閉じる。  
本文には、変える範囲の説明、変えない項目、規則の欄をこの順に置く。  
規則の欄は、見出しを左、欄を右に置く 2 列にし、幅 768px 未満では見出しを欄の上に置く。  
下端の右には、キャンセルと保存のボタンをこの順に置く。  
読み込み中、読み込みの失敗、権限が無いとき、繰り返しを変えられない予定、予定の正本を切り替えている間は、下端を出さず、右上に閉じるボタンを置く。  
幅 768px 未満では、モーダルを画面いっぱいに出し、下端を画面の下に固定する。  
時刻、利用者、職員、訪問の内容、メモは、この画面では変えられない。

モックは、今日を 11月8日（日）とし、毎週月曜の訪問の予定の 11月9日（月）の回を開いたところを描く。

## 覆い

**概要**: モーダルの後ろの予定のカレンダーを、暗くぼかして覆う覆い。

**値のソース**: 文言は無い。  
後ろには予定のカレンダーを、`/schedule` の画面として描いたまま残す。

**カタログ**: [ScheduleRecurrenceModalContainer の Weekly](https://buddy-docs.emon-apps.workers.dev/storybook/?path=/story/画面-schedule-schedulerecurrencemodalcontainer--weekly)

**操作**: 押すと、欄を出す状態では [キャンセル](#キャンセル) を、下端を出さない状態では [閉じる](#閉じる) を押したときと同じ結果になる。

1. 押し始めがモーダルの中で、覆いで離したときは閉じない。

## 閉じる

**概要**: 下端を出さない状態で、モーダルを閉じるボタン。  
「読み込み中」「読み込みの失敗」「繰り返しを変えられない予定」「予定の正本を切り替えている」「権限が無い」の状態で、モーダルの右上に出す。

## 繰り返し

**概要**: 新しい繰り返しを、今の規則と開いた回の日から作る選択肢か、「カスタム…」から選ぶセレクト。

**値のソース**: 見出し「繰り返し」と、次の選択肢。  
選択肢の曜日、日、週は、開いた回の日から決める。  
今日より前の回から開いたときも、開いた回の日から決める。

| 選択肢 | 11月9日（月）の回を開いたとき |
| --- | --- |
| 今の規則の、曜日の並び。今の規則が複数の曜日の毎週のときだけ出す | 隔週の月曜と木曜なら「隔週 月曜日、木曜日」。7 つの曜日で間隔が 1 なら「毎日」 |
| 毎週の、開いた回の曜日 | 「毎週 月曜日」。今の規則が隔週なら「隔週 月曜日」、3 週ごとなら「3 週ごと 月曜日」 |
| 毎月の、開いた回の日 | 「毎月 9 日」 |
| 毎月の、開いた回の第何週の曜日 | 「毎月 第 2 月曜日」 |
| ほかの繰り返し | 「カスタム…」 |

- 開いたときは、今の繰り返しに当たる選択肢を選ぶ。どれにも当たらなければ「カスタム…」を選び、「カスタム（毎週）」か「カスタム（毎月）」の状態で始める。
- 第何週かは、月の 1 日から 7 日ずつ区切って数える。
- 毎週の選択肢は、[間隔](#間隔) の値で送る。間隔が 1 なら「毎週」、2 なら「隔週」、3 以上なら「3 週ごと」の形で出す。
  - 間隔の初期値は今の規則の間隔で、今の規則が毎月なら 1 である。曜日の選択肢を選んでも、間隔は 1 に戻さない（ADR-0038）。
  - 今の規則の選択肢と間隔の文言は、[RecurringRuleFields の BiweeklyDays](https://buddy-docs.emon-apps.workers.dev/storybook/?path=/story/画面-schedule-recurringrulefields--biweekly-days) にある。
  - 7 つの曜日の今の規則の「毎日」は、[RecurringRuleFields の Daily](https://buddy-docs.emon-apps.workers.dev/storybook/?path=/story/画面-schedule-recurringrulefields--daily) にある。
  - 3 週ごとの文言は、[RecurringRuleFields の EveryThreeWeeks](https://buddy-docs.emon-apps.workers.dev/storybook/?path=/story/画面-schedule-recurringrulefields--every-three-weeks) にある。

**カタログ**: [RecurringRuleFields の Weekly](https://buddy-docs.emon-apps.workers.dev/storybook/?path=/story/画面-schedule-recurringrulefields--weekly)、[RecurringRuleFields の Custom](https://buddy-docs.emon-apps.workers.dev/storybook/?path=/story/画面-schedule-recurringrulefields--custom)

**操作**:

- 「カスタム…」のほかの選択肢を選ぶと、その繰り返しにし、頻度と、曜日か日の欄を閉じる。
  - 毎週の選択肢を選んだとき、間隔が 1〜52 の整数でなければ、開いたときの間隔に戻す。間隔の欄が閉じ、見えない誤りで保存できなくなるのを防ぐためである。
  - 毎月の選択肢を選んでも、毎週の曜日は残す。
- 「カスタム…」を選ぶと、同じモーダルの中に [頻度](#頻度) と、[間隔](#間隔) と [曜日](#曜日) か日の欄を開き、「カスタム（毎週）」か「カスタム（毎月）」の状態にする。
  - 欄の初期値は、その前に選んでいた繰り返しのままにする。
- 「カスタム…」で選んだ繰り返しがほかの選択肢のどれかと同じになっても、「カスタム…」を選んだまま欄を開いておく。

**概要**: 「カスタム…」で、毎週か毎月かを選ぶセレクト。

**値のソース**: 見出し「頻度」と、「毎週」「毎月」。  
「毎週」は、[間隔](#間隔) の値が 2 なら「隔週」、3 以上なら「3 週ごと」の形で出す。間隔の欄を空にしている間は「毎週」と出す。

1. 替えても、ほかの頻度の欄の値は残す。

## 間隔

**概要**: 毎週の繰り返しを、何週ごとに繰り返すかを入れる数のテキストボックス。

## 入力の誤りの文

**概要**: 入力が検証に通らないことを、欄の下に出すメッセージ。

**値のソース**: 欄ごとに、次の文を出す。  
誤りのある欄は、枠を危険の色で太くし、読み上げでは文を欄の説明として読ませる。  
文の日付は、変える範囲の説明の日付（今日以降の回では開いた回の日、今日より前の回では今日）から決める。

| 欄 | 条件 | 文 |
| --- | --- | --- |
| 繰り返し | 繰り返しも終了日も、今のまま変えていない | 「今の繰り返しから変えてください」 |
| 間隔 | 頻度が毎週で、1〜52 の整数でないか、空 | 「間隔は 1〜52 の週の数で入力してください」 |
| 曜日 | 頻度が毎週で、曜日を 1 つも選んでいない | 「曜日を 1 つ以上選んでください」 |
| 終了日 | 「あり」を選び、日付として読めない | 「終了日を入力してください」 |
| 終了日 | 繰り返しを今のままにし、変える範囲の説明の日付の前の日より前 | 「終了日は 2026-11-08 以降にしてください」の形。日付は変える範囲の説明の日付の前の日 |
| 終了日 | 繰り返しを変え、変える範囲の説明の日付より前 | 「繰り返しを変えるときは、終了日を 2026-11-09 以降にしてください」の形。日付は変える範囲の説明の日付 |

- 繰り返しを今のままにして終了日を変える範囲の説明の日付の前の日にすると、その日から後の回が無くなる。
  - ある日から後の訪問をやめるときに使う。
- 新しい繰り返しの最初の回が終了日より後になる組み合わせは、画面で確認せず、保存の失敗の文が出る。

**カタログ**: [RecurringRuleFields の Invalid](https://buddy-docs.emon-apps.workers.dev/storybook/?path=/story/画面-schedule-recurringrulefields--invalid)、[ScheduleRecurrenceModalContainer の Unchanged](https://buddy-docs.emon-apps.workers.dev/storybook/?path=/story/画面-schedule-schedulerecurrencemodalcontainer--unchanged)

## 保存の失敗の文

**概要**: 繰り返しを変えられなかったことと、職員が次にすることを伝えるメッセージ。  
規則の欄の下に出す。

**値のソース**: 失敗ごとに、次の文を出す。  
読み上げでは警告として扱う。  
文と、その要因の対応は [API との対応の状態と失敗の要因](api.md#状態と失敗の要因) にある。

| 失敗 | 文 |
| --- | --- |
| 画面を開いた後に、予定を編集する権限を外された | 「この操作をする権限がありません。」 |
| 入力が保存の規則に合わない | 「入力の内容では予定を更新できません。内容を直してください。」 |
| 事業所が、Google カレンダーを予定の正本にしている | 「この事業所の予定は Google カレンダーで管理しています。予定は Google カレンダーで作成、変更してください。」 |
| Google カレンダーで予定が変更されていた | 「Google カレンダーで予定が変更されていました。最新の予定を確認してから、もう一度保存してください。」 |
| Google カレンダーで予定が消されたか、見つからない | 「Google カレンダーで予定が消されたか、見つかりません。」 |
| 前の保存の結果を確認している | 「前の保存の結果を確認しています。時間をおいて、予定を開き直してください。」 |
| Google カレンダーに書けなかった | 「Google カレンダーに書けませんでした。時間をおいて、やり直してください。」 |
| Google カレンダーに書けたかを確認できなかった | 「Google カレンダーに書けたかを確認できませんでした。時間をおいて、予定を開き直してください。」 |
| Google カレンダーに予定を書く権限が無い | 「Google カレンダーに予定を書く権限がありません。カレンダーの共有の設定を、事業所の管理者に確認してください。」 |
| Google カレンダーが予定を受け付けなかった | 「Google カレンダーが予定を受け付けませんでした。入力を確認してください。」 |
| 予定の職員が Google カレンダーを結び付けていない | 「予定の職員が Google カレンダーを結び付けていません。カレンダーの結び付けを、事業所の管理者に頼んでください。」 |
| 事業所に Google カレンダーと連携する設定が無い | 「この事業所には、Google カレンダーと連携する設定がありません。事業所の管理者に確認してください。」 |
| 画面を開いた後に、マネージャーが予定の正本の切り替えを始めた | 「予定の正本を buddy に切り替えています。切り替えが終わるまで、予定を作成、変更、キャンセルできません。」 |
| ほかの失敗と、つながらない | 「予定を更新できませんでした。」 |

**カタログ**: [ScheduleRecurrenceModalContainer の Weekly](https://buddy-docs.emon-apps.workers.dev/storybook/?path=/story/画面-schedule-schedulerecurrencemodalcontainer--weekly)

## 読み込みの失敗の文

**概要**: 予定を出せない理由を伝えるメッセージ。

**値のソース**: 理由ごとに、次の文を出す。  
読み上げでは警告として扱う。  
文と、その要因の対応は [API との対応の状態と失敗の要因](api.md#状態と失敗の要因) にある。

- 予定が見つからないとき: 「予定が見つかりません。」
- 見る権限が無い予定と、ほかの事業所の予定を開いたとき: 「この予定を見る権限がありません。」
- ほかの理由で読めなかったとき: 「予定を取得できませんでした。」

## キャンセル

**概要**: 繰り返しを変えずにモーダルを閉じるボタン。  
欄を出す状態では、モーダルの右上に × を置かず、このボタンで閉じる。

**値のソース**: 「キャンセル」  
閉じるときに出す確認の文は次のとおり。

| 条件 | 文 |
| --- | --- |
| 入力を変えた | 「変更が破棄されますがよろしいですか？」 |

- 「カスタム…」を選んだだけでは、入力を変えたことにしない。

**カタログ**: [ScheduleRecurrenceModalContainer の Weekly](https://buddy-docs.emon-apps.workers.dev/storybook/?path=/story/画面-schedule-schedulerecurrencemodalcontainer--weekly)

**操作**: 押すか Escape キーを押すと、閉じて予定の詳細に戻る。

1. 入力を変えていなければ、予定の詳細（`/schedule/{予定の id}`）に戻る。
   - カレンダーの search params の `view`、`date`、`staff`、`cancelled` を引き継ぐ。
2. 入力を変えていれば、変更を破棄するかの確認を出す。OK なら予定の詳細に戻り、キャンセルならモーダルに留まる。
3. [覆い](#覆い) を押したときも同じにする。

## 保存

**概要**: 入力を検証し、繰り返しを変えるボタン。  
入力を変えていなくても押せる。

**値のソース**: 「保存」。  
送っている間は、文字の代わりに回転するインジケーターを出す。

**活性**: 次の全てに当てはまるとき。

- 職員が、保存を送っている途中でない

**カタログ**: [ScheduleRecurrenceModalContainer の Weekly](https://buddy-docs.emon-apps.workers.dev/storybook/?path=/story/画面-schedule-schedulerecurrencemodalcontainer--weekly)、[ScheduleRecurrenceModalContainer の Unchanged](https://buddy-docs.emon-apps.workers.dev/storybook/?path=/story/画面-schedule-schedulerecurrencemodalcontainer--unchanged)

**操作**: 押すと、入力を検証し、変える範囲の説明の日付以降の回に新しい繰り返しを当てる。

1. 検証に通らなければ、「入力の誤り」の状態を出す。
   - 保存はしない。
   - この後は、入力を変えるたびに検証し直す。
2. 検証に通れば、変える範囲の説明の日付以降の回に、新しい繰り返しを当てる。
   - その日より前の回は変わらない。
   - 1 回だけ変えた回とキャンセルした回は、日時と内容を変えずに残す。1 回だけ変えた回の元の日には、新しい繰り返しの回を出さない。職員が移した訪問と、同じ週に 2 件の訪問を出さないためである。
   - Google カレンダーで消した回は、新しい繰り返しに引き継がない。消した日に新しい繰り返しの回が当たれば、その日に回を出す。
   - 時刻、職員、訪問の内容、メモは、今の繰り返しのままにする。
   - 予定を Google カレンダーで管理する事業所では、Google カレンダーの繰り返しの予定も書き換える。
3. 成功したら、予定の詳細ではなく、予定のカレンダー（`/schedule`）に戻る。
   - 繰り返しを変えると、開いた回は別の予定に替わり、開いた回の日に回が無くなることがあるためである。
   - `view`、`staff`、`cancelled` を引き継ぎ、`date` を新しい繰り返しの最初の回の日にする。最初の回の日が変える範囲の説明の日付より前なら、変える範囲の説明の日付にする。履歴に積む。
   - 成功の文は出さない。
4. 失敗したら、「保存の失敗」の状態にし、モーダルを開いたままにする。
5. 編集を開いた後に Google カレンダーで予定が変更されていて失敗したら、予定を読み直し、次の保存では読み直した予定に当てる。
   - 入力は消さない。
   - 読み直した予定は画面に出さない。

決め方は [ADR-0037](../../adr/0037-recurring-rule-change.md) にある。

## 全体動作

### 使う場面

訪問の曜日や日が変わったとき、または訪問をある日でやめるときに、繰り返しの予定の 1 回を予定のカレンダーで押し、予定の詳細の「編集」のメニューから開く。  
その回だけを変えるときは、同じメニューの「この予定を編集」から [予定の編集](../schedule-edit_予定の編集/index.md) を開く。

### 初期処理

予定と、職員、利用者の一覧と、事業所を同時に読む。  
予定を Google カレンダーで管理する事業所でも、同じく予定を読む。  
予定を Google カレンダーで管理する事業所では、予定の正本を切り替えているかを知るために、予定の詳細と同じく、カレンダーの期間の予定の一覧も読む。  
全てを読み終えるまでは「読み込み中」の状態を出し、どれかを読めなかったら「読み込みの失敗」の状態を出す。  
読む順と失敗の扱いは、[予定の管理の Design Doc の予定の画面の読み込みと保存](https://github.com/Fukuemon/buddy/blob/develop/services/schedule/DesignDoc.md#予定の画面の読み込みと保存) にある。

読み終えたら、次の順に決める。

1. 予定の職員の予定を編集できなければ、「権限が無い」の状態を出す。
2. 読んだ予定がキャンセルした予定なら、「繰り返しを変えられない予定」の状態を出す。
3. 読んだ予定が繰り返しの予定のまだ変えていない回でなければ、「繰り返しを変えられない予定」の状態を出す。
4. 事業所が予定の正本を buddy に切り替えている途中なら、「予定の正本を切り替えている」の状態を出す。
5. ほかは、欄を出す。

開いた後に切り替えが始まっても、状態は変えない。保存を押すと「保存の失敗」の状態にし、[保存の失敗の文](#保存の失敗の文) の切り替えの文を出す。

欄の初期値は、今の繰り返しから作り、今の繰り返しが持たない曜日と日は開いた回の日から決める。  
繰り返しの選択は、今の繰り返しに当たる選択肢にし、当たらなければ「カスタム…」にする。

開いた直後のフォーカスは、ダイアログのタイトルに置く。  
Tab キーのフォーカスは、モーダルの中だけを回る。  
閉じると、開く前にフォーカスがあった要素に戻す。

URL の search params は、閉じたときと保存した後に引き継ぐだけで、表示には使わない。

### 入力の確認と送信

- 保存を押したときに入力を検証する。
  - 押した後は、入力を変えるたびに検証し直す。
- 保存を拒まれたときと、つながらないときは、「保存の失敗」の状態にし、[保存の失敗の文](#保存の失敗の文) を出す。
- 予定を Google カレンダーで管理する事業所では、保存を押すと、buddy が Google カレンダーの繰り返しの予定を書き換える。
  - Google カレンダーに書けたときだけ成功になる。
  - 開いたときの予定と比べ、Google カレンダーで予定が変わっていれば、保存せずに「保存の失敗」の状態にする。

### 変えた後の表示

保存に成功すると、予定のカレンダーの予定を読み直した結果を出す。  
カレンダーの `date` は、新しい繰り返しの最初の回の日にする。  
変える範囲の説明の日付より前の回は、元の繰り返しのまま残る。

### 権限の確認

画面は、ログインした職員の予定の権限から、予定の職員の予定を編集できるかを決める。  
規則は [画面仕様書の規約の権限の出し分け](../rules.md#権限の出し分け) にある。

- 予定の職員の予定を編集できないときは、欄を出さず、「権限が無い」の状態を出す。
  - 予定の詳細は「編集」のメニューを出さないので、URL を直に開いたときにだけ起きる。
- 予定を Google カレンダーで管理する事業所でも、同じ権限で変えられる。
- 見る権限の無い予定を開くと、「読み込みの失敗」の状態にし、「この予定を見る権限がありません。」を出す。
- 画面を開いた後に予定を編集する権限を外された職員が保存を押すと、「保存の失敗」の状態にし、「この操作をする権限がありません。」を出す。
