# receipt-upload 照合

照合の担当が、予定の取り方を選び、電子カルテから書き出した実績の CSV を上げて、照合を始める画面。照合が終わると、照合の結果の画面へ移る。

| 項目 | 値 |
| --- | --- |
| URL | `/receipt` |
| 使う人 | 全ての職員 |
| 実装 | `apps/web/src/routes/receipt.index.tsx`、`apps/web/src/features/receipt/components/ReceiptCheckFormContainer.tsx`、`apps/web/src/features/receipt/components/ReceiptCheckForm.tsx`、`apps/web/src/features/receipt/components/CsvFileField.tsx` |

画面の項目と、web の型、OpenAPI の項目の対応は [API との対応](api.md) にある。

## 構成

ヘッダーの左のメニューのボタンで、左のサイドバーを開閉する。サイドバーには、画面の間を移るナビゲーションを置く。幅 768px 以上では、サイドバーを開いた状態で出し、閉じると画面の中身を広げる。モックは閉じた状態を描かない。幅 768px 未満では、サイドバーをドロワーにし、閉じた状態で出す。モックのモバイルの表示では、メニューのボタンでドロワーが開き、閉じるボタン、背景、Escape で閉じる。ナビゲーションとメニューを閉じるボタンの印は、ドロワーを開くと出る。

上端のヘッダーの下に、ページのタイトル、説明の文、照合の入力のフォームを縦に並べる。フォームは、予定の取り方、対象の月か予定の CSV、実績の CSV、失敗の文、照合するのボタンの順に並ぶ。

## ナビゲーション

**概要**: 予定と照合の画面を行き来する。

**値のソース**: 「予定」と「照合」のリンク。この画面では「照合」を今の画面として示す。

**活性条件**: 常に活性

**表示条件**: サイドバーの上の段に、アイコンの右に名前を置いて出す。「取り込み」と「要確認」は、アイコンを付けずに「予定」の下に字下げして置く。今の画面のリンクは、面の色で示す。

**カタログ**: [SiteNav の Receipt](https://buddy-docs.emon-apps.workers.dev/storybook/?path=/story/画面-common-sitenav--receipt)、[SiteNav の List](https://buddy-docs.emon-apps.workers.dev/storybook/?path=/story/画面-common-sitenav--list)

### インタラクション

#### 1. 「予定」を押す

1. 予定のカレンダーへ移る。入力は消える。

#### 2. 「照合」を押す

1. この画面を読み込み直す。入力は消える。

## メニューを開く

**概要**: 左のサイドバーを開閉する。幅 768px 未満では、サイドバーをドロワーにして開く。

**値のソース**: 3 本の横線のアイコン。読み上げる名前は「メニュー」。

**活性条件**: 常に活性

**表示条件**: 常に、ヘッダーの左端に出す。

**カタログ**: [SiteLayoutContainer の Mobile](https://buddy-docs.emon-apps.workers.dev/storybook/?path=/story/画面-common-sitelayoutcontainer--mobile)

### インタラクション

#### 1. 幅 768px 以上で押す

1. サイドバーを閉じ、画面の中身を広げる。もう一度押すと開く。

#### 2. 幅 768px 未満で押す

1. 左端から「メニュー」のドロワーが開き、ナビゲーションを出す。

## メニューを閉じる

**概要**: メニューのドロワーを閉じる。

**値のソース**: × のアイコン。読み上げる名前は「閉じる」。

**活性条件**: 常に活性

**表示条件**: メニューのドロワーを開いている間だけ出す。

**カタログ**: [SiteLayoutContainer の MobileOpen](https://buddy-docs.emon-apps.workers.dev/storybook/?path=/story/画面-common-sitelayoutcontainer--mobile-open)

### インタラクション

#### 1. 押すか、背景を押すか、Escape キーを押す

1. ドロワーが閉じ、フォーカスがメニューのボタンに戻る。

## アカウント

**概要**: ログインしている職員を示し、名前とログアウトを入れたメニューを開く。

**値のソース**: 職員の名前の先頭の 1 文字を入れた丸いボタン。読み上げる名前は「アカウント」。

**活性条件**: 常に活性

**表示条件**: ログインしているとき

**カタログ**: [ViewerMenu の Default](https://buddy-docs.emon-apps.workers.dev/storybook/?path=/story/画面-common-viewermenu--default)

### インタラクション

#### 1. 押す

1. 職員の名前とログアウトのボタンを入れたメニューを、ボタンの下に開く。
2. もう一度押すか、メニューの外を押すか、Escape キーを押すと閉じる。

## ログアウト

**概要**: ログアウトする。

**値のソース**: 「ログアウト」

**活性条件**: 常に活性

**表示条件**: アカウントのメニューを開いている間。BFF を通して API を呼ぶ構成で、ログインしているとき

**カタログ**: [ViewerMenu の Default](https://buddy-docs.emon-apps.workers.dev/storybook/?path=/story/画面-common-viewermenu--default)

### インタラクション

#### 1. 押す

1. ログアウトし、`/` へ移る。ログインしていないので、`/` からそのままログインの画面へ移る。
2. ログインした後は、`/` を経て予定のカレンダーに戻る。

**値のソース**: 「予定の取り方」の見出しと、「Google カレンダー」と「予定の CSV」の 2 つの選択肢。デフォルトは「Google カレンダー」。

## 失敗の文

**概要**: 照合できなかった理由と、職員が次にすることを示す。入力は残す。読み上げでは警告として扱う。

**値のソース**: 状態ごとに次の文を出す。

| 状態 | 文 |
| --- | --- |
| ファイルが大きすぎる | 「ファイルが大きすぎます。10 MB までのファイルにしてください。」 |
| 行のエラー | 「入力の CSV に誤りがあります。次の行を直して、もう一度照合してください。」と、行ごとのエラーの一覧 |
| ファイルのエラー（422） | 「入力の CSV に誤りがあります。」の後に、照合の API の文 |
| ファイルのエラー（413） | 「ファイルが大きすぎます。10 MB までのファイルにしてください。」 |
| ファイルのエラー（400） | 「入力を読めませんでした。ファイルを選び直して、もう一度照合してください。」 |
| カレンダーの失敗（502） | 「Google カレンダーから予定を取れませんでした。時間をおいて、もう一度照合してください。」 |
| カレンダーの失敗（503） | 「事業所の Google カレンダーの設定がありません。予定の CSV で照合してください。」 |
| カレンダーの失敗（403） | 「アカウントに事業所が結び付いていないので、Google カレンダーから予定を取れません。予定の CSV で照合してください。」 |
| 照合の失敗 | 「照合できませんでした。時間をおいて、もう一度照合してください。」 |

- 行ごとのエラーは、「実績の CSV の 3 行目の「訪問日」: 暦にない日付: 2024-13-01」の形で、ファイル、行、カラム、照合の API の文を並べる。カラムの無いエラーはカラムを省く。行は、見出しの行を 1 行目として数える。
- ファイルの合計が上限を超えているときは、前の照合の失敗より、ファイルが大きすぎることの文を先に出す。

**活性条件**: 常に活性

**表示条件**: 最後の照合が失敗したか、選んだファイルの合計が上限を超えたとき

**カタログ**: [ReceiptCheckForm の RowErrors](https://buddy-docs.emon-apps.workers.dev/storybook/?path=/story/画面-receipt-receiptcheckform--row-errors)

## 照合する

**概要**: 選んだ入力で照合し、結果の画面へ移る。

**値のソース**: 「照合する」。送信中は、文字に替えて回転するインジケーターを出す。

**活性条件**: 実績の CSV と、対象の月か予定の CSV がそろい、ファイルの合計が上限以下で、送信中でないとき

**表示条件**: 常に表示

**カタログ**: [ReceiptCheckForm の Calendar](https://buddy-docs.emon-apps.workers.dev/storybook/?path=/story/画面-receipt-receiptcheckform--calendar)

### インタラクション

#### 1. 押す

1. BFF を通して照合の API を呼び、「送信中」の状態にする。予定の取り方が「Google カレンダー」なら対象の月を、「予定の CSV」なら予定の CSV を、実績の CSV と一緒に送る。
2. 成功したら、照合の結果をブラウザの中に置き、照合の結果（`/receipt/result`）へ移る。
3. セッションが切れていたら、ログインの画面へ移る。ログインの後はこの画面に戻る。入力は残らない。
4. そのほかの失敗では、[失敗の文](#失敗の文) を出し、入力を残す。

## 全体動作

### 初期処理

- 対象の月のデフォルトは、職員のデバイスの日付の前の月にする。照合は、月が終わった後に前の月を対象にするためである。デバイスの日付で決めるので、この画面はサーバーで描画しない。
- フォーカスは `body` にある。URL の search params は読まない。

### 入力の変更と失敗の文

- 予定の取り方、対象の月、ファイルを変えたら、前の照合の失敗の文と行のエラーを消す。
- ファイルの合計の上限は、照合の API の本文の上限のデフォルト（10 MiB）から、multipart の境界と見出しの分の 64 KiB を引いた値にする。上限を超えたら、送らずに止める。

## 未決

- Google カレンダーの照合の対象のカレンダーは、照合の API の設定ファイルのうち、ログインした職員の事業所のものである。画面で職員やカレンダーを選ぶかは決めていない。
- 照合の権限は、PRD では全ての職員である。権限による判定は未実装である。
