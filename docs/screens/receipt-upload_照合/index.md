# receipt-upload 照合

照合する職員が、予定の取り方を選び、電子カルテから書き出した実績の CSV を上げて、照合を始める画面。照合が終わると、照合の結果の画面へ移る。

| 項目 | 値 |
| --- | --- |
| URL | `/receipt` |
| 使う人 | 全ての職員 |
| 実装 | `apps/web/src/routes/receipt.index.tsx`、`ReceiptCheckFormContainer`、`ReceiptCheckForm`、`CsvFileField` |

画面の項目と、web の型、OpenAPI の項目の対応は [API との対応](api.md) にある。

## 構成

上端のヘッダーの下に、ページの題、説明の文、照合の入力のフォームを縦に並べる。フォームは、予定の取り方、対象の月か予定の CSV、実績の CSV、失敗の文、照合するのボタンの順に並ぶ。

## ナビゲーション

**概要**: 予定と照合の画面を行き来する。

**値のソース**: 「予定」と「照合」のリンク。この画面では「照合」を今の画面として示す。

**活性条件**: 常に活性

**表示条件**: 常に表示

### インタラクション

#### 1. 「予定」を押す

1. 予定のカレンダーへ移る。入力は消える。

#### 2. 「照合」を押す

1. この画面を読み込み直す。入力は消える。

## ログインした職員

**概要**: ログインしている職員を示す。

**値のソース**: 職員の名前。

**活性条件**: 常に活性

**表示条件**: ログインしているとき。幅 768px 未満では出さない

## ログアウト

**概要**: ログアウトする。

**値のソース**: 「ログアウト」

**活性条件**: 常に活性

**表示条件**: BFF を通して API を呼ぶ動かし方で、ログインしているとき

### インタラクション

#### 1. 押す

1. ログアウトし、ログインの画面へ移る。

## ページの題

**概要**: 何の画面かを示す。

**値のソース**: 「照合」

**活性条件**: 常に活性

**表示条件**: 常に表示

## 説明の文

**概要**: 照合で何をするかを示す。

**値のソース**: 次の文。

| 文言 |
| --- |
| 「予定と、電子カルテから書き出した実績の CSV を比べ、食い違いを不整合、予定のみ、実績のみ、整合の 4 つに分けます。」 |

**活性条件**: 常に活性

**表示条件**: 常に表示

## 予定の取り方

**概要**: 照合に使う予定を、Google カレンダーから取るか、予定の CSV で渡すかを選ぶ。

**値のソース**: 「予定の取り方」の見出しと、「Google カレンダー」と「予定の CSV」の 2 つの選択肢。既定は「Google カレンダー」。

**活性条件**: 常に活性

**表示条件**: 常に表示

### インタラクション

#### 1. 「予定の CSV」を選ぶ

1. 対象の月の欄を、予定の CSV の欄に入れ替える。予定の CSV はまだ選んでいない。
2. 失敗の文を消す。

#### 2. 「Google カレンダー」を選ぶ

1. 予定の CSV の欄を、対象の月の欄に入れ替える。選んでいた予定の CSV は捨てる。対象の月は前に入れた値のままである。
2. 失敗の文を消す。

## 対象の月

**概要**: Google カレンダーから予定を取る月を入れる。

**値のソース**: 見出し、年と月の入力、補足を縦に並べる。年と月の既定は、職員の端末の日付の前の月。

| 部分 | 文言 |
| --- | --- |
| 見出し | 「対象の月」 |
| 補足 | 「その月の 1 日から月末までの予定を、職員の Google カレンダーから取ります。」 |

**活性条件**: 常に活性

**表示条件**: 予定の取り方が「Google カレンダー」のとき

### インタラクション

#### 1. 月を変える

1. 失敗の文を消す。月を空にしたときは、照合するのボタンを押せなくする。

## 予定の CSV

**概要**: 照合に使う予定の CSV のファイルを 1 つ選ぶ。

**値のソース**: 「予定の CSV」の見出しと、ファイルを選ぶ欄。選んだファイルの名前は、ブラウザの欄が出す。選べるのは CSV のファイルである。

**活性条件**: 常に活性

**表示条件**: 予定の取り方が「予定の CSV」のとき

### インタラクション

#### 1. ファイルを選ぶ

1. 失敗の文を消す。ファイルの合計が上限を超えたときは、[ファイルが大きすぎる](#ファイルが大きすぎる) にする。

## 実績の CSV

**概要**: 電子カルテから書き出した実績の CSV のファイルを 1 つ選ぶ。

**値のソース**: 「実績の CSV」の見出しと、ファイルを選ぶ欄。選んだファイルの名前は、ブラウザの欄が出す。選べるのは CSV のファイルである。下に「電子カルテから書き出した CSV。UTF-8 か Shift_JIS で、10 MB まで。」の補足を出す。

**活性条件**: 常に活性

**表示条件**: 常に表示

### インタラクション

#### 1. ファイルを選ぶ

1. 失敗の文を消す。ファイルの合計が上限を超えたときは、[ファイルが大きすぎる](#ファイルが大きすぎる) にする。

## 失敗の文

**概要**: 照合できなかった理由と、職員が次にすることを示す。入力は残す。読み上げでは警告として扱う。

**値のソース**: 状態ごとに次の文を出す。

| 状態 | 文 |
| --- | --- |
| ファイルが大きすぎる | 「ファイルが大きすぎます。10 MB までのファイルにしてください。」 |
| 行の誤り | 「入力の CSV に誤りがあります。次の行を直して、もう一度照合してください。」と、行ごとの誤りの一覧 |
| ファイルの誤り（422） | 「入力の CSV に誤りがあります。」の後に、照合の API の文 |
| ファイルの誤り（413） | 「ファイルが大きすぎます。10 MB までのファイルにしてください。」 |
| ファイルの誤り（400） | 「入力を読めませんでした。ファイルを選び直して、もう一度照合してください。」 |
| カレンダーの失敗（502） | 「Google カレンダーから予定を取れませんでした。時間をおいて、もう一度照合してください。」 |
| カレンダーの失敗（503） | 「Google カレンダーの設定がありません。予定の CSV で照合してください。」 |
| 照合の失敗 | 「照合できませんでした。時間をおいて、もう一度照合してください。」 |

- 行ごとの誤りは、「実績の CSV の 3 行目の「訪問日」: 暦にない日付: 2024-13-01」の形で、ファイル、行、列、照合の API の文を並べる。列の無い誤りは列を省く。行は、見出しの行を 1 行目として数える。
- ファイルの合計が上限を超えているときは、前の照合の失敗より、ファイルが大きすぎることの文を先に出す。

**活性条件**: 常に活性

**表示条件**: 最後の照合が失敗したか、選んだファイルの合計が上限を超えたとき

## 照合する

**概要**: 選んだ入力で照合し、結果の画面へ移る。

**値のソース**: 「照合する」。送信中は、文字に替えて回転するインジケーターを出す。

**活性条件**: 実績の CSV と、対象の月か予定の CSV がそろい、ファイルの合計が上限以下で、送信中でないとき

**表示条件**: 常に表示

### インタラクション

#### 1. 押す

1. BFF を通して照合の API を呼び、[送信中](#送信中) にする。予定の取り方が「Google カレンダー」なら対象の月を、「予定の CSV」なら予定の CSV を、実績の CSV と一緒に送る。
2. 成功したら、照合の結果をブラウザの中に置き、照合の結果（`/receipt/result`）へ移る。
3. セッションが切れていたら、ログインの画面へ移る。ログインの後はこの画面に戻る。入力は残らない。
4. そのほかの失敗では、[失敗の文](#失敗の文) を出し、入力を残す。

## 全体動作

### 初期処理

- 対象の月の既定は、職員の端末の日付の前の月にする。照合は、月が終わった後に前の月を対象にするためである。端末の日付で決めるので、この画面はサーバーで描画しない。
- フォーカスは `body` にある。URL の search params は読まない。

### 入力の変更と失敗の文

- 予定の取り方、対象の月、ファイルを変えたら、前の照合の失敗の文と行の誤りを消す。
- ファイルの合計の上限は、照合の API の本文の上限の既定（10 MiB）から、multipart の境界と見出しの分の 64 KiB を引いた値にする。上限を超えたら、送らずに止める。

## 未決

- Google カレンダーの照合の対象のカレンダーは、照合の API の設定ファイルで決まる。画面で職員やカレンダーを選ぶかは決めていない。
- 照合の権限は、PRD では全ての職員である。権限による判定は未実装である。
