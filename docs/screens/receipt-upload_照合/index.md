# receipt-upload 照合

照合の担当が、予定の取り方を選び、電子カルテから書き出した実績の CSV を上げて、照合を始める画面。  
照合が終わると、照合の結果の画面へ移る。

| 項目 | 値 |
| --- | --- |
| URL | `/receipt` |
| 使う人 | 照合の権限を持つ職員。デフォルトでは、マネージャーと事務の役職の職員である |
| 実装 | `apps/web/src/routes/receipt.index.tsx`、`apps/web/src/features/receipt/components/ReceiptCheckFormContainer.tsx` |

画面の項目と、web の型、OpenAPI の項目の対応は [API との対応](api.md) にある。

画面を描くコンポーネントのうち、実装の行のほかのものは次のとおり。

- `apps/web/src/features/receipt/components/ReceiptCheckPage.tsx`
- `apps/web/src/features/receipt/components/ReceiptCategoryGuide.tsx`
- `apps/web/src/features/receipt/components/ReceiptCheckForm.tsx`
- `apps/web/src/features/receipt/components/CsvFileField.tsx`

## 構成

ヘッダーの左に、メニューのボタンと buddy を置く。  
ヘッダーの右には、アカウントのボタンを置く。  
ヘッダーの下の左端には、画面の間を移るナビゲーションを置く。  
ナビゲーションに並べる項目と、権限で出し分ける項目は、[ナビゲーション](#ナビゲーション) にある。  
幅 768px 以上では、ナビゲーションを幅 224px の開いた形で始め、メニューのボタンで幅 80px のレールと切り替える。  
幅 768px 未満では、ナビゲーションをドロワーにし、閉じた状態で始める。  
ナビゲーションの印は、幅 768px 未満ではドロワーを開くと出る。

ヘッダーの下の、ナビゲーションの右に、ページのタイトル、説明の文、照合の入力のフォームを縦に並べる。  
フォームは、予定の取り方、対象の月か予定の CSV、実績の CSV、照合の失敗の文、照合するのボタンの順に並ぶ。

## メニュー

**概要**: ナビゲーションの形を切り替えるボタン。  
ヘッダーの左端に出す。  
幅 768px 未満では、ナビゲーションのドロワーを開く。

**値のソース**: 3 本の横線のアイコン。  
読み上げる名前は「メニュー」。

**カタログ**: [SiteLayoutContainer の Mobile](https://buddy-docs.emon-apps.workers.dev/storybook/?path=/story/画面-common-sitelayoutcontainer--mobile)

**操作**:

- 幅 768px 以上で押すと、ナビゲーションを、開いた形からレールに切り替える。
  - もう一度押すと開いた形に戻る。
- 幅 768px 未満で押すと、左端からナビゲーションのドロワーが開く。

## ナビゲーション

**概要**: 予定、照合、職員、利用者の画面の間を移る領域。  
ヘッダーの下の左端に出す。  
幅 768px 以上では、この画面では開いた形で始める。  
幅 768px 未満では、メニューのボタンで開いたドロワーの中に出す。

**値のソース**: 見出しと項目、出す職員は、[職員の一覧のナビゲーション](../staff-list_職員の一覧/index.md#ナビゲーション) にある。  
この画面では「照合」に今の画面の印を付ける。  
モックは、職員の管理の権限を持たず、照合の権限を持つ職員の画面を描くので、「カレンダー」と「照合」だけを出す。

**カタログ**: [SiteNav の Staff](https://buddy-docs.emon-apps.workers.dev/storybook/?path=/story/画面-common-sitenav--staff)

**操作**:

- 「カレンダー」を押すと、予定のカレンダーへ移る。
  - 入力は消える。
- 「照合」を押すと、この画面を読み込み直す。
  - 入力は消える。
- 幅 768px 未満で、閉じるボタンか覆いを押すか、Escape キーを押すと、ナビゲーションのドロワーが閉じ、フォーカスがメニューのボタンに戻る。

## アカウント

**概要**: ログインしている職員を示し、名前、自分の情報、ログアウトを入れたメニューを開くボタン。  
ヘッダーの右端に出す。

**値のソース**: 職員の名前の先頭の 1 文字を入れた丸と、職員の名前を並べたボタン。  
幅 768px 未満では、丸だけを出す。  
読み上げる名前は「アカウント（<職員の名前>）」にする。  
幅 768px 未満で名前を隠しても、読み上げる名前は変えない。

**カタログ**: [ViewerMenu の Default](https://buddy-docs.emon-apps.workers.dev/storybook/?path=/story/画面-common-viewermenu--default)

**操作**:

- 押すと、職員の名前、自分の情報のリンク、ログアウトのボタンを入れたメニューを、ボタンの下に開く。
  - もう一度押すか、メニューの外を押すか、Escape キーを押すと閉じる。
- メニューの「自分の情報」を押すと、メニューを閉じ、[自分の情報](../account-profile_自分の情報/index.md) へ移る。

## ログアウト

**概要**: ログアウトするボタン。  
アカウントのメニューの中に出す。

**値のソース**: 「ログアウト」

## 照合の失敗の文

**概要**: 照合できなかった理由と、職員が次にすることを示すメッセージ。  
実績の CSV の下の、照合するのボタンの上に出す。  
入力は残す。  
読み上げでは警告として扱う。

**値のソース**: 状態ごとに次の文を出す。

| 状態 | 文 |
| --- | --- |
| ファイルが大きすぎる | 「ファイルが大きすぎます。10 MB までのファイルにしてください。」 |
| 行のエラー、ファイルのエラーで、入力の CSV に誤りがあるとき | 「入力の CSV に誤りがあります。次のところを直して、もう一度照合してください。」と、誤りの一覧 |
| ファイルのエラーで、ファイルが大きすぎるとき | 「ファイルが大きすぎます。10 MB までのファイルにしてください。」 |
| ファイルのエラーで、選んだファイルか対象の月を読めないとき | 「入力を読めませんでした。ファイルを選び直して、もう一度照合してください。」 |
| カレンダーの失敗で、Google カレンダーから予定を取れないとき | 「Google カレンダーから予定を取れませんでした。時間をおいて、もう一度照合してください。」 |
| カレンダーの失敗で、事業所で Google カレンダーの準備ができていないとき | 「この事業所では、まだ Google カレンダーを使う準備ができていません。予定の CSV で照合してください。」 |
| 照合の失敗で、画面を開いた後に照合の権限を外されたとき | 「照合の権限がありません。権限が要るときは、職員の管理の権限を持つ職員に頼んでください。」 |
| 照合の失敗で、照合の権限を確認できないとき | 「照合の権限を確認できませんでした。時間をおいて、もう一度照合してください。」 |
| 照合の失敗で、そのほかの理由で照合できないとき | 「照合できませんでした。時間をおいて、もう一度照合してください。」 |

状態と文の要因の対応は、[API との対応の状態と失敗の要因](api.md#状態と失敗の要因) にある。

誤りの一覧には、誤りの理由ごとに次の文を並べる。  
<ファイル> には、実績の CSV か予定の CSV が入る。  
<次にすること> には、実績の CSV なら「電子カルテから書き出し直してください。」が、予定の CSV なら「CSV として保存し直してください。」が入る。

| 理由 | 文 |
| --- | --- |
| 列が無い | 「<ファイル> に「開始時間」「提供時間」の列がありません。<次にすること>」。足りない列を、ファイルごとに 1 つの文にまとめ、一覧の先頭に出す |
| 文字を読めない | 「<ファイル> の文字を読めません。<次にすること>」 |
| ファイルが空 | 「<ファイル> が空です。<次にすること>」 |
| CSV として読めない行 | 「<ファイル> の 3 行目を読めません。値の中の「"」を確認してください。」 |
| 値が空 | 「<ファイル> の 3 行目の「利用者名」が空です。」 |
| 日付を読めない | 「<ファイル> の 3 行目の「訪問日」を日付として読めません。」 |
| 時刻を読めない | 「<ファイル> の 3 行目の「開始時間」を時刻として読めません。」 |
| 提供時間が分の数でない | 「<ファイル> の 3 行目の「提供時間」が分の数になっていません。」 |
| ほかの理由 | 「<ファイル> の 3 行目に誤りがあります。」 |

- 行は、見出しの行を 1 行目として数える。
- 文字コードの名前と、照合の仕組みが内部で作る英語の文は出さない。
- ファイルの合計が上限を超えているときは、前の照合の失敗より、ファイルが大きすぎることの文を先に出す。

**カタログ**: [ReceiptCheckForm の RowErrors](https://buddy-docs.emon-apps.workers.dev/storybook/?path=/story/画面-receipt-receiptcheckform--row-errors)

## 全体動作

### 初期処理

- 対象の月のデフォルトは、職員のデバイスの日付の前の月にする。
  - 照合は、月が終わった後に前の月を対象にするためである。
- フォーカスは `body` にある。
- URL の search params は読まない。

### 入力の確認と送信

- 予定の取り方、対象の月、ファイルを変えたら、前の照合の失敗の文と誤りの一覧を消す。
- 選んだファイルの合計が上限を超えたら、照合を始めずに「ファイルが大きすぎる」の状態にする。
  - 上限は、画面に書く「10 MB まで」より少し小さい。上限の決め方は、[レセプトの照合の Design Doc の画面の照合の流れ](https://github.com/Fukuemon/buddy/blob/develop/services/receipt/DesignDoc.md#画面の照合の流れ) にある。

### 権限の確認

- 照合の権限を持たない職員には、「権限が無い」の状態を出す。
- ログインした職員の権限は、画面を開いたときに読み、開いた後も次のときに読み直す。
  - 前に読んでから 5 分が過ぎた後に、職員がほかのウィンドウからこの画面に戻ったとき
  - 前に読んでから 5 分が過ぎた後に、職員が画面を移ったとき
- 読み直して照合の権限が無くなっていたら、画面を読み込み直さなくても「権限が無い」の状態に替える。
  - 照合の権限を足された職員には、同じときに「権限が無い」の状態を消し、照合の入力を出す。
- 権限を外されてから読み直すまでの間に照合するを押すと、照合できず、「照合の失敗」の状態になる。
- 読み直す時機は、[ADR-0008 の Viewer を取り直す時機](../../adr/0008-web-permission-checks.md#viewer-を取り直す時機) で決めた。
