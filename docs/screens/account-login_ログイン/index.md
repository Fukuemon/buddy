# account-login ログイン

職員が、事業所に登録したメールアドレスを入れて、ふだん使っているログインの画面へ進む画面。  
web の画面ではなく、buddy のログインを受け持つサービスが出す。

| 項目 | 値 |
| --- | --- |
| URL | ブローカーの `/login`。web の `/auth/login` から Hydra を通って、`login_challenge` を付けてリダイレクトされる |
| 使う人 | ログインを試す全ての職員。ログインしていなくても開ける |
| 実装 | ID ブローカー（`services/broker`）の `services/broker/internal/login/pages.go`、`services/broker/internal/login/login.go` |

画面の項目と、web の型、OpenAPI の項目の対応は [API との対応](api.md) にある。  
ログインとログアウトの流れは、[ID ブローカーの Design Doc のログイン](../../design/services/broker.md#ログイン) と [ID ブローカーの Design Doc のログアウト](../../design/services/broker.md#ログアウト) にある。

## 構成

画面の背景の中央に白いカードを置き、カードの上端にロゴ、その下にページのタイトルを出す。  
3 つの状態は同じカードの形で、カードの中身だけが違う。  
幅 768px 未満では、カードの内側の余白を狭める。

## ロゴ

**概要**: buddy の画面であることを示す。

**値のソース**: 「buddy」。  
web のヘッダーの名前と同じ主の色で出す。  
ページのタイトルと続けて読み上げないよう、スクリーンリーダーには読ませない。

**活性条件**: 常に活性

**表示条件**: 常に表示

## ページのタイトル

**概要**: 画面の用途か、失敗したことを示す。

**値のソース**: 状態ごとに次の文を出す。  
ブラウザのタブのタイトルは、状態によらず「buddy にログイン」。

| 状態 | 文 |
| --- | --- |
| メールの入力 | 「buddy にログイン」 |
| ログインの失敗 | 「ログインできませんでした」 |
| ログアウトの失敗 | 「ログアウトできませんでした」 |

**活性条件**: 常に活性

**表示条件**: 常に表示

## メールアドレス

**概要**: 職員が、事業所に登録したメールアドレスを入れる。

**値のソース**: ラベルは「メールアドレス」。  
開いたときは空。

**活性条件**: 常に活性

**表示条件**: 「メールの入力」の状態で表示

## 入力の説明

**概要**: 入れるメールアドレスと、次に移る画面を伝える。

**値のソース**: 次の文を出す。

| 文 |
| --- |
| 「事業所に登録したメールアドレスを入れると、ふだん使っているログインの画面が開きます。」 |

- 「ふだん使っているログインの画面」は、事業所が職員に使わせている Google や LINE のようなサービスのログインの画面である。
  - 職員が見慣れた画面として書く。

**活性条件**: 常に活性

**表示条件**: 「メールの入力」の状態で表示

## 次へ

**概要**: 入れたメールアドレスで、ふだん使っているログインの画面へ進む。

**値のソース**: 「次へ」。  
カードの幅いっぱいの主のボタンにする。

**活性条件**: 常に活性。  
メールアドレスが空か、メールアドレスの形でなければ、ブラウザが送信を止めて入力欄に知らせる。

**表示条件**: 「メールの入力」の状態で表示

### インタラクション

#### 1. 押す

1. メールアドレスが登録した有効な職員のものなら、その職員の事業所の、ふだん使っているログインの画面へ移る。
2. 登録していないメールアドレスと、休職と退職の職員のメールアドレスでは、ふだん使っているログインの画面へ移らず、[ログインの失敗](../account-error_ログインの失敗/index.md) の画面へ移る。
   - 事業所を示さないよう、ログインの途中の失敗と同じ文言を出す。
3. 同じメールアドレスか同じ送信元から続けて押し、試行の回数の上限を超えたときは、メールアドレスによらず、[ログインの失敗](../account-error_ログインの失敗/index.md) の画面へ移る。
   - 画面は「試行の回数の上限を超えた」の状態にし、時間をおいてから試すよう伝える文を出す。

## 説明の文

**概要**: 職員が次にすることを伝える。

**値のソース**: 状態ごとに次の文を出す。  
文言は、[ログインの失敗](../account-error_ログインの失敗/index.md) の画面が、ログインの途中の失敗で出す文と同じにする。

| 状態 | 文 |
| --- | --- |
| ログインの失敗 | 「時間をおいて、もう一度ログインしてください。」 |
| ログアウトの失敗 | 「時間をおいて、もう一度 buddy を開いてログアウトしてください。」 |

- 「ログインの失敗」の状態には、[ログインの失敗](../account-error_ログインの失敗/index.md) の画面と違い、もう一度ログインするリンクが無い。
- 登録していないメールアドレスのように、ログインを断るときは、この状態でなく [ログインの失敗](../account-error_ログインの失敗/index.md) の画面を出す。
  - この状態になる失敗の一覧は、[ID ブローカーの Design Doc のログイン](../../design/services/broker.md#ログイン) にある。

**活性条件**: 常に活性

**表示条件**: 「ログインの失敗」と「ログアウトの失敗」の状態で表示

## 全体動作

### 初期処理

- フォーカスはメールアドレスの入力欄にある。
- 前にログインしてから 12 時間の間は、この画面を出さずに buddy に戻る。
  - ログアウトした後と、[ログインの失敗](../account-error_ログインの失敗/index.md) の画面から入り直すときは、この画面を出す。
- URL の search params から表示を復元しない。
- 色と書体は、web と同じ値で描く。
  - 値をそろえる方法は [ID ブローカーの Design Doc のログイン](../../design/services/broker.md#ログイン) にある。
