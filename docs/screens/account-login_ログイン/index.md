# account-login ログイン

職員が、事業所に登録したメールアドレスを入れて、ふだん使っているログインの画面へ進む画面。  
web の画面ではなく、buddy のログインを受け持つサービスが出す。

| 項目 | 値 |
| --- | --- |
| URL | ブローカーの `/login`。web の `/auth/login` から Hydra を通って、`login_challenge` を付けてリダイレクトされる |
| 使う人 | ログインを試す全ての職員。ログインしていなくても開ける |
| 実装 | 画面のソースは `apps/broker/src/pages.tsx`。ID ブローカー（`services/broker`）が、生成したテンプレートを `services/broker/internal/login/pages.go` で埋め込み、`services/broker/internal/login/login.go` で出す |

画面の項目と、web の型、OpenAPI の項目の対応は [API との対応](api.md) にある。  
ログインとログアウトの流れは、[ID ブローカーの Design Doc のログイン](../../design/services/broker.md#ログイン) と [ID ブローカーの Design Doc のログアウト](../../design/services/broker.md#ログアウト) にある。

## 構成

画面の背景の中央に白いカードを置き、カードの上端にロゴ、その下にページのタイトルを出す。  
5 つの状態は同じカードの形で、カードの中身だけが違う。  
幅 768px 未満では、カードの内側の余白を狭める。

## ロゴ

**概要**: buddy の画面であることを示すラベル。

**値のソース**: 「buddy」。  
web のヘッダーの名前と同じ主の色で出す。  
ページのタイトルと続けて読み上げないよう、スクリーンリーダーには読ませない。

## ページのタイトル

**概要**: 画面の用途か、失敗したことを示すラベル。

**値のソース**: 状態ごとに次の文を出す。  
ブラウザのタブのタイトルは、状態によらず「buddy にログイン」。

| 状態 | 文 |
| --- | --- |
| メールの入力 | 「buddy にログイン」 |
| ログインを続けられない | 「ログインを続けられませんでした」 |
| 試行の回数の上限を超えた | 「しばらくログインできません」 |
| 障害でログインできない | 「ログインできませんでした」 |
| ログアウトの失敗 | 「ログアウトできませんでした」 |

## メールアドレス

**概要**: 職員が、事業所に登録したメールアドレスを入れるテキストボックス。

**値のソース**: ラベルは「メールアドレス」。  
開いたときは空。

## 入力の説明

**概要**: 入れるメールアドレスと、次に移る画面を伝えるラベル。

**値のソース**: 次の文を出す。

| 文 |
| --- |
| 「事業所に登録したメールアドレスを入れると、ふだん使っているログインの画面が開きます。」 |

- 「ふだん使っているログインの画面」は、事業所が職員に使わせている Google や LINE のようなサービスのログインの画面である。
  - 職員が見慣れた画面として書く。

## 次へ

**概要**: 入れたメールアドレスで、ふだん使っているログインの画面へ進むボタン。

**値のソース**: 「次へ」。  
カードの幅いっぱいの主のボタンにする。  
メールアドレスが空か、メールアドレスの形でなければ、ブラウザが送信を止めて入力欄に知らせる。

**操作**: 押すと、入れたメールアドレスの職員の事業所を探す。

1. メールアドレスが登録した有効な職員 1 人のものなら、その職員の事業所の、ふだん使っているログインの画面へ移る。
2. 次のときは、ふだん使っているログインの画面へ移らず、[ログインの失敗](../account-error_ログインの失敗/index.md) の画面へ移る。
   - 登録していないメールアドレス
   - 休職と退職の職員のメールアドレス
   - 登録の途中の職員のメールアドレス
   - 同じメールアドレスの職員が、2 つ以上の事業所にいる
   - 事業所と職員の状態を示さないよう、どれも「登録を確認できない」の状態にし、事業所の管理者に登録のメールアドレスを確認するよう伝える。
3. 同じメールアドレスで続けて押し、試行の回数の上限を超えたときは、メールアドレスが登録されているかによらず、[ログインの失敗](../account-error_ログインの失敗/index.md) の画面へ移る。
   - 画面は「試行の回数の上限を超えた」の状態にし、待つ長さを伝える文を出す。
4. 同じ送信元から続けて開くか押し、試行の回数の上限を超えたときは、この画面を「試行の回数の上限を超えた」の状態にする。
5. ブラウザの確認を通ったが、buddy がメールアドレスの形を認めなかったときは、この画面を「ログインを続けられない」の状態にする。

## 説明の文

**概要**: 職員が次にすることを伝えるラベル。

**値のソース**: 状態ごとに次の文を出す。

| 状態 | 文 |
| --- | --- |
| ログインを続けられない | 「もう一度 buddy を開いて、ログインしてください。」 |
| 試行の回数の上限を超えた | 「続けて何度もログインを試したため、受け付けを止めています。30 秒ほどおいてから、もう一度ログインしてください。」 |
| 障害でログインできない | 「時間をおいて、もう一度ログインしてください。」 |
| ログアウトの失敗 | 「時間をおいて、もう一度 buddy を開いてログアウトしてください。」 |

- 試行の回数の上限を超えたときと、障害でログインできないときは、[ログインの失敗](../account-error_ログインの失敗/index.md) の画面の同じ状態と同じ文を出す。
- 3 つの失敗の状態には、[ログインの失敗](../account-error_ログインの失敗/index.md) の画面と違い、もう一度ログインするリンクが無い。
  - ログインを続けられないときは、buddy を開き直すよう伝える。
- 時間をおいて試すよう伝えるのは、障害でログインできないときだけにする。
- 登録していないメールアドレスのように、ログインを断るときは、3 つの失敗の状態でなく [ログインの失敗](../account-error_ログインの失敗/index.md) の画面を出す。
  - 3 つの失敗の状態になる失敗の一覧は、[ID ブローカーの Design Doc のログイン](../../design/services/broker.md#ログイン) にある。

## 全体動作

### 初期処理

- フォーカスはメールアドレスの入力欄にある。
- 前にログインしてから 12 時間の間は、この画面を出さずに buddy に戻る。
  - ログアウトした後と、[ログインの失敗](../account-error_ログインの失敗/index.md) の画面から入り直すときは、この画面を出す。
  - 12 時間の間でも、職員が休職か退職になっていれば、この画面を出さずに [ログインの失敗](../account-error_ログインの失敗/index.md) の画面へ移る。
- URL の search params から表示を復元しない。
- 色と書体は、web と同じ値で描く。
  - 値をそろえる方法は [ID ブローカーの Design Doc のログイン](../../design/services/broker.md#ログイン) にある。
