# account-login ログイン

職員が、事業所に登録したメールアドレスを入れて、事業所の上流の IdP のログインの画面へ進む画面。  
web の画面ではなく、ID ブローカー（`services/broker`）が出す。

| 項目 | 値 |
| --- | --- |
| URL | ブローカーの `/login`。web の `/auth/login` から Hydra を通って、`login_challenge` を付けてリダイレクトされる |
| 使う人 | ログインを試す全ての職員。ログインしていなくても開ける |
| 実装 | `services/broker/internal/login/pages.go`、`services/broker/internal/login/login.go` |

画面の項目と、web の型、OpenAPI の項目の対応は [API との対応](api.md) にある。

## 構成

画面の背景の中央に白いカードを置き、カードの上端にロゴ、その下にページのタイトルを出す。  
3 つの状態は同じカードの形で、カードの中身だけが違う。  
幅 768px 未満では、カードの内側の余白を狭める。

## ロゴ

**概要**: buddy の画面であることを示す。

**値のソース**: 「buddy」。  
web のヘッダーの名前と同じ主の色で出す。  
ページのタイトルと続けて読み上げないよう、スクリーンリーダーには読ませない。

**活性条件**: 常に活性

**表示条件**: 常に表示

## ページのタイトル

**概要**: 画面の用途か、失敗したことを示す。

**値のソース**: 状態ごとに次の文を出す。  
ブラウザのタブのタイトルは、状態によらず「buddy にログイン」。

| 状態 | 文 |
| --- | --- |
| メールの入力 | 「buddy にログイン」 |
| ログインの失敗 | 「ログインできませんでした」 |
| ログアウトの失敗 | 「ログアウトできませんでした」 |

**活性条件**: 常に活性

**表示条件**: 常に表示

## メールアドレス

**概要**: 職員が、事業所に登録したメールアドレスを入れる。

**値のソース**: ラベルは「メールアドレス」。  
開いたときは空。

**活性条件**: 常に活性

**表示条件**: 「メールの入力」の状態で表示

## 入力の説明

**概要**: 入れるメールアドレスと、次に移る画面を伝える。

**値のソース**: 次の文を出す。

| 文 |
| --- |
| 「事業所に登録したメールアドレスを入れてください。事業所のログインの画面へ移ります。」 |

**活性条件**: 常に活性

**表示条件**: 「メールの入力」の状態で表示

## 次へ

**概要**: 入れたメールアドレスで、事業所の上流の IdP のログインの画面へ進む。

**値のソース**: 「次へ」。  
カードの幅いっぱいの主のボタン。

**活性条件**: 常に活性。  
メールアドレスが空か、メールアドレスの形でなければ、ブラウザが送信を止めて入力欄に知らせる。

**表示条件**: 「メールの入力」の状態で表示

### インタラクション

#### 1. 押す

1. メールアドレスが登録した有効な職員のものなら、その職員の事業所の上流の IdP のログインの画面へ移る。
2. 登録していないメールアドレスと、休職と退職の職員のメールアドレスでは、上流の IdP へ移らず、web の [ログインの失敗](../account-error_ログインの失敗/index.md) へ移る。
   - 事業所を示さないよう、ログインの途中の失敗と同じ文言を出す。

## 説明の文

**概要**: 職員が次にすることを伝える。

**値のソース**: 状態ごとに次の文を出す。  
文言は、web のログインの失敗の画面が、ログインの途中の失敗で出す文と同じにする。

| 状態 | 文 |
| --- | --- |
| ログインの失敗 | 「時間をおいて、もう一度ログインしてください。」 |
| ログアウトの失敗 | 「時間をおいて、もう一度 buddy を開いてログアウトしてください。」 |

**活性条件**: 常に活性

**表示条件**: 「ログインの失敗」と「ログアウトの失敗」の状態で表示

## 全体動作

### 初期処理

- API を呼ばない。
- フォーカスはメールアドレスの入力欄にある。
- Hydra がログインのセッションを保っているときは、この画面を出さずに web へ戻す。
- 色と書体は、web と同じ packages/ui のトークンの値で描く。
  - 値をそろえる方法は [ID ブローカーの Design Doc のログイン](../../design/services/broker.md#ログイン) にある。

### web のログインの失敗の画面との分担

ログインを拒んだとき（登録していないメールアドレス、休職と退職の職員、上流の IdP のメールアドレスの違い）は、ブローカーが Hydra へ拒んだ結果を返し、web が [ログインの失敗](../account-error_ログインの失敗/index.md) を出す。  
この画面の「ログインの失敗」の状態は、ブローカーが Hydra へ結果を返さずに終えるときに出る。  
この状態には、もう一度ログインするリンクが無い。  
例は次のとき。

- `login_challenge` か `consent_challenge` が無いか、読めない
- 上流の IdP からの戻りの値が、このブラウザで始めたログインのものと確認できない
- 上流の IdP の discovery の文書を読めない
- メールを入れた後に、職員を DB から引けない
- ほかのサイトから送られた
- Hydra へ結果を返せない

### E2E が指す要素

ブローカーの画面は web の画面ではないので、`data-testid` を持たない。  
E2E は、メールアドレスの入力欄を `name="email"` で、次へを送信のボタンで指す。
