# staff-list 職員の一覧

職員の管理の権限を持つ職員が、事業所の有効な職員を、チーム、役職、部署とともに一覧し、登録と詳細へ移る画面。
休職と退職の職員は、状態の絞り込みで出す。

| 項目 | 値 |
| --- | --- |
| URL | `/staff` |
| 使う人 | 職員の管理の権限を持つ職員（デフォルトはマネージャー） |
| 実装 | `apps/web/src/routes/staff.tsx`、`apps/web/src/features/staff/components/StaffListContainer.tsx`、`apps/web/src/features/staff/components/StaffListView.tsx`、`apps/web/src/components/site/RowTable.tsx`、`apps/web/src/components/site/ListTools.tsx`、`apps/web/src/components/site/PageForbiddenMessage.tsx` |

画面の項目と、web の型、OpenAPI の項目の対応は [API との対応](api.md) にある。
カラム、絞り込み、並び順は、[使う場面](#使う場面) から決めた。

## 構成

ヘッダーの左に、メニューのボタンと buddy を置く。
ヘッダーの右には、アカウントのボタンを置く。
ヘッダーの下の左端には、画面の間を移るナビゲーションを置く。
ナビゲーションは、見出し「予定」の下にカレンダー、取り込み、要確認、連携を並べ、見出し「照合」の下に照合を、見出し「職員」の下に職員を並べる。
取り込み、要確認、連携と、見出し「職員」のまとまりは、職員の管理の権限を持つ職員にだけ出す。
今の画面の職員に印を付ける。
幅 768px 以上では、ナビゲーションを幅 224px の開いた形で始め、メニューのボタンで幅 80px のレールと切り替える。
幅 768px 未満では、ナビゲーションをドロワーにし、閉じた状態で始める。
ナビゲーションの印は、幅 768px 未満ではドロワーを開くと出る。

ヘッダーの下の、ナビゲーションの右に、ページのタイトルとヘルプと職員を登録のボタン、名前の検索と絞り込みと人数、職員の一覧を縦に並べる。
職員の一覧は、[画面仕様書の規約の一覧](../rules.md#一覧) の形にする。
幅 768px 以上では、行全体を押せる表にする。
幅 768px 未満では、1 行目に名前、2 行目にチーム、役職、部署を「・」でつなげた 2 行のリストにする。
休職と退職の職員を出すときは、戻る予定の日と退職した日を、1 行目の名前の右に出す。
ヘルプの説明の印は、ヘルプを開くと出る。

## メニュー

**概要**: ナビゲーションの形を切り替える。  
幅 768px 未満では、ナビゲーションのドロワーを開く。

**値のソース**: 3 本の横線のアイコン。  
読み上げる名前は「メニュー」。

**活性条件**: 常に活性

**表示条件**: 常に、ヘッダーの左端に出す。

**カタログ**: [SiteLayoutContainer の Mobile](https://buddy-docs.emon-apps.workers.dev/storybook/?path=/story/画面-common-sitelayoutcontainer--mobile)

### インタラクション

#### 1. 幅 768px 以上で押す

1. ナビゲーションを、開いた形からレールに切り替える。もう一度押すと開いた形に戻る。

#### 2. 幅 768px 未満で押す

1. 左端からナビゲーションのドロワーが開く。

## ナビゲーション

**概要**: 予定、照合、職員の画面の間を移る。

**値のソース**: 見出し「予定」の下に、「カレンダー」「取り込み」「要確認」「連携」のアイコンと名前を並べる。  
見出し「照合」の下に、「照合」のアイコンと名前を置く。  
見出し「職員」の下に、人のアイコンと「職員」を置く。  
確認が必要な予定の件数を、「要確認」の右端に印で示す。  
今の画面に面の色の印を付ける。  
この画面では「職員」に付ける。  
レールでは見出しを出さず、アイコンの下に名前を置き、見出しのまとまりの間を区切り線で分ける。

**活性条件**: 常に活性

**表示条件**: 常に、ヘッダーの下の左端に出す。  
幅 768px 以上では、この画面では開いた形で始める。  
幅 768px 未満では、メニューのボタンで開いたドロワーの中に出す。  
「取り込み」「要確認」「連携」と、見出し「職員」のまとまりは、職員の管理の権限を持つ職員にだけ出す。

**カタログ**: [SiteNav の Manager](https://buddy-docs.emon-apps.workers.dev/storybook/?path=/story/画面-common-sitenav--manager)

### インタラクション

#### 1. 「カレンダー」を押す

1. 予定のカレンダーへ移る。

#### 2. 「取り込み」「要確認」「連携」を押す

1. 予定の取り込み、確認が必要な予定、カレンダーの連携の画面へ移る。

#### 3. 「照合」を押す

1. 照合の画面へ移る。

#### 4. 「職員」を押す

1. この画面を開き直す。

#### 5. 幅 768px 未満で、閉じるボタンか背景を押すか、Escape キーを押す

1. ナビゲーションのドロワーが閉じ、フォーカスがメニューのボタンに戻る。

## アカウント

**概要**: ログインしている職員を示し、名前とログアウトを入れたメニューを開く。

**値のソース**: 職員の名前の先頭の 1 文字を入れた丸と、職員の名前を並べたボタン。  
幅 768px 未満では、丸だけを出す。  
読み上げる名前は「アカウント（<職員の名前>）」にし、幅 768px 未満で名前を隠しても変えない。

**活性条件**: 常に活性

**表示条件**: ログインしているとき

**カタログ**: [ViewerMenu の Default](https://buddy-docs.emon-apps.workers.dev/storybook/?path=/story/画面-common-viewermenu--default)

### インタラクション

#### 1. 押す

1. 職員の名前とログアウトのボタンを入れたメニューを、ボタンの下に開く。
2. もう一度押すか、メニューの外を押すか、Escape キーを押すと閉じる。

## ログアウト

**概要**: ログアウトする。

**値のソース**: 「ログアウト」

**活性条件**: 常に活性

**表示条件**: アカウントのメニューを開いている間。  
BFF を通して API を呼ぶ構成で、ログインしているとき

**カタログ**: [ViewerMenu の Default](https://buddy-docs.emon-apps.workers.dev/storybook/?path=/story/画面-common-viewermenu--default)

### インタラクション

#### 1. 押す

1. ログアウトし、`/` へ移る。ログインしていないので、`/` からそのままログインの画面へ移る。

**値のソース**: 「職員」

**活性条件**: 常に活性

**表示条件**: 職員の管理の権限を持つとき

## ヘルプ

**値のソース**: 「?」のボタン。読み上げる名前は「ヘルプ」。  
押すと、ページのタイトルの下に次の説明を出す。

## 状態の絞り込み

**概要**: 有効の職員だけを出すか、休職か退職の職員を出すかを選ぶ。

**値のソース**: 次の選択肢のセレクト。  
最初は「有効」を選ぶ。  
「有効」のほかを選んだときだけ、枠を太くする。

| 選択肢 | 出す職員 | 一覧に足すカラム |
| --- | --- | --- |
| 「有効」 | 有効の職員 | なし |
| 「休職」 | 休職の職員 | 「戻る予定の日」 |
| 「退職」 | 退職の職員 | 「退職した日」 |
| 「すべて」 | 全ての職員 | 「状態」 |

「すべて」を選んだときの「状態」のカラムには、休職と退職の行にだけ状態の印を出し、有効の行には印を出さない。  
休職の印は「休職（2027/04/01 に戻る予定）」か「休職」で、注意の面の色で示す。退職の印は「退職（2026/09/30）」で、薄い面の色で示す。  
「すべて」の状態のモックは無い。

**活性条件**: 常に活性

**表示条件**: 職員を読み終えたとき

### インタラクション

#### 1. 値を選ぶ

1. 選んだ状態の職員だけを一覧に出し、人数を出し直す。「休職」を選ぶと「休職の職員」の状態に、「退職」を選ぶと「退職の職員」の状態にする。
2. 合う職員がいなければ、「絞り込みで 0 件」の状態にする。

## 全体動作

### 使う場面

職員の一覧は、職員の管理の権限を持つ職員（マネージャー）が、次の場面で開く。  
場面は、[PRD の事業所と職員のユーザーストーリー](../../PRD.md#事業所と職員-職員が最初のログインから自分の事業所の予定を使い始める) と、マネージャーの仕事から書き出した。  
職員の管理は毎日の仕事ではないので、毎日の場面は無い。

| 場面 | 頻度 | 一覧に要る情報 |
| --- | --- | --- |
| 職員を探して詳細を開き、役職、権限、休職を変える | 週に数回 | 名前。同じ名字の職員を見分けるチームと役職 |
| チームの人数と顔ぶれを見て、訪問の割り振りと体制を考える | 週に数回 | チーム、役職、人数 |
| 新しい職員を登録し、一覧に出たことを見る | まれ（入職のとき） | 登録のボタン、名前、チーム |
| 休職中の職員と、戻る予定の日を見る | まれ（月に 1 回ほど） | 休職の職員だけ、戻る予定の日 |
| 退職した職員を確認する | まれ | 退職の職員だけ、退職した日 |
| 看護部、リハビリ部のような部署ごとに職員を見る | まれ | 部署 |

利用者の一覧（#347）にも、同じ考え方が当てはまる。  
利用者の一覧を開く場面の多くは、利用中の利用者を探して担当と受けているサービスを見ることで、利用の終了の利用者を見るのは、利用を再開するときと過去を確認するときに限られる。  
そのため、利用の終了の利用者はデフォルトでは出さず、状態の絞り込みで出す形を写せる。  
ただし、PRD の要件は「利用の終了の利用者は、利用者の一覧に印を付けて出て」と書いているので、この形を写すときは #347 で PRD の文も直す。

### 決めたこと

場面から、カラム、絞り込み、並び順、デフォルトの表示を次のとおり決めた。

- デフォルトは有効の職員だけを出し、状態のカラムを出さない。休職と退職の職員を見る場面は、どれもまれだからである。
- 休職と退職は、状態の絞り込みで出す。休職を選ぶと戻る予定の日を、退職を選ぶと退職した日を出す。どの行も同じ状態になるので、状態の文字は繰り返さない。
- 状態の絞り込みの「在籍」（有効と休職）をやめた。有効と休職の職員を混ぜて見る場面が無い。
- カラムは、名前、チーム、役職、部署の順にする。週に数回の 2 つの場面が、名前の次にチームと役職を見るためである。
- 部署は最後のカラムに残す。部署ごとに見る場面はまれだが、看護師とリハビリの職員を見分ける値は部署だけである。
- メールアドレスを一覧から外した。どの場面も一覧でメールアドレスを見比べず、[職員の詳細](../staff-detail_職員の詳細/index.md) のプロフィールにある。
- 名前の頭文字の丸を外した。丸とチームの色の点が同じ行に並ぶと、どちらが何を示すかが紛れる。
- チームのカラムに、チームの色の小さい点を置く。チームのまとまりを見る場面で、色の切れ目がまとまりの境を示す。部署には色を付けない。
- 並び順は、チームの順、同じチームの中は名前の順にする。チームの顔ぶれを見る場面は並びで見るが、職員を探す場面は名前の検索で探すので、並びによらない。
- 絞り込みは、名前の検索、チーム、役職、部署、状態の順に置き、カラムの順にそろえる。

### 初期処理

- 開くと、ログインした職員の権限を読む。職員の管理の権限が無ければ、ほかの API を呼ばず、「権限が無い」の状態にする。
- 権限があれば、事業所の全ての職員と、チーム、役職、部署の選択肢を読み、職員を読み終えるまで「読み込み中」の状態にする。
  - 読めなかったときは、「読み込みの失敗」の状態にする。
- URL の search params は読まない。

### 絞り込み

名前の検索と、チーム、役職、部署、状態の絞り込みは、読んだ全ての職員を画面で絞り込む。  
並び順も、画面で決める。  
絞り込むたびに API を呼び直さない。  
絞り込みの値は、詳細から一覧へ戻ると、開いた直後の値に戻る。

### 権限の確認

画面の判定は表示のためだけにする。  
予定の API も、職員の管理の権限が無い職員の変更のリクエストを 403 で拒む。

## 未決

- 職員の管理の権限を持たない職員が、同じ事業所の職員の連絡先を見る画面は無い。要るかは、プロフィールの画面を作るときに決める。
- 絞り込みの値を URL の search params に残すかは決めていない。詳細から戻ったときに絞り込みを保つ要望が出たら決める。
- チームの順は、チームの管理の画面（#368）で決める。モックは東チーム、西チーム、南チームの順で描く。
- チームの色の点の色は、#367 のチームの色のトークンで決める。モックの 3 色は仮である。
