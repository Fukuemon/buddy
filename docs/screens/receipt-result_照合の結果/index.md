# receipt-result 照合の結果

照合の担当が、照合の結果を区分ごとに見て、CSV で受け取る画面。  
照合の画面で照合が終わったときに開く。

| 項目 | 値 |
| --- | --- |
| URL | `/receipt/result` |
| 使う人 | 全ての職員 |
| 実装 | `apps/web/src/routes/receipt.result.tsx`、`apps/web/src/features/receipt/components/ReceiptResultContainer.tsx`、`apps/web/src/features/receipt/components/ReceiptResultView.tsx`、`apps/web/src/features/receipt/components/ReceiptResultTable.tsx` |

画面の項目と、web の型、OpenAPI の項目の対応は [API との対応](api.md) にある。

## 構成

ヘッダーの左に、メニューのボタンと buddy を置く。  
ヘッダーの右には、アカウントのボタンを置く。  
ヘッダーの下の左端には、画面の間を移るナビゲーションを置く。  
ナビゲーションに並べる項目と、権限で出し分ける項目は、[ナビゲーション](#ナビゲーション) にある。  
幅 768px 以上では、ナビゲーションを幅 224px の開いた形で始め、メニューのボタンで幅 80px のレールと切り替える。  
幅 768px 未満では、ナビゲーションをドロワーにし、閉じた状態で始める。  
ナビゲーションの印は、幅 768px 未満ではドロワーを開くと出る。

## メニュー

**概要**: ナビゲーションの形を切り替える。  
幅 768px 未満では、ナビゲーションのドロワーを開く。

**値のソース**: 3 本の横線のアイコン。  
読み上げる名前は「メニュー」。

**活性条件**: 常に活性

**表示条件**: 常に、ヘッダーの左端に出す。

**カタログ**: [SiteLayoutContainer の Mobile](https://buddy-docs.emon-apps.workers.dev/storybook/?path=/story/画面-common-sitelayoutcontainer--mobile)

### インタラクション

#### 1. 幅 768px 以上で押す

1. ナビゲーションを、開いた形からレールに切り替える。もう一度押すと開いた形に戻る。

#### 2. 幅 768px 未満で押す

1. 左端からナビゲーションのドロワーが開く。

## ナビゲーション

**概要**: 予定と照合の画面の間を移る。

**値のソース**: 見出し「予定」の下に、「カレンダー」「取り込み」「要確認」「連携」のアイコンと名前を並べる。  
見出し「照合」の下に、「照合」のアイコンと名前を置く。  
今の画面に面の色の印を付ける。  
この画面では「照合」に付ける。  
レールでは見出しを出さず、アイコンの下に名前を置き、「予定」と「照合」の間を区切り線で分ける。

**活性条件**: 常に活性

**表示条件**: 常に、ヘッダーの下の左端に出す。  
幅 768px 以上では、この画面では開いた形で始める。  
幅 768px 未満では、メニューのボタンで開いたドロワーの中に出す。  
「取り込み」「要確認」「連携」は、職員の管理の権限を持つ職員にだけ出す（[予定のカレンダー](../schedule-calendar_予定のカレンダー/index.md#ナビゲーション)）。  
モックは、職員の管理の権限を持たない職員の画面を描くので、「カレンダー」と「照合」だけを出す。

**カタログ**: [SiteNav の Staff](https://buddy-docs.emon-apps.workers.dev/storybook/?path=/story/画面-common-sitenav--staff)

### インタラクション

#### 1. 「カレンダー」を押す

1. 予定のカレンダーへ移る。照合の結果は消える。

#### 2. 「照合」を押す

1. 照合の画面へ移る。照合の結果は消える。

#### 3. 幅 768px 未満で、閉じるボタンか背景を押すか、Escape キーを押す

1. ナビゲーションのドロワーが閉じ、フォーカスがメニューのボタンに戻る。

## CSV をダウンロード

**概要**: 結果の表と同じ内容を CSV で保存する。

**値のソース**: 「CSV をダウンロード」

**活性条件**: 常に活性

**表示条件**: 照合の結果があるとき

**カタログ**: [ReceiptResultView の Default](https://buddy-docs.emon-apps.workers.dev/storybook/?path=/story/画面-receipt-receiptresultview--default)

### インタラクション

#### 1. 押す

1. 結果の CSV を保存させる。元の照合のアプリの CSV と、行と印を同じにする。
   - ファイル名は `照合結果_<対象の月>.csv`。予定の CSV で照合したときは `照合結果_<照合した日の YYYY-MM-DD>.csv`
   - 文字コードは BOM 付きの UTF-8 で、行は CRLF で区切る。Excel で開いても文字化けしないためである
   - 1 行目は列の名前。その後に区分ごとに、区分の名前と `---` の区切りの行、区分の行を並べる
   - 区切り、引用符、改行を含む値と、空白で始まる値は、引用符で囲む
   - 値と印は、結果の表と同じ文字列にする

## 照合に使わなかった予定

**概要**: Google カレンダーの予定のうち、照合に使わなかったものを示し、直すよう案内する。

**値のソース**: 「照合に使わなかった予定（<件数> 件）」、「次の Google カレンダーの予定は、照合に使いませんでした。予定を直して、もう一度照合してください。」と、予定の開始の日時と理由の一覧。  
予定のタイトルは出さない。  
理由は、照合の API が返した理由ごとに次の文にする。照合の API の文は出さない。

| 理由 | 文 |
| --- | --- |
| タイトルを読めない | 「タイトルが「【サービス内容】利用者名」の形になっていません。」 |
| 日時を読めない | 「開始か終了の日時を読めません。」 |
| 日付をまたぐ | 「日付をまたいでいます。」 |
| 列の値の誤り | 「「主訪問者」が空です。」の形で、列の名前と、照合の画面の誤りの一覧と同じ誤りの文を入れる |
| そのほか | 「予定を読めません。」 |

**活性条件**: 常に活性

**表示条件**: 照合に使わなかった予定が 1 件以上あるとき

**カタログ**: [ReceiptResultView の Default](https://buddy-docs.emon-apps.workers.dev/storybook/?path=/story/画面-receipt-receiptresultview--default)

## 結果の表

**概要**: 予定と実績の対を、区分ごとに並べる。  
表は横に送れる。  
送っても、どの行かを示す訪問日と利用者名の 2 列は左端に残る。  
PC の幅で表が画面に収まり、横に送らないときの列の幅と並びは、2 列を残さないときと同じにする。  
幅 768px 未満では、利用者名の列の幅を 8rem にし、長い名前は折り返す。  
残す 2 列が、送る列を覆わないためである。

**値のソース**: 列は「訪問日」「利用者名」「主訪問者」「サービス内容_予定」「開始時間_予定」「終了時間_予定」「提供時間_予定」「サービス内容_実績」「開始時間_実績」「終了時間_実績」「提供時間_実績」「加算」の順。  
列の名前と並びは、元の照合のアプリの CSV に合わせる。

- 片側の無い行の、無い側の値と、空の提供時間は「データなし」にする。
  - 実績の無い行は、加算も「データなし」にする。
  - 実績に加算が無ければ、加算は空欄にする。
- 不整合の行
  - 開始時間、サービス内容、提供時間の一致のどれかが合わなければ、予定と実績の両方に「 ❌」を付ける。
  - 終了時間と提供時間が許容範囲を外れたら、その側に「 ❌ (最小~最大)」を付ける。範囲の無いサービス内容は「 ❌」だけにする。
  - 加算が規則に合わなければ、加算に「 ※」を付ける。規則に合うのは、加算が「通常」の 1 つだけのときと、予定の開始時間の時間帯の加算（早朝、夜間、深夜）の 1 つだけのときである。緊急時の訪問の加算を含むときは合わない。
- 整合の行
  - 提供時間が違えば、両側の提供時間に「 ※ (最小~最大)」を付ける。
  - 終了時間が違えば、両側の終了時間に「 ※」を付ける。
- 「❌」の付いた値は危険の背景、「※」の付いた値は注意の背景の色にする。

**活性条件**: 常に活性

**表示条件**: 照合の結果があるとき

**カタログ**: [ReceiptResultView の Default](https://buddy-docs.emon-apps.workers.dev/storybook/?path=/story/画面-receipt-receiptresultview--default)

## 全体動作

### 初期処理

- 結果は、照合の画面が照合を終えたときにブラウザの中に置く。
- この画面はサーバーで描画せず、ブラウザの中に置かれた結果を読む。
- フォーカスは `body` にある。
- URL の search params は読まない。

## 未決

- 区分で行を絞る操作を足すか。
  - 元の照合のアプリには無い。
- 結果の表が数千行になったときに、表示を分けるか。
