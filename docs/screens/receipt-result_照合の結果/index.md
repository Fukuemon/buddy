# receipt-result 照合の結果

照合の担当が、照合の結果を区分ごとに見て、CSV で受け取る画面。  
照合の画面で照合が終わったときに開く。

| 項目 | 値 |
| --- | --- |
| URL | `/receipt/result` |
| 使う人 | 照合の権限を持つ職員。デフォルトでは、マネージャーと事務の役職の職員である |
| 実装 | `apps/web/src/routes/receipt.result.tsx`、`apps/web/src/features/receipt/components/ReceiptResultContainer.tsx` |

画面の項目と、web の型、OpenAPI の項目の対応は [API との対応](api.md) にある。

画面を描くコンポーネントのうち、実装の行のほかのものは次のとおり。

- `apps/web/src/features/receipt/components/ReceiptResultView.tsx`
- `apps/web/src/features/receipt/components/ReceiptResultTable.tsx`
- `apps/web/src/features/receipt/components/ReceiptResultEmpty.tsx`

## 構成

ヘッダーの左に、メニューのボタンと buddy を置く。  
ヘッダーの右には、アカウントのボタンを置く。  
ヘッダーの下の左端には、画面の間を移るナビゲーションを置く。  
ナビゲーションに並べる項目と、権限で出し分ける項目は、[ナビゲーション](#ナビゲーション) にある。  
幅 768px 以上では、ナビゲーションを幅 224px の開いた形で始め、メニューのボタンで幅 80px のレールと切り替える。  
幅 768px 未満では、ナビゲーションをドロワーにし、閉じた状態で始める。  
ナビゲーションの印は、幅 768px 未満ではドロワーを開くと出る。

## メニュー

**概要**: ナビゲーションの形を切り替えるボタン。  
ヘッダーの左端に出す。  
幅 768px 未満では、ナビゲーションのドロワーを開く。

**値のソース**: 3 本の横線のアイコン。  
読み上げる名前は「メニュー」。

**カタログ**: [SiteLayoutContainer の Mobile](https://buddy-docs.emon-apps.workers.dev/storybook/?path=/story/画面-common-sitelayoutcontainer--mobile)

**操作**:

- 幅 768px 以上で押すと、ナビゲーションを、開いた形からレールに切り替える。
  - もう一度押すと開いた形に戻る。
- 幅 768px 未満で押すと、左端からナビゲーションのドロワーが開く。

## ナビゲーション

**概要**: 予定、照合、職員、利用者の画面の間を移る領域。  
ヘッダーの下の左端に出す。  
幅 768px 以上では、この画面では開いた形で始める。  
幅 768px 未満では、メニューのボタンで開いたドロワーの中に出す。

**値のソース**: 見出しと項目、出す職員は、[職員の一覧のナビゲーション](../staff-list_職員の一覧/index.md#ナビゲーション) にある。  
この画面では「照合」に今の画面の印を付ける。  
モックは、職員の管理の権限を持たず、照合の権限を持つ職員の画面を描くので、「カレンダー」と「照合」だけを出す。

**カタログ**: [SiteNav の Staff](https://buddy-docs.emon-apps.workers.dev/storybook/?path=/story/画面-common-sitenav--staff)

**操作**:

- 「カレンダー」を押すと、予定のカレンダーへ移る。
  - 照合の結果は消える。
- 「照合」を押すと、照合の画面へ移る。
  - 照合の結果は消える。
- 幅 768px 未満で、閉じるボタンか覆いを押すか、Escape キーを押すと、ナビゲーションのドロワーが閉じ、フォーカスがメニューのボタンに戻る。

## アカウント

**概要**: ログインしている職員を示し、名前、自分の情報、ログアウトを入れたメニューを開くボタン。  
ヘッダーの右端に出す。

**値のソース**: 職員の名前の先頭の 1 文字を入れた丸と、職員の名前を並べたボタン。  
幅 768px 未満では、丸だけを出す。  
読み上げる名前は「アカウント（<職員の名前>）」にする。  
幅 768px 未満で名前を隠しても、読み上げる名前は変えない。

**カタログ**: [ViewerMenu の Default](https://buddy-docs.emon-apps.workers.dev/storybook/?path=/story/画面-common-viewermenu--default)

**操作**:

- 押すと、職員の名前、自分の情報のリンク、ログアウトのボタンを入れたメニューを、ボタンの下に開く。
  - もう一度押すか、メニューの外を押すか、Escape キーを押すと閉じる。
- メニューの「自分の情報」を押すと、メニューを閉じ、[自分の情報](../account-profile_自分の情報/index.md) へ移る。

## CSV をダウンロード

**概要**: 結果の表の行を CSV で保存するボタン。  
別のファイルで照合するの右に出す。

**値のソース**: 「CSV をダウンロード」

**カタログ**: [ReceiptResultView の Default](https://buddy-docs.emon-apps.workers.dev/storybook/?path=/story/画面-receipt-receiptresultview--default)

**操作**: 押すと、結果の CSV を保存させる。

1. 1 行に 1 つの対を書く。照合の担当が Excel で区分を絞り込み、値のまま並べ替えられるためである。
2. ファイル名は `照合結果_<対象の月>.csv` にする。
   - 予定の CSV で照合したときは `照合結果_<照合した日の YYYY-MM-DD>.csv` にする。
3. 文字コードは BOM 付きの UTF-8 で、行は CRLF で区切る。
   - Excel で開いても文字化けしないためである。
4. 1 行目は列の名前にし、その後に結果の行を、区分、訪問日、開始時間、利用者名、主訪問者の順に並べる。区切りの行は置かない。
5. 区切り、引用符、改行を含む値と、空白で始まる値は、引用符で囲む。
6. 列は「区分」「訪問日」「利用者名」「主訪問者」「サービス内容_予定」「開始時間_予定」「終了時間_予定」「提供時間_予定」「サービス内容_実績」「開始時間_実績」「終了時間_実績」「提供時間_実績」「加算」「確認すること」の順にする。
7. 区分の値は、区分の見出しの名前（「不整合データ」「予定のみ」「実績のみ」「整合データ」）にする。
8. 値に印を混ぜない。片側の無い行の無い側のセルと、空の提供時間は空にする。実績の無い行は、加算も空にする。
9. 確認することの値は、[確認すること](#確認すること) の文に、重さを「不一致: 」「注意: 」と前に付け、「 / 」でつなぐ。
   - 例: 「不一致: 開始時間が予定と違う / 注意: 提供時間が予定と違う」
   - 予定のみと実績のみの行は「実績が無い」「予定が無い」にする。
   - 文の無い整合の行は空にする。
10. 結果の表の表示を「確認が要る行」にしていても、全ての行を書く。

## 照合に使わなかった予定

**概要**: Google カレンダーの予定のうち、照合に使わなかったものを示し、直すよう案内するメッセージ。  
ページのタイトルと結果の表の間に出す。

**値のソース**: 「照合に使わなかった予定（<件数> 件）」、「次の Google カレンダーの予定は、照合に使いませんでした。予定を直して、もう一度照合してください。」と、予定の開始の日時と理由の一覧。  
開始の日時は `2024年4月5日（金） 10:00` の形で出す。  
予定のタイトルは出さない。  
理由は、理由の種類ごとに次の文にする。  
照合の仕組みが内部で作る文は出さない。

| 理由 | 文 |
| --- | --- |
| タイトルを読めない | 「タイトルが「【サービス内容】利用者名」の形になっていません。」 |
| 日時を読めない | 「開始か終了の日時を読めません。」 |
| 2 日以上にわたるか、24 時間以上 | 「2 日以上にわたるか、24 時間以上の予定です。」 |
| 列の値の誤り | 「「主訪問者」が空です。」の形で、列の名前と、照合の画面の誤りの一覧と同じ誤りの文を入れる |
| そのほか | 「予定を読めません。」 |

**カタログ**: [ReceiptResultView の Default](https://buddy-docs.emon-apps.workers.dev/storybook/?path=/story/画面-receipt-receiptresultview--default)

## 表示する行

**概要**: 結果の表に出す行を、確認が要る行と全ての行で切り替えるラジオボタンの組。  
印の意味の上に出す。

**値のソース**: 「確認が要る行（<件数> 件）」と「全ての行（<件数> 件）」。  
確認が要る行は、不整合、予定のみ、実績のみの区分の行と、注意の印のある整合の行である。  
注意の印の無い整合の行は、全ての行にだけ入る。  
表示している行の数は、読み上げだけの次の文言で伝え、切り替えると読み上げる。

| 文言 |
| --- |
| 「<件数> 件の行を表示しています。」 |

**カタログ**: [ReceiptResultView の WithCleanMatch](https://buddy-docs.emon-apps.workers.dev/storybook/?path=/story/画面-receipt-receiptresultview--with-clean-match)

**操作**:

- 「全ての行」を押すと、注意の印の無い整合の行と、行の無い区分の見出しの行も表に出す。
- 「確認が要る行」を押すと、確認が要る行だけを表に出し、行の無い区分の見出しの行を出さない。
  - 確認が要る行が無いときは、「確認が要る行が無い」の状態にする。
- 選択肢の間は、← と → で移る。
- 切り替えても、CSV をダウンロードで保存する行は変わらない。

## 結果の表

**概要**: 予定と実績の対を、区分ごとに並べる表。  
表示する行で選んだ行だけを並べる。  
1 つの対を 1 行の結果の行にする。  
表は横に送れる。  
送っても、どの行かを示す訪問日と利用者名の 2 列は左端に残る。  
PC の幅で表が画面に収まり、横に送らないときの列の幅と並びは、2 列を残さないときと同じにする。  
幅 768px 未満では、利用者名の列の幅を 8rem にし、長い名前は折り返す。  
残す 2 列が、送る列を覆わないためである。

**値のソース**: 列は「訪問日」「利用者名」「主訪問者」「確認すること」「サービス内容_予定」「開始時間_予定」「終了時間_予定」「提供時間_予定」「サービス内容_実績」「開始時間_実績」「終了時間_実績」「提供時間_実績」「加算」の順。  
「確認すること」のほかの列の名前は、元の照合のアプリの CSV に合わせる。  
訪問日は`2024年4月1日（月）`の形で出す。ダウンロードする CSV の訪問日は変えない。

- 片側の無い行の、無い側のセルは空にする。
  - 「予定のみ」と「実績のみ」の、行の区分の見出しが、片側が無いことを示すためである。
  - 読み上げでは、空にしたセルを「データなし」と読ませる。
  - 実績の無い行は、加算も空にする。
  - 実績に加算が無ければ、加算は空欄にする。
- 空の提供時間は「データなし」にする。
- 予定と実績の値と加算のセルには、次の 2 つの重さの印を付ける。
  - 不一致: 規則に合わない値。丸の中に「!」のアイコンと、危険の面の色
  - 注意: 規則に合うが、予定と実績で違う値。三角のアイコンと、注意の面の色
- 印は、値の前にアイコンを置き、セルの面の色を変える。
  - 読み上げでは、アイコンを読ませず、値の後ろに「（不一致）」か「（注意）」と読ませる。
  - 1 つのセルが不一致と注意の両方に当たるときは、不一致の印だけを付ける。
- 印を付けるセルは、次のとおり。

  | 判定 | 印を付けるセル | 重さ |
  | --- | --- | --- |
  | 開始時間が予定と実績で違う | 両側の開始時間 | 不一致 |
  | サービス内容が対応しない | 両側のサービス内容 | 不一致 |
  | 開始から終了までの分が許容範囲を外れる | その側の終了時間 | 不一致 |
  | 提供時間が許容範囲を外れるか、空 | その側の提供時間 | 不一致 |
  | 加算が規則に合わない | 加算 | 不一致 |
  | 提供時間が予定と実績で違う | 両側の提供時間 | 注意 |
  | 終了時間が予定と実績で違う | 両側の終了時間 | 注意 |

  - 範囲の無いサービス内容は、終了時間と提供時間を不一致にする。
  - 加算が規則に合うのは、加算が「通常」の 1 つだけのときと、予定の開始時間の時間帯の加算の 1 つだけのときである。
    - 時間帯の加算は、早朝、夜間、深夜を指す。
    - 緊急時の訪問の加算を含むときは合わない。
  - 注意の 2 つは、行の区分（不整合、整合）によらず付ける。
- 許容範囲を外れた終了時間と提供時間と、注意の提供時間のセルには、値の下に「範囲 20〜29 分」の形で許容範囲を出す。
  - 範囲の無いサービス内容は、範囲を出さない。

**カタログ**: [ReceiptResultView の Default](https://buddy-docs.emon-apps.workers.dev/storybook/?path=/story/画面-receipt-receiptresultview--default)

## 印の意味

結果の表のすぐ上に出す。

**値のソース**: 丸の中に「!」のアイコンと「不一致: 規則に合わない」、三角のアイコンと「注意: 範囲の中だが予定と違う」を横に並べる。

## 確認すること

**概要**: 結果の行ごとに、何を確認すればよいかを文で示すカラム。  
主訪問者の右に置く。  
左の 3 列の直後に置くのは、横に送らずに理由が見え、理由を読んでから右の値を見るためである。

**値のソース**: 行の判定の文を、1 つずつ並べる。  
不一致と注意の文の前には、セルの印と同じアイコンを置く。  
文は、不一致を次の表の上から順に並べ、その後に注意を並べる。  
同じ文は 1 つだけ出す。

| 判定 | 重さ | 文 |
| --- | --- | --- |
| 開始時間が予定と実績で違う | 不一致 | 「開始時間が予定と違う」 |
| サービス内容が対応しない | 不一致 | 「サービス内容が予定と違う」 |
| 開始から終了までの分が許容範囲を外れる | 不一致 | 「実績の終了時間が範囲（20〜29 分）の外」の形。予定の側は「予定の」で始める |
| 提供時間が許容範囲を外れる | 不一致 | 「実績の提供時間 35 分が範囲（20〜29 分）の外」の形。予定の側は「予定の」で始める |
| 範囲の無いサービス内容 | 不一致 | 「実績のサービス内容に許容範囲が無い」。予定の側は「予定の」で始める |
| 提供時間が空 | 不一致 | 「実績の提供時間が空」。予定の側は「予定の」で始める |
| 加算が規則に合わない | 不一致 | 「加算が規則に合わない」 |
| 提供時間が予定と実績で違う | 注意 | 「提供時間が予定と違う」 |
| 終了時間が予定と実績で違う | 注意 | 「終了時間が予定と違う」 |
| 予定のみの行 | なし | 「実績が無い」 |
| 実績のみの行 | なし | 「予定が無い」 |

- 予定と実績が全て合う整合の行は、空にする。

**カタログ**: [ReceiptResultView の Default](https://buddy-docs.emon-apps.workers.dev/storybook/?path=/story/画面-receipt-receiptresultview--default)

## 全体動作

### 初期処理

- 照合の画面で最後に終えた照合の結果を出す。
  - 結果が無いときは、「結果が無い」の状態にする。
  - 結果の渡し方は、[レセプトの照合の Design Doc の画面の照合の流れ](https://github.com/Fukuemon/buddy/blob/develop/services/receipt/DesignDoc.md#画面の照合の流れ) にある。
- 表示する行は「確認が要る行」で始める。
- フォーカスは `body` にある。
- URL の search params は読まない。
  - 表示する行の選択も URL に残さない。結果は画面を読み直すと消えるので、URL に残しても戻せないためである。

### 権限の確認

- 照合の権限を持たない職員には、「権限が無い」の状態を出す。
- ログインした職員の権限は、画面を開いたときに読み、開いた後も次のときに読み直す。
  - 前に読んでから 5 分が過ぎた後に、職員がほかのウィンドウからこの画面に戻ったとき
  - 前に読んでから 5 分が過ぎた後に、職員が画面を移ったとき
- 読み直して照合の権限が無くなっていたら、画面を読み込み直さなくても、開いている結果の代わりに「権限が無い」の状態を出す。
  - 権限を外されてから読み直すまでの間は、開いている結果を見られ、CSV をダウンロードできる。
- 読み直す時機は、[ADR-0008 の Viewer を取り直す時機](../../adr/0008-web-permission-checks.md#viewer-を取り直す時機) で決めた。
