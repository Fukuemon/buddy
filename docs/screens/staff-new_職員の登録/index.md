# staff-new 職員の登録

職員の管理の権限を持つ職員が、新しい職員をメールアドレス、所属、役職で登録する画面。  
職員の一覧の上にモーダルで重ねて出す。  
登録した職員は、そのメールアドレスで最初にログインしたときから buddy を使える。

| 項目 | 値 |
| --- | --- |
| URL | `/staff/new`。`/staff` の子 |
| 使う人 | 職員の管理の権限を持つ職員（デフォルトはマネージャー） |
| 実装 | 未実装 |

画面の項目と、web の型、OpenAPI の項目の対応は [API との対応](api.md) にある。

## 構成

[職員の一覧](../staff-list_職員の一覧/index.md) の上に覆いを重ね、その上にダイアログを出す。  
ダイアログの上端にタイトルと閉じるボタンを、本文に入力の欄を、下端にキャンセルと登録のボタンを置く。  
部署、チーム、役職は、幅 768px 以上では横に並べ、幅 768px 未満では縦に並べる。

## 覆い

**概要**: 職員の一覧の上に重ね、ダイアログの外を押せないようにする。

**値のソース**: 半透明の面

**活性条件**: 常に活性

**表示条件**: ダイアログを開いている間

### インタラクション

#### 1. 押す

1. 何も登録せずにダイアログを閉じ、職員の一覧に戻る。

## ダイアログのタイトル

**概要**: 何のダイアログかを示す。

**値のソース**: 「職員を登録」

**活性条件**: 常に活性

**表示条件**: 常に表示

## 閉じる

**概要**: 登録せずにダイアログを閉じる。

**値のソース**: × のアイコン。読み上げる名前は「閉じる」。

**活性条件**: 常に活性

**表示条件**: 常に、タイトルの右に出す。

### インタラクション

#### 1. 押すか、Escape キーを押す

1. 何も登録せずにダイアログを閉じ、職員の一覧に戻る。

## 名前

**概要**: 職員の名前を入れる。  
予定のカレンダーの職員の列と、照合の主訪問者に出る名前である。

**値のソース**: 見出し「名前」。  
最初は空。  
128 文字まで入れられる。

**活性条件**: 常に活性

**表示条件**: 常に表示

## メールアドレス

**概要**: 職員が事業所の IdP でログインするときのメールアドレスを入れる。

**値のソース**: 見出し「メールアドレス」と、欄の下の次の文言。

| 文言 |
| --- |
| 「職員が事業所の IdP でログインするときのメールアドレス。登録した後は変えられません。」 |

最初は空。  
大文字と小文字は区別せず、小文字にそろえて保存する。

**活性条件**: 常に活性

**表示条件**: 常に表示

## 電話番号

**概要**: 職員の電話番号を入れる。省いてよい。

**値のソース**: 見出し「電話番号（任意）」。  
最初は空。  
数字で 11 桁まで入れられる。

**活性条件**: 常に活性

**表示条件**: 常に表示

## 部署

**概要**: 職員の部署を選ぶ。

**値のソース**: 見出し「部署」と、事業所の部署の名前の選択肢。  
最初は名前の順の最初の部署を選ぶ。

**活性条件**: 部署の選択肢を読み終えたとき

**表示条件**: 常に表示

## チーム

**概要**: 職員の所属のチームを選ぶ。  
役職のデフォルトの権限のうち、チームを対象にする権限は、このチームを指す。

**値のソース**: 見出し「チーム」と、事業所のチームの名前の選択肢。  
最初は名前の順の最初のチームを選ぶ。

**活性条件**: チームの選択肢を読み終えたとき

**表示条件**: 常に表示

## 役職

**概要**: 職員の役職を選ぶ。

**値のソース**: 見出し「役職」と、事業所の役職の名前の選択肢。  
最初は名前の順の最初の役職を選ぶ。

**活性条件**: 役職の選択肢を読み終えたとき

**表示条件**: 常に表示

## 登録の説明

**概要**: 登録すると何が起きるかを示す。

**値のソース**: 次の文言。

| 文言 |
| --- |
| 「登録すると、役職のデフォルトの権限が付きます。職員は、このメールアドレスで最初にログインしたときから使えます。」 |

**活性条件**: 常に活性

**表示条件**: 常に、入力の欄の下に出す。

## 入力の誤り

**概要**: 登録できない入力を、欄ごとに示す。  
読み上げでは警告として扱う。

**値のソース**: 欄ごとに次の文言。

| 欄 | 条件 | 文言 |
| --- | --- | --- |
| 名前 | 空 | 「名前を入れてください」 |
| メールアドレス | 空か、メールアドレスの形でない | 「メールアドレスの形で入れてください」 |
| 電話番号 | 数字と先頭の + 以外を含むか、数字が 11 桁を超える | 「電話番号は数字で 11 桁まで入れてください」 |

**活性条件**: 常に活性

**表示条件**: 登録を押し、入力が誤っていたとき。  
誤った欄を直すと、その欄の文を消す。

## 登録の失敗の文

**概要**: 予定の API が登録を拒んだ理由を示す。  
読み上げでは警告として扱う。

**値のソース**: 理由ごとに次の文言。

| 理由 | 文言 |
| --- | --- |
| 同じメールアドレスの職員が、この事業所かほかの事業所にいる | 「このメールアドレスの職員は、すでに登録されています。」 |
| 部署、チーム、役職が無くなった | 「部署、チーム、役職のどれかが見つかりません。開き直してから、選び直してください。」 |
| 職員の管理の権限を外された | 「この操作をする権限がありません。」 |
| 予定の API に届かないか、ほかのエラー | 「登録できませんでした。時間をおいて、もう一度登録してください。」 |

**活性条件**: 常に活性

**表示条件**: 登録を押し、予定の API が拒んだか、届かなかったとき。  
ダイアログの下端の、ボタンの左に出す。

## キャンセル

**概要**: 登録せずにダイアログを閉じる。

**値のソース**: 「キャンセル」

**活性条件**: 常に活性

**表示条件**: 常に表示

### インタラクション

#### 1. 押す

1. 何も登録せずにダイアログを閉じ、職員の一覧に戻る。

## 登録

**概要**: 入れた値で職員を登録する。

**値のソース**: 次の文言。

| 状態 | 文言 |
| --- | --- |
| 送る前 | 「登録」 |
| 送っている間 | 「登録しています」 |

**活性条件**: 送っていない間

**表示条件**: 常に表示

### インタラクション

#### 1. 押す

1. 入力が誤っていれば、送らずに「入力の誤り」の状態にする。
2. 誤りが無ければ、職員を登録する。
3. 登録できたら、ダイアログを閉じ、登録した職員の [職員の詳細](../staff-detail_職員の詳細/index.md) へ移る。役職のデフォルトの権限が付いたことを、詳細の権限の一覧で確認できる。
4. 登録できなかったら、ダイアログを閉じずに「登録の失敗」の状態にする。入れた値は残す。

## 全体動作

### 初期処理

- 開くと、ログインした職員の権限を読む。職員の管理の権限が無ければ、ダイアログを出さず、[職員の一覧](../staff-list_職員の一覧/index.md) の「権限が無い」の状態にする。
- 権限があれば、職員の一覧の上にダイアログを出し、部署、チーム、役職の選択肢を読む。
  - 選択肢を読めなかったときは、選択の欄を押せないままにし、登録の失敗の文の位置に「部署、チーム、役職を読み込めませんでした。閉じてから、開き直してください。」を出す。
- フォーカスは名前の欄に置く。

## 未決

- 職員の性別は持たない。PRD の Open Questions のとおり、担当の候補を性別で絞る機能を作るときに、項目を足すかを決め直す。
- 役職のデフォルトの権限は仮決定である。PRD の Open Questions のとおり、事業所で使い始めるまでに事業所の責任者に確認する。この画面は、確認の結果によらず、役職を選ぶだけにする。
- 部署とチームを、この画面で作るかは決めていない。予定の API はチームを作る API を持つが、部署を作る API は持たない。
