# schedule-new 予定の作成

職員が、通常の予定か訪問の予定を、1 件か、毎週か毎月の繰り返しで作る画面。  
予定のカレンダーの上にモーダルで重ねて出す。  
予定を作ると、作った予定の日のカレンダーに戻る。

| 項目 | 値 |
| --- | --- |
| URL | `/schedule/new`。`/schedule` の子で、カレンダーの search params を引き継ぐ |
| 使う人 | 誰かの予定を編集できる職員。主訪問者と予定者に選べる職員は、予定の権限で決まる |
| 実装 | `apps/web/src/routes/schedule.new.tsx`、`apps/web/src/features/schedule/components/ScheduleCreateModalContainer.tsx` |

画面の項目と、web の型、OpenAPI の項目の対応は [API との対応](api.md) にある。

画面を描くコンポーネントのうち、実装の行のほかのものは次のとおり。

- `apps/web/src/features/schedule/components/ScheduleFormModal.tsx`
- `apps/web/src/features/schedule/components/ScheduleForm.tsx`

- `apps/web/src/features/schedule/components/ScheduleDateTimeEdit.tsx`

## 構成

モーダルの上端には、左にタイトル、右に種類のタブを置く。  
フォームを出す状態では、右上に閉じるボタン（×）を置かず、下端のキャンセルで閉じる。  
左に項目の一覧、右に選んだ項目の入力を置く。  
下端の右には、キャンセルと作成のボタンをこの順に置く。  
読み込み中と読み込みの失敗では、種類のタブと下端を出さず、右上に閉じるボタンを置き、閉じるボタンだけで閉じる。  
予定を Google カレンダーで管理する事業所でも、予定を buddy で管理する事業所と同じフォームを出し、作った予定を Google カレンダーにも書く。  
幅 768px 未満では、モーダルを画面いっぱいに出し、項目の一覧の下に入力を置く。  
フォームを出す状態では、下端を画面の下に固定し、常に出す。

=== "作成の失敗"

    予定を作れなかったとき。  
    予定を作れなかった理由は、次の 5 つ。

    - 画面を開いた後に、予定を作る権限を外された。
    - 入力が作成の規則に合わない。
      - 主訪問者か予定者が、画面を開いた後に休職か退職か、訪問しない職員になったときを含む。
    - 画面を開いた後に、事業所が予定を Google カレンダーで管理するようになった。
    - 予定を Google カレンダーで管理する事業所で、Google カレンダーに書けなかった。
      - 書けたかを確認できなかったときは、「Google カレンダーに書けたかを確認できなかった」の状態になる。
    - つながらない。

    作成の失敗の文は、職員が次にできることで分ける。  
    文は、[作成の失敗の文](#作成の失敗の文) にある。  
    作成の規則に合わない項目は、項目の一覧に示さない。  
    ログインが切れていたときは、この状態にならず、ログインの画面へ移るまで「送信中」の状態が続く。  
    モックは、つながらなかったときを描く。

    失敗の要因は、[API との対応の状態と失敗の要因](api.md#状態と失敗の要因) にある。  
    作成の流れは、[予定の管理の Design Doc の予定の画面の読み込みと保存](https://github.com/Fukuemon/buddy/blob/develop/services/schedule/DesignDoc.md#予定の画面の読み込みと保存) にある。

## 項目の一覧

**概要**: フォームの項目と今の値を要約して並べるボタンの一覧。  
押した項目の入力を右に出す。  
右に出している項目は枠を太くする。

**値のソース**: 項目の名前と、今の値の要約。  
項目は、種類の列の種類のときだけ出す。

| 項目 | 種類 | 名前 | 値の要約 |
| --- | --- | --- | --- |
| タイトル | 通常 | 「タイトル」 | 入力したタイトル。空なら何も出さない |
| 日時 | 訪問 | 「訪問日時」 | 「2024-04-01 09:00 - 09:29（29 分、訪看I2）」の形。終了が翌日なら「2024-04-01 23:00 - 翌 00:30（90 分、医）」の形にする。提供時間が数でなければ、終了時間と提供時間を「-」にする |
| 日時 | 通常 | 「予定日時」 | 「2024-04-01 09:00 - 10:00」の形。終了は翌日を選んでいれば「2024-04-01 22:00 - 翌 01:00」の形にする |
| 繰り返し | 訪問、通常 | 「繰り返し」 | 「繰り返しの予定にする」を選んでいなければ「繰り返さない」。選んでいれば、「毎週 月曜日」「毎月 16 日」「毎月 第 3 月曜日」の形の規則の文。終了日があれば `毎週 月曜日（2027年3月31日まで）` の形で後ろに付ける |
| 利用者 | 訪問 | 「利用者」 | 選んだ利用者の名前。選んでいなければ、薄い色の「選んでください」 |
| 主訪問者 | 訪問 | 「主訪問者」 | 選んだ職員の名前。選んでいなければ、薄い色の「選んでください」 |
| 予定者 | 通常 | 「予定者」 | 選んだ職員の名前。選んでいなければ、薄い色の「選んでください」 |
| 訪問の区分 | 訪問 | 「訪問の区分」 | 選んだ区分を「、」でつなぐ。空なら「通常」 |
| メモ | 訪問、通常 | 「メモ」 | 入力したメモ。空なら何も出さない |

- 値を入れていない項目は、要約を空にする。
  - 利用者、主訪問者、予定者は、薄い色で「選んでください」と出す。
  - 読み上げでは、項目の名前と「未入力」を読ませる。
- 入力エラーがある項目は、枠を赤く太くし、要約の下にエラーの文を出す。
  - 日付と時間とサービスコードのエラーは、日時の 1 つの枠にまとめ、日付、開始時間、終了時間、サービスコード、提供時間の順で最初の 1 つの文を出す。
  - 繰り返しのエラーは、「繰り返しの予定にする」を選んでいるときだけ出し、繰り返しの 1 つの枠にまとめ、繰り返し、終了日の順で最初の 1 つの文を出す。
- 日時、タイトル、繰り返しの入力では、右の入力の欄ごとに、その欄のエラーの文を欄の下に出す。
  - 日付が繰り返しの回に当たらないことの文は、[繰り返し](#繰り返し) の下に出す。
  - 終了日の文は、終了日の欄の下に出す。
  - 利用者、主訪問者、予定者は、項目の一覧の枠と文だけで示す。
- 作成を押した後、検証に通らない項目にエラーの文を出す。
  - 押した後は、入力を変えるたびに検証し直す。
- エラーの文は、項目と条件ごとに次のとおり。

| 項目 | 条件 | 文 |
| --- | --- | --- |
| タイトル（通常） | 空白だけか空 | 「タイトルを入力してください」 |
| 日付 | 日付として読めない | 「日付を入力してください」 |
| 開始時間 | `HH:mm` でない | 「開始時間を入力してください」 |
| 終了時間（通常） | `HH:mm` でない | 「終了時間を入力してください」 |
| 終了時間（通常） | 終了は翌日を選ばず、開始時間より後でない | 「終了時間は開始時間より後にしてください」 |
| 終了時間（通常） | 終了は翌日を選び、開始時間より前でない。24 時間以上になる | 「翌日に終わる予定は、終了時間を開始時間より前にしてください」 |
| 利用者（訪問） | 選んでいない | 「利用者を選んでください」 |
| 主訪問者（訪問） | 選んでいない | 「主訪問者を選んでください」 |
| 予定者（通常） | 選んでいない | 「予定者を選んでください」 |
| サービスコード（訪問） | 選んでいないか、事業所のサービスコードの一覧に無い | 「サービスコードを選んでください」 |
| 提供時間（訪問） | 数でないか、整数でない | 「提供時間を入力してください」 |
| 提供時間（訪問） | サービスコードの提供時間の範囲の外 | 「訪看I2 の提供時間は 20 分から 29 分です」の形。サービスコード、下限、上限を入れる。下限と上限は、事業所のサービスコードの一覧の値 |
| 繰り返し | 日付が繰り返しの回に当たらない。「カスタム…」で日付の曜日でない曜日を選んだときなど | 「日付が繰り返しの回に当たりません。日付か繰り返しを変えてください」 |
| 繰り返し | 終了日を「あり」にして、日付として読めない | 「終了日を入力してください」 |
| 繰り返し | 終了日が日付より前 | 「終了日は日付以降にしてください」 |

- サービスコードのエラーは、事業所のサービスコードの一覧が空のときに出る。
  - サービスコードを選べないので、訪問の予定は作れない。
- タイトルとメモの長さは、画面で確認しない。
  - タイトルは 255 文字、メモは 2000 文字まで保存できる。
  - 超えると作成の失敗の文が出る。

**カタログ**: [ScheduleFormModal の Visit](https://buddy-docs.emon-apps.workers.dev/storybook/?path=/story/画面-schedule-scheduleformmodal--visit)

**操作**: 項目を押すと、右の入力をその項目に替える。

1. URL は変わらない。

## 日付

**概要**: 予定の日を入れるテキストボックス。

**値のソース**: ラベルは、訪問では「訪問日」、通常では「日付」。  
初期値は URL の `start` の日。

**カタログ**: [ScheduleFormModal の Visit](https://buddy-docs.emon-apps.workers.dev/storybook/?path=/story/画面-schedule-scheduleformmodal--visit)

**操作**: 変えると、[繰り返し](#繰り返し) と終了日の欄の値を、新しい日付に合わせる。

1. 繰り返しが、変える前の日付から作る選択肢のどれかと同じなら、新しい日付から作る同じ選択肢にする。
   - 選択肢は、毎週の曜日、毎月の日、毎月の第何週の曜日の 3 つである。
   - 例えば、「毎週 月曜日」のまま日付を 2024-04-02（火）に変えると、「毎週 火曜日」になる。
   - 「カスタム…」で選んだ、選択肢と違う繰り返しは変えない。
2. 繰り返しの終了日が「なし」なら、「あり」にしたときの終了日の欄の初期の日を、新しい日付にそろえる。
   - 終了日が「あり」なら、終了日は変えない。

**概要**: 予定の開始の時刻を入れるテキストボックス。

**値のソース**: 「開始時間」。

## 提供時間

**概要**: 訪問の長さを分で入れるテキストボックス。  
種類が訪問のときだけ出す。

**値のソース**: 「提供時間（分）」。  
初期値は、初期のサービスコードの提供時間の範囲の上限。  
例えば、訪看I2 の範囲が 20 分から 29 分なら 29。  
利用者を選んでサービスコードが替わると、替わったコードの提供時間の範囲の上限にする。

**カタログ**: [ScheduleFormModal の Visit](https://buddy-docs.emon-apps.workers.dev/storybook/?path=/story/画面-schedule-scheduleformmodal--visit)

**操作**: 変えると、[終了時間](#終了時間) を、開始時間に提供時間を足した時刻にする。

## 終了時間

**概要**: 予定の終わりの時刻。  
通常の予定では入れるテキストボックスで、訪問の予定では開始時間と提供時間から求めて示すラベルである。

**値のソース**: 通常では「終了時間」の入力で、初期値は開始時間の 1 時間後。  
訪問では「終了時間 09:29」の形の文で、提供時間が数でなければ「終了時間 -」にする。  
訪問で、開始時間と提供時間の和が 24 時以上なら、終了を翌日にし、「終了時間 翌 00:30」の形にする。  
24 時ちょうどは「終了時間 翌 00:00」になる。

**カタログ**: [ScheduleFormModal の Visit](https://buddy-docs.emon-apps.workers.dev/storybook/?path=/story/画面-schedule-scheduleformmodal--visit)

## 終了は翌日

**概要**: 通常の予定で、終了が日付の翌日の終了時間かを選ぶチェックボックス。  
夜勤のように日をまたぐ予定を入れるときに選ぶ。  
終了時間の下に置く。

**値のソース**: 「終了は翌日」。  
初期値は、開始時間の 1 時間後が 24 時を過ぎれば選んだ状態、過ぎなければ選んでいない状態。

- 選んでいなければ、終了時間は開始時間より後にする。
- 選んでいれば、終了時間は開始時間より前にする。
  - 開始時間と同じか後だと、予定が 24 時間以上になるので受けない。
  - 翌日の 0:00 に終わる予定は、終了時間を 00:00 にして選ぶ。

**カタログ**: [ScheduleFormModal の Normal](https://buddy-docs.emon-apps.workers.dev/storybook/?path=/story/画面-schedule-scheduleformmodal--normal)

**操作**: 押すと、選択を切り替え、項目の一覧の「予定日時」の要約の終了時間に「翌日」を付けるか外す。

1. 作成を押した後なら、終了時間を検証し直す。

## サービスコード

**操作**: 選ぶと、提供時間を、そのコードの提供時間の範囲の上限にし、検証し直す。

1. この後は、利用者を選んでも、サービスコードを利用者のサービスコードに替えない。

## 作成

**概要**: 入力を検証し、予定を作るボタン。

**値のソース**: 「作成」。  
送っている間は、文字に替えて回転するインジケーターを出す。

**活性**: 次の全てに当てはまるとき。

- 職員が、作成を送っている途中でない

**カタログ**: [ScheduleFormModal の Visit](https://buddy-docs.emon-apps.workers.dev/storybook/?path=/story/画面-schedule-scheduleformmodal--visit)

**操作**: 押すと、入力を検証し、予定を作る。

1. 検証に通らなければ、「入力エラー」の状態を出す。
   - 項目の一覧のエラーのある項目に、エラーの文を出す。
   - 作成はしない。
2. 検証に通れば、予定を作り、「送信中」の状態にする。
   - 「繰り返しの予定にする」を選んでいなければ、1 件の予定を作る。
   - 「繰り返しの予定にする」を選んでいれば、日付の日を最初の回にして、繰り返しの予定を作る。
3. 成功したら、モーダルを閉じ、`/schedule` に戻る。
   - `view`、`staff`、`cancelled` を引き継ぎ、`date` を日付の欄の日にする。
   - 履歴に積む。
   - 成功の文は出さない。
4. 失敗したら、「作成の失敗」の状態にし、モーダルを開いたままにする。
   - 繰り返しの予定でも、出す文は 1 件の予定と同じである。
   - Google カレンダーに書けたかを確認できなかったときは、「Google カレンダーに書けたかを確認できなかった」の状態にする。
   - 失敗の後にもう一度押しても、同じ予定として送る。予定を Google カレンダーで管理する事業所では、前の作成で Google カレンダーに書けていても、予定は 2 つにならない。繰り返しの予定も同じである。

## 全体動作

### 初期処理

開くと、職員、利用者、サービスコードの一覧を読む。  
読み終えるまでは「読み込み中」の状態を出し、どれかの一覧を読めなかったら「読み込みの失敗」の状態を出す。  
全てを読み終えると、フォームを出す。  
予定を Google カレンダーで管理する事業所でも、同じフォームを出す。  
フォームを開いたときに、作る予定の ID と、作る繰り返しの予定の ID を 1 つずつ決め、閉じるまで変えない。  
送り直しても同じ ID で送るので、予定は 2 つにならない。  
読む順と失敗の扱いは、[予定の管理の Design Doc の予定の画面の読み込みと保存](https://github.com/Fukuemon/buddy/blob/develop/services/schedule/DesignDoc.md#予定の画面の読み込みと保存) にある。

職員の一覧は、休職と退職の職員と、訪問しない職員も含めて読む。  
主訪問者と予定者の候補からは、休職と退職の職員と、訪問しない職員を除く。  
訪問しない職員の扱いは [ADR-0006](../../adr/0006-non-visiting-staff.md) にある。

開くと、ダイアログのタイトルにフォーカスを移す。  
Tab はモーダルの中だけを回る。  
閉じると、開く前にフォーカスがあった要素へ戻す。

背後のカレンダーは、`/schedule` の画面として描いたまま残る。

作成を送っている間も、閉じる、キャンセル、覆い、入力の欄は押せる。

予定のカレンダーの「予定を作成」、週の表示の空いた時間、日の表示の時間の枠から開く。

- 週の表示の空いた時間から開くと、`start` と `time` に枠の日と時刻が入る。
  - `staffId` は入らない。
- 日の表示の時間の枠から開くと、`start`、`time`、`staffId` に枠の日、時刻、列の職員が入る。
- 「予定を作成」から開くと、主訪問者と予定者は未選択である。

### URL の search params からの復元

search params は次のとおり復元する。  
読めない値はデフォルト値に置き換える。

| search param | 意味 | 省いたときと読めないとき |
| --- | --- | --- |
| `kind` | 種類のタブ。`normal`、`visit` | `visit`。デフォルト値は URL から消す |
| `start` | 日付の初期値。`YYYY-MM-DD` | カレンダーの `date`。それも無ければ今日 |
| `time` | 開始時間の初期値。`HH:mm` | 09:00 |
| `staffId` | 主訪問者と予定者の初期値。[職員の一覧](#職員の一覧) に並べる職員の外の職員を指すときは、値にしない | 未選択 |
| `view`、`date`、`staff`、`cancelled` | カレンダーの search params。閉じたときに戻す | カレンダーのデフォルト値 |

### 入力の確認と送信

- 作成を押したときに入力を検証する。
  - 押した後は、入力を変えるたびに検証し直す。
- 名前の絞り込みは、読み終えた一覧の中で行う。
- 種類を切り替えると、タイトル、利用者、サービスコード、提供時間、訪問の区分、メモを、確認を出さずに初期値に戻す。
  - 「繰り返しの予定にする」と繰り返しの欄の値は残す。
  - 切り替えの動きは、[予定の種類](#予定の種類) にある。
- 作成を拒まれたときと、つながらないときは、「作成の失敗」の状態にし、[作成の失敗の文](#作成の失敗の文) を出す。
  - 権限を外されたときと、入力が作成の規則に合わないときは、読み直さずにすぐ文を出す。
- 予定を Google カレンダーで管理する事業所では、作成を押すと、buddy が予定の職員の Google カレンダーに予定を書く。
  - Google カレンダーに書けたときだけ成功になる。
  - 書けなかったときは、入力を残し、[作成の失敗の文](#作成の失敗の文) に理由を出す。
  - 書き込みの扱いは、[ADR-0029](../../adr/0029-google-calendar-sync.md) にある。

### 変えた後の表示

作成に成功すると、予定のカレンダーの予定を読み直し、作った予定の日を出す。

### 権限の確認

画面は、ログインした職員の予定の権限から、職員ごとに予定を作れるかを決める。  
規則は [画面仕様書の規約の権限の出し分け](../rules.md#権限の出し分け) にある。

- 主訪問者と予定者の候補には、ログインした職員が予定を作れる職員だけを出す。
  - 休職と退職の職員と、訪問しない職員は、権限によらず除く。
- 利用者の候補は、権限で絞らない。
  - 利用の終了の利用者は、権限によらず除く。扱いは [ADR-0005](../../adr/0005-patient-service-end.md) にある。
- 誰の予定も作れない職員には、予定のカレンダーに「予定を作成」を出さない。
- 予定を Google カレンダーで管理する事業所でも、同じ権限で予定を作れる。
  - 予定の正本を切り替えている間は、権限によらず、予定のカレンダーに予定の作成を開く操作を出さない。
- URL の `staffId` が予定を作る権限の外の職員を指すときは、主訪問者と予定者を未選択で開く。
- 画面を開いた後に予定を作る権限を外された職員が作成を押すと、「作成の失敗」の状態にし、「この操作をする権限がありません。」を出す。
