# schedule-new 予定の作成

職員が、通常の予定か訪問の予定を 1 件作る画面。  
予定のカレンダーの上にモーダルで重ねて出す。  
予定を作ると、作った予定の日のカレンダーに戻る。

| 項目 | 値 |
| --- | --- |
| URL | `/schedule/new`。`/schedule` の子で、カレンダーの search params を引き継ぐ |
| 使う人 | 全ての職員。予定を作れる職員の範囲は、編集の権限で決まる |
| 実装 | `apps/web/src/routes/schedule.new.tsx`、`apps/web/src/features/schedule/components/ScheduleCreateModalContainer.tsx`、`apps/web/src/features/schedule/components/ScheduleFormModal.tsx`、`apps/web/src/features/schedule/components/ScheduleForm.tsx` |

画面の項目と、web の型、OpenAPI の項目の対応は [API との対応](api.md) にある。

## 構成

モーダルの上端には、左にタイトル、右上に閉じるボタンを置き、閉じるボタンの左に種類のタブを置く。  
左に項目の一覧、右に選んだ項目の入力を置く。  
下端の右には、キャンセルと作成のボタンをこの順に置く。  
幅 768px 未満では、モーダルを画面いっぱいに出し、項目の一覧の下に入力を置く。

=== "作成の失敗"

    予定を作れなかったとき。  
    次のどれでも、今は分けずにこの状態になる。

    - 作成を拒まれた。予定を作る権限が無いときと、入力が作成の規則に合わないときを含む。
    - 担当者が、画面を開いた後に休職か退職か、訪問しない職員になった。休職と退職の職員と、訪問しない職員は、予定の担当者にできない。
    - つながらない。

    作成の規則に合わない項目は、項目の一覧に示さない。  
    ログインが切れていたときは、この状態にならず、ログインの画面へ移るまで「送信中」の状態が続く。  
    失敗の要因は [API との対応の状態と失敗の要因](api.md#状態と失敗の要因) に、作成の流れは [予定の管理の Design Doc の予定の画面の読み込みと保存](https://github.com/Fukuemon/buddy/blob/develop/services/schedule/DesignDoc.md#予定の画面の読み込みと保存) にある。

## 覆い

**概要**: モーダルの後ろの予定のカレンダーを暗くぼかして覆い、操作できなくする。押すとモーダルを閉じる。

**値のソース**: 文言は無い。後ろには `/schedule` の画面として描いたカレンダーが残る。

**活性条件**: 常に活性

**表示条件**: 常に表示

**カタログ**: [ScheduleFormModal の Visit](https://buddy-docs.emon-apps.workers.dev/storybook/?path=/story/画面-schedule-scheduleformmodal--visit)

### インタラクション

#### 1. 押す

1. [閉じる](#閉じる) を押したときと同じ。中身から覆いへドラッグして離したときは閉じない。

## 閉じる

**概要**: 予定を作らずにモーダルを閉じる。

**値のソース**: ×のアイコン。読み上げの名前は「閉じる」。閉じるときに出す確認の文は次のとおり。

| 条件 | 文 |
| --- | --- |
| 入力を変えた | 変更が破棄されますがよろしいですか？ |

**活性条件**: 常に活性

**表示条件**: 常に表示

**カタログ**: [ScheduleFormModal の Visit](https://buddy-docs.emon-apps.workers.dev/storybook/?path=/story/画面-schedule-scheduleformmodal--visit)

### インタラクション

#### 1. 入力を変えずに押すか、Escape キーを押す

1. `/schedule` に戻る。カレンダーの `view`、`date`、`staff`、`cancelled` を引き継ぐ。

#### 2. 入力を変えてから押すか、Escape キーを押す

1. ブラウザの確認のダイアログで、変更を破棄してよいかを尋ねる。
2. OK なら `/schedule` に戻る。キャンセルならモーダルに留まる。

## ダイアログのタイトル

**概要**: 何のモーダルかを示す。開いたとき、ここにフォーカスを移す。

**値のソース**: 「予定の作成」

**活性条件**: 常に活性

**表示条件**: 常に表示

**カタログ**: [ScheduleFormModal の Visit](https://buddy-docs.emon-apps.workers.dev/storybook/?path=/story/画面-schedule-scheduleformmodal--visit)

## 予定の種類

**概要**: 通常の予定と訪問の予定を切り替える。

**値のソース**: 「通常」「訪問」。読み上げの名前は「予定の種類」。

**活性条件**: 常に活性

**表示条件**: 常に表示。編集の画面は出さず、作成の画面だけが持つ

**カタログ**: [ScheduleFormModal の Visit](https://buddy-docs.emon-apps.workers.dev/storybook/?path=/story/画面-schedule-scheduleformmodal--visit)

### インタラクション

#### 1. 種類を押す

1. フォームを、選んだ種類の初期値に戻す。日付、開始時間、担当者は残す。タイトル、利用者、提供時間、訪問の種類、メモは初期値に戻る。確認は出さない。
   - 残した日付、開始時間、担当者を開いたときの値から変えていれば、変更ありとして扱い、閉じるときに確認を出す。
2. URL の `kind` を置き換える。履歴には積まない。
3. 右の入力に開いていた項目が、選んだ種類に無ければ、右には日時の入力を出す。

## 項目の一覧

**概要**: フォームの項目と今の値を要約して並べる。押した項目の入力を右に出す。右に出している項目は枠を太くする。

**値のソース**: 項目の名前と、今の値の要約。

| 項目 | 種類 | 名前 | 値の要約 |
| --- | --- | --- | --- |
| タイトル | 通常 | 「タイトル」 | 入力したタイトル。空なら何も出さない |
| 日時 | 訪問 | 「訪問日時」 | 「2024-04-01 09:00 - 09:29（29 分、訪看I2）」の形。提供時間が数でなければ、終了時間と提供時間を「-」にする |
| 日時 | 通常 | 「予定日時」 | 「2024-04-01 09:00 - 10:00」の形 |
| 利用者 | 訪問 | 「利用者」 | 選んだ利用者の名前。選んでいなければ、薄い色の「選んでください」 |
| 担当者 | 訪問、通常 | 「担当者」。通常では「予定者」 | 選んだ職員の名前。選んでいなければ、薄い色の「選んでください」 |
| 訪問の種類 | 訪問 | 「訪問の種類」 | 選んだ種類を「、」でつなぐ。空なら「通常」 |
| メモ | 訪問、通常 | 「メモ」 | 入力したメモ。空なら何も出さない |

- 値を入れていない項目は、要約を空にする。利用者、担当者、予定者は、薄い色で「選んでください」と出す。読み上げでは、項目の名前と「未入力」を読ませる。
- 入力エラーがある項目は、枠を赤く太くし、要約の下にエラーの文を出す。日付と時間のエラーは、日時の 1 つの枠にまとめ、日付、開始時間、終了時間、提供時間の順で最初の 1 つの文を出す。
- 日時とタイトルの入力では、右の入力の欄ごとに、その欄のエラーの文を欄の下に出す。利用者と担当者は、項目の一覧の枠と文だけで示す。
- 作成を押した後、検証に通らない項目にエラーの文を出す。
  - 押した後は、入力を変えるたびに検証し直す。
- エラーの文は、項目と条件ごとに次のとおり。

| 項目 | 条件 | 文 |
| --- | --- | --- |
| タイトル（通常） | 空白だけか空 | 「タイトルを入力してください」 |
| 日付 | 日付として読めない | 「日付を入力してください」 |
| 開始時間 | `HH:mm` でない | 「開始時間を入力してください」 |
| 終了時間（通常） | `HH:mm` でない | 「終了時間を入力してください」 |
| 終了時間（通常） | 開始時間より後でない | 「終了時間は開始時間より後にしてください」 |
| 利用者（訪問） | 選んでいない | 「利用者を選んでください」 |
| 担当者、予定者 | 選んでいない | 「担当者を選んでください」 |
| 提供時間（訪問） | 数でないか、整数でない | 「提供時間を入力してください」 |

## 全体動作

### 初期処理

- 開いた直後から、全ての操作ができる。職員と利用者の一覧を読み終えるのを待たずにフォームを出す。読み終えるまでと、読めなかったときは、職員の一覧と利用者の一覧は 0 件である（「選択肢が無い」の状態）。
  - 読む順と失敗の扱いは、[予定の管理の Design Doc の予定の画面の読み込みと保存](https://github.com/Fukuemon/buddy/blob/develop/services/schedule/DesignDoc.md#予定の画面の読み込みと保存) にある。
- 職員の一覧は、休職と退職の職員と、訪問しない職員も含めて読む。休職と退職の職員と、訪問しない職員は担当者の候補から除く。訪問しない職員の扱いは [ADR-0022](../../adr/0022-receipt-check-policy-and-non-visiting-staff.md) にある。
- 開くと、ダイアログのタイトルにフォーカスを移す。Tab はモーダルの中だけを回る。閉じると、開く前にフォーカスがあった要素へ戻す。
- 背後のカレンダーは、`/schedule` の画面として描いたまま残る。
- 予定のカレンダーの「予定を作成」、週の表示の空いた時間、日の表示の時間の枠から開く。
  - 週の表示の空いた時間から開くと、`start` と `time` に枠の日と時刻が入る。`staffId` は入らない。
  - 日の表示の時間の枠から開くと、`start`、`time`、`staffId` に枠の日、時刻、列の職員が入る。
  - 「予定を作成」から開くと、担当者は未選択である。

### URL の search params からの復元

search params は次のとおり復元する。読めない値はデフォルト値に置き換える。

| search param | 意味 | 省いたときと読めないとき |
| --- | --- | --- |
| `kind` | 種類のタブ。`normal`、`visit` | `visit`。デフォルト値は URL から消す |
| `start` | 日付の初期値。`YYYY-MM-DD` | カレンダーの `date`。それも無ければ今日 |
| `time` | 開始時間の初期値。`HH:mm` | 09:00 |
| `staffId` | 担当者の初期値。職員の一覧に無い ID も、そのまま値にする。休職か退職の職員か、訪問しない職員の ID は値にしない | 未選択 |
| `view`、`date`、`staff`、`cancelled` | カレンダーの search params。閉じたときに戻す | カレンダーのデフォルト値 |

### 入力の確認と送信

- 作成を押したときに入力を検証する。押した後は、入力を変えるたびに検証し直す。
- 名前の絞り込みは、読み終えた一覧の中で行う。
- URL の `staffId` が職員の一覧に無い ID のときは、「選んでください」と出したまま検証に通し、その値のまま作る。作成を拒まれれば、「作成の失敗」の状態になる。
- 種類を切り替えると、タイトル、利用者、提供時間、訪問の種類、メモを、確認を出さずに初期値に戻す（[予定の種類](#予定の種類)）。

### 変えた後の表示

- 作成に成功すると、予定のカレンダーの予定を読み直し、作った予定の日を出す。

### 権限の確認

- 職員の一覧には、編集の権限によらず、事業所の職員を出す（休職と退職の職員と、訪問しない職員を除く）。
- 予定を作る権限の無い職員の予定を作ろうとすると、「作成の失敗」の状態になる。

## 未決

### 決まっていないこと

- 職員の一覧に、編集の権限の外の職員を出すか。出して作成のときに止めるか。出さないなら、画面が職員の権限をどこから読むか。
  - 今の動き: 編集の権限によらず出し、作成を拒まれると「作成の失敗」の状態になる。
  - 決める人: 開発者
  - 期限: #383
- 職員と利用者の一覧を読んでいる間と、読めなかったときを、フォームの中でどう見せるか。
  - 今の動き: 選択肢が 0 件のときと見分けが付かず、読み込みの失敗の文も出さない。
  - 決める人: 開発者
  - 期限: #383
- 予定を作る権限が無いときと、入力が作成の規則に合わないときを、ほかの作成の失敗と分けて見せるか。規則に合わない項目を項目の一覧に示すか。
  - 今の動き: どれも「予定を作成できませんでした。」を出し、項目には示さない。
  - 決める人: 開発者
  - 期限: #383
- 提供時間の範囲を、画面に持たせたままにするか、予定の管理のサービスコードの一覧から読むか。
  - 今の動き: 画面が定数で持つ。
  - 決める人: 開発者
  - 期限: サービスコードの提供時間の範囲を変えるとき

### PRD と実装の食い違い

- PRD は、訪問の予定に同行者を持たせ、毎週と毎月の繰り返しの予定を作れるとしている。この画面は、同行者を入れられず、単発の予定だけを作る。
  - 決める人: 開発者が、事業所の責任者に確認して決める
  - 期限: 同行者と繰り返しの予定を画面で扱うとき
- PRD と Design Doc は、サービスコードを「訪看I２」のように全角の数字で書き、画面は半角の数字で書く。
  - 決める人: 開発者
  - 期限: 画面の語を PRD にそろえるとき
