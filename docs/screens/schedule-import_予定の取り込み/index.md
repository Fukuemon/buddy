# schedule-import 予定の取り込み

職員の管理の権限を持つ職員が、職員の Google カレンダーの予定を、期間を選んでプレビューし、確定して buddy の予定に取り込む画面。  
カレンダーは、[カレンダーの連携](../schedule-link_カレンダーの連携/index.md) で職員に結び付けておく。

| 項目 | 値 |
| --- | --- |
| URL | `/schedule/import` |
| 使う人 | 職員の管理の権限を持つ職員。デフォルトはマネージャー |
| 実装 | `apps/web/src/routes/schedule_.import.tsx`、`apps/web/src/features/calendar/components/CalendarImportContainer.tsx`、`apps/web/src/features/calendar/components/CalendarImportView.tsx`、`apps/web/src/features/calendar/components/CalendarImportForm.tsx`、`apps/web/src/features/calendar/components/CalendarImportPreview.tsx`、`apps/web/src/features/calendar/components/CalendarImportReviewItem.tsx`、`apps/web/src/features/calendar/components/CalendarImportCounts.tsx`、`apps/web/src/features/calendar/components/CalendarImportDone.tsx`、`apps/web/src/components/page/PageForbiddenMessage.tsx` |

画面の項目と、web の型、OpenAPI の項目の対応は [API との対応](api.md) にある。

## 構成

ヘッダーの左に、メニューのボタンと buddy を置く。  
ヘッダーの右には、アカウントのボタンを置く。  
ヘッダーの下の左端には、画面の間を移るナビゲーションを置く。  
ナビゲーションの見出しと項目、出す職員は、[職員の一覧のナビゲーション](../staff-list_職員の一覧/index.md#ナビゲーション) にある。  
今の画面の取り込みに印を付ける。  
幅 768px 以上では、ナビゲーションを幅 224px の開いた形で始め、メニューのボタンで幅 80px のレールと切り替える。  
幅 768px 未満では、ナビゲーションをドロワーにし、閉じた状態で始める。  
ナビゲーション、要確認、取り込みの印は、幅 768px 未満ではドロワーを開くと出る。

ヘッダーの下の、ナビゲーションの右に、ページのタイトル、説明の文、職員と期間の入力、プレビューの結果を縦に並べる。  
プレビューの結果は、件数、確認が必要な予定、取り込まない予定、確定して取り込むの順に並ぶ。  
幅 768px 以上では、職員と期間の入力を横に並べ、確認が必要な予定の取り込み方を予定の右に置く。

=== "プレビューの失敗"

    プレビューが失敗したとき。

## メニュー

**概要**: ナビゲーションの形を切り替える。  
幅 768px 未満では、ナビゲーションのドロワーを開く。

**値のソース**: 3 本の横線のアイコン。  
読み上げる名前は「メニュー」。

**活性条件**: 常に活性

**表示条件**: 常に、ヘッダーの左端に出す。

**カタログ**: [SiteLayoutContainer の Mobile](https://buddy-docs.emon-apps.workers.dev/storybook/?path=/story/画面-common-sitelayoutcontainer--mobile)

### インタラクション

#### 1. 幅 768px 以上で押す

1. ナビゲーションを、開いた形からレールに切り替える。
  - もう一度押すと開いた形に戻る。

#### 2. 幅 768px 未満で押す

1. 左端からナビゲーションのドロワーが開く。

## ナビゲーション

**概要**: 予定、照合、職員、利用者の画面の間を移る。

**値のソース**: 見出しと項目、出す職員は、[職員の一覧のナビゲーション](../staff-list_職員の一覧/index.md#ナビゲーション) にある。  
今の画面に面の色の印を付ける。  
この画面では「取り込み」に付ける。  
レールでは見出しを出さず、アイコンの下に名前を置き、見出しのまとまりの間を区切り線で分ける。

**活性条件**: 常に活性

**表示条件**: 常に、ヘッダーの下の左端に出す。  
幅 768px 以上では、この画面では開いた形で始める。  
幅 768px 未満では、メニューのボタンで開いたドロワーの中に出す。  
モックは、職員の管理の権限を持つ職員の画面を描く。

**カタログ**: [SiteNav の Manager](https://buddy-docs.emon-apps.workers.dev/storybook/?path=/story/画面-common-sitenav--manager)

### インタラクション

#### 1. 「カレンダー」を押す

1. 予定のカレンダーへ移る。
  - プレビューの結果と選んだ取り込み方は捨てる。

#### 2. 「連携」を押す

1. カレンダーの連携の画面へ移る。
  - プレビューの結果と選んだ取り込み方は捨てる。

#### 3. 「照合」を押す

1. 照合の画面へ移る。
  - プレビューの結果と選んだ取り込み方は捨てる。

#### 4. 「職員」「部署とチーム」「利用者」を押す

1. 職員の一覧、部署とチーム、利用者の一覧へ移る。
  - プレビューの結果と選んだ取り込み方は捨てる。

#### 5. 幅 768px 未満で、閉じるボタンか覆いを押すか、Escape キーを押す

1. ナビゲーションのドロワーが閉じ、フォーカスがメニューのボタンに戻る。

## 要確認

**概要**: 確認が必要な予定の件数を示し、確認が必要な予定の画面を開く。

**値のソース**: 鈴のアイコンと「要確認」。  
確認が必要な予定の件数を、開いた形では項目の右端に、レールではアイコンの右上に、印で示す。  
0 件のときは印を出さない。  
読み上げる名前は、「要確認 3 件」のように件数を入れる。

**活性条件**: 常に活性

**表示条件**: 職員の管理の権限を持つ職員にだけ、ナビゲーションの「取り込み」と「連携」の間に出す。  
モックは、職員の管理の権限を持つ職員の画面を描く。

**カタログ**: [CalendarReviewBadge の WithReview](https://buddy-docs.emon-apps.workers.dev/storybook/?path=/story/画面-calendar-calendarreviewbadge--with-review)、[CalendarReviewBadge の NoReview](https://buddy-docs.emon-apps.workers.dev/storybook/?path=/story/画面-calendar-calendarreviewbadge--no-review)

### インタラクション

#### 1. 押す

1. 確認が必要な予定の画面へ移る。
  - プレビューの結果と選んだ取り込み方は捨てる。

## 件数

## 取り込まない予定

**概要**: 取り込まない予定を 1 件ずつ、日時と理由で示す。  
職員が Google カレンダーでその予定を探し、直せるようにする。

**値のソース**: 「取り込まない予定（4 件）」の形の、件数のある見出しと、「日時」と「理由」のカラム。  
取り込まない予定の件数は、この見出しにだけ出す。  
理由ごとの件数は出さない。

日時は「2026/11/12（木）17:00〜翌 09:00」の形で、読めた分だけを出す。  
終了の時刻の前の「翌」は、日をまたぐ予定と、終了が翌日の予定に付ける。  
終日の予定は「2026/11/03（火）終日」、日時を読めない予定は「日時を読めない」とする。

理由は次の文言にする。

| 理由 | 文言 | 当たる予定 |
| --- | --- | --- |
| 終日 | 「終日の予定」 | 時刻の無い予定 |
| 日をまたぐ | 「日をまたぐ予定」 | 終了が開始の翌日より後の予定と、24 時間以上の予定。翌日に終わる 24 時間未満の予定は、終了が翌日の予定として取り込む |
| 時刻を読めない | 「時刻を読めない予定」 | 開始か終了の日時が無いか、読めない予定 |
| 長さが無い | 「長さの無い予定」 | 分に丸めると、終了が開始より後でない予定 |
| タイトルを読めない | 「タイトルを読めない予定」 | タイトルに `【` と `】` を含むが、サービス内容か利用者名を読めない予定 |
| サービス内容を引けない | 「サービス内容を引けない予定」 | タイトルから読んだサービス内容が、buddy のサービスコードに無い予定 |
| 休職 | 「休職の職員の新しい予定」 | 職員が休職しているときの、前の取り込みで取り込んでいない予定。扱いは [職員](#職員) にある |
| 訪問しない | 「訪問しない職員の新しい予定」 | 職員が訪問しない職員のときの、前の取り込みで取り込んでいない予定。扱いは [職員](#職員) にある |

日時の順に並べ、日時を読めない予定は最後に置く。  
タイトルは利用者名を含むので出さない。

**活性条件**: 常に活性

**表示条件**: プレビューの結果に取り込まない予定があるとき

**カタログ**: [CalendarImportPreview の Preview](https://buddy-docs.emon-apps.workers.dev/storybook/?path=/story/画面-calendar-calendarimportpreview--preview)

## 全体動作

### 決めたこと

- 1 回の取り込みで選べる職員は 1 人にした。
  - 取り込みの記録と最後の取り込みを、職員のカレンダーごとに持つためである。

### 初期処理

- ログインした職員が職員の管理の権限を持たなければ、「権限が無い」の状態にする。
- 権限があれば、結び付けたカレンダーと職員を読み終えるまで、「読み込み中」の状態にする。
  - 結び付けたカレンダーが無ければ、「結び付けたカレンダーが無い」の状態にする。
  - 読めなかったときは、「読み込みの失敗」の状態にする。
- プレビューは自動では始めない。

### URL の search params からの復元

- `staff` に職員の ID があり、その職員にカレンダーが結び付いていれば、職員の欄でその職員を選ぶ。
  - 無ければ、名前の順で最初の職員を選ぶ。
- 職員の欄で職員を変えると、`staff` を選んだ職員の ID にする。

### 入力の確認と送信

- 確定して取り込むを押すと、プレビューの後に Google カレンダーで変わった予定も、プレビューと同じ規則で読み直して取り込む。
- プレビューの後に、確認が必要な予定が増えたか減ったか、確認が必要な予定のタイトルか時刻が Google カレンダーで変わったときは、「取り込みの失敗」の状態にし、予定は 1 件も取り込まない。
  - プレビューし直すと、今の予定で取り込み方を選び直せる。
- プレビューの後、確定して取り込むを押す前に職員が休職か復職になったか、訪問するかが変わったときは、押した時点の職員の状態で取り込む。
  - 確認が必要な予定が変われば、「取り込みの失敗」の状態にする。
- 確定して取り込むを押してから取り込み終えるまでの間に、職員が休職か復職になったか、訪問するかが変わったときは、「取り込みの失敗」の状態にし、予定は 1 件も取り込まない。
  - 職員が退職したときは、カレンダーの結び付けが外れたことを、取り込みの失敗の文に出す。
- 同じ職員の取り込みがほかの画面で進んでいる間は、取り込めない。
- 処理の流れは、[Google カレンダーとの連携の Design Doc の Google カレンダーの取り込み](https://github.com/Fukuemon/buddy/blob/develop/services/schedule/internal/features/calendar/DesignDoc.md#google-カレンダーの取り込み) にある。

### 変えた後の表示

取り込んだ予定は、予定のカレンダーに次の形で出る。

- タイトルに `【` と `】` の両方を含む予定は、タイトルから読んだサービス内容と利用者の、訪問の予定になる。
  - 主訪問者は、カレンダーを結び付けた職員になる。
  - 同行者と訪問の区分はタイトルに無いので、空になる。取り込んだ後に、予定の編集で足す。
- `【` と `】` を含まない予定は、タイトルをそのまま使った通常の予定になる。
- 毎週の曜日、毎月の日付、毎月の第何週の曜日で繰り返す予定は、buddy の繰り返しの予定になる。
  - Google カレンダーで取り消した回は出ず、1 回だけ変えた回は変えた日時で出る。
  - ADR-0009: [Google カレンダーとの連携](../../adr/0009-google-calendar-sync.md)
- 隔週、複数の曜日、最終週などの、ほかの形の繰り返しは、期間の中の回ごとの予定になる。
  - Google カレンダーで取り消した回は取り込まず、取り込まない件数にも数えない。

同じ期間を 2 回取り込んでも、予定は重ならない。

- 2 回目のプレビューでは、1 回目に取り込んだ予定を取り込み済みに数え、確定しても取り込まない。
- 1 回目の取り込みの後に Google カレンダーで足した予定だけが、取り込む件数に出る。
- 1 回目の後に Google カレンダーで変えた予定は、取り込み済みのまま、取り込みでは buddy の予定を変えない。

取り込みが成功すると、[カレンダーの連携](../schedule-link_カレンダーの連携/index.md) の最後の取り込みに、終わった日時と期間が出る。

### 権限の確認

職員の管理の権限を持たない職員には、「権限が無い」の状態を出し、職員と期間の欄を出さない。  
画面を開いた後に権限を外された職員が操作したときは、プレビューの失敗の文、取り込みの失敗の文、読み込みの失敗の文の位置に、「この操作をする権限がありません。」を出す。

## 未決

### 決まっていないこと

- 複数の職員の予定を、1 回でまとめて取り込めるようにするか。
  - 今の動き: 1 回の取り込みで選べる職員は 1 人である。
  - 決める人: 開発者が、事業所の責任者に確認して決める
  - 期限: 予定の取り込みを使い始めた事業所の声を聞いた後
- 期間の上限を 1 年にし、期間のデフォルトを次の月にしてよいか。
  - 今の動き: 期間が 1 年を超えるとプレビューできない。期間のデフォルトは、今日の次の月の 1 日から月末である。
  - 決める人: 開発者が、事業所の責任者に確認して決める
  - 期限: 事業所で予定の取り込みを使い始めるまで
- 繰り返しのまま取り込む予定で、期間の外の回を取り込まない形が要るか。
  - 今の動き: 期間の外の回も規則ごと取り込む。期間で回を切ると、次の期間を取り込むときに同じ繰り返しが取り込み済みに数えられ、残りの回が入らないためである。
  - 決める人: 開発者が、事業所の責任者に確認して決める
  - 期限: 予定の取り込みを使い始めた事業所の声を聞いた後
- 利用者を選んだ結果を、利用者の別名として覚えるか。
  - 今の動き: 覚えない。次の期間を取り込むときも、同じ予定は確認が必要な予定になる。
  - 決める人: 開発者
  - 期限: 予定の取り込みを使い始めた事業所の声を聞いた後
- タイトルから読んだサービス内容が buddy のサービスコードに無いときに、確認が必要な予定にして選ばせるか。
  - 今の動き: 「サービス内容を引けない予定」の取り込まない予定にする。
    - サービス内容の表記のそろえ方は、照合と同じである。
  - 決める人: 開発者が、事業所の責任者に確認して決める
