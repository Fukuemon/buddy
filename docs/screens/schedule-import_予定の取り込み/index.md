# schedule-import 予定の取り込み

職員の管理の権限を持つ職員が、職員の Google カレンダーの予定を、期間を選んでプレビューし、確定して buddy の予定に取り込む画面。カレンダーは、[カレンダーの連携](../schedule-link_カレンダーの連携/index.md) で職員に結び付けておく。

| 項目 | 値 |
| --- | --- |
| URL | `/schedule/import` |
| 使う人 | 職員の管理の権限を持つ職員（デフォルトはマネージャー） |
| 実装 | `apps/web/src/routes/schedule_.import.tsx`、`apps/web/src/features/calendar/components/CalendarImportContainer.tsx`、`apps/web/src/features/calendar/components/CalendarImportView.tsx`、`apps/web/src/features/calendar/components/CalendarImportForm.tsx`、`apps/web/src/features/calendar/components/CalendarImportPreview.tsx`、`apps/web/src/features/calendar/components/CalendarImportReviewItem.tsx`、`apps/web/src/features/calendar/components/CalendarImportCounts.tsx`、`apps/web/src/features/calendar/components/CalendarImportDone.tsx`、`apps/web/src/components/site/PageForbiddenMessage.tsx` |

画面の項目と、web の型、OpenAPI の項目の対応は [API との対応](api.md) にある。

## 構成

ヘッダーの左に、メニューのボタンと buddy を置く。ヘッダーの右には、アカウントのボタンを置く。ヘッダーの下の左端には、画面の間を移るナビゲーションを置く。ナビゲーションは、見出し「予定」の下にカレンダー、取り込み、要確認、連携を並べ、見出し「照合」の下に照合を並べる。取り込み、要確認、連携は、職員の管理の権限を持つ職員にだけ出す。今の画面の取り込みに印を付ける。幅 768px 以上では、ナビゲーションを幅 224px の開いた形で始め、メニューのボタンで幅 80px のレールと切り替える。幅 768px 未満では、ナビゲーションをドロワーにし、閉じた状態で始める。ナビゲーション、要確認、取り込みの印は、幅 768px 未満ではドロワーを開くと出る。

ヘッダーの下の、ナビゲーションの右に、ページのタイトル、説明の文、職員と期間の入力、プレビューの結果を縦に並べる。プレビューの結果は、件数、確認が必要な予定、取り込まない予定、確定して取り込むの順に並ぶ。
幅 768px 以上では、職員と期間の入力を横に並べ、確認が必要な予定の取り込み方を予定の右に置く。

## メニュー

**概要**: ナビゲーションの形を切り替える。幅 768px 未満では、ナビゲーションのドロワーを開く。

**値のソース**: 3 本の横線のアイコン。読み上げる名前は「メニュー」。

**活性条件**: 常に活性

**表示条件**: 常に、ヘッダーの左端に出す。

**カタログ**: [SiteLayoutContainer の Mobile](https://buddy-docs.emon-apps.workers.dev/storybook/?path=/story/画面-common-sitelayoutcontainer--mobile)

### インタラクション

#### 1. 幅 768px 以上で押す

1. ナビゲーションを、開いた形からレールに切り替える。もう一度押すと開いた形に戻る。

#### 2. 幅 768px 未満で押す

1. 左端からナビゲーションのドロワーが開く。

## ナビゲーション

**概要**: 予定と照合の画面の間を移る。

**値のソース**: 見出し「予定」の下に、「カレンダー」「取り込み」「要確認」「連携」のアイコンと名前を並べる。見出し「照合」の下に、「照合」のアイコンと名前を置く。今の画面に面の色の印を付ける。この画面では「取り込み」に付ける。レールでは見出しを出さず、アイコンの下に名前を置き、「予定」と「照合」の間を区切り線で分ける。

**活性条件**: 常に活性

**表示条件**: 常に、ヘッダーの下の左端に出す。幅 768px 以上では、この画面では開いた形で始める。幅 768px 未満では、メニューのボタンで開いたドロワーの中に出す。「取り込み」「要確認」「連携」は、職員の管理の権限を持つ職員にだけ出す。モックは、職員の管理の権限を持つ職員の画面を描く。

**カタログ**: [SiteNav の Import](https://buddy-docs.emon-apps.workers.dev/storybook/?path=/story/画面-common-sitenav--import)

### インタラクション

#### 1. 「カレンダー」を押す

1. 予定のカレンダーへ移る。プレビューの結果と選んだ取り込み方は捨てる。

#### 2. 「連携」を押す

1. カレンダーの連携の画面へ移る。プレビューの結果と選んだ取り込み方は捨てる。

#### 3. 「照合」を押す

1. 照合の画面へ移る。プレビューの結果と選んだ取り込み方は捨てる。

#### 4. 幅 768px 未満で、閉じるボタンか背景を押すか、Escape キーを押す

1. ナビゲーションのドロワーが閉じ、フォーカスがメニューのボタンに戻る。

## 要確認

**概要**: 確認が必要な予定の件数を示し、確認が必要な予定の画面を開く。

**値のソース**: 鈴のアイコンと「要確認」。確認が必要な予定の件数を、開いた形では項目の右端に、レールではアイコンの右上に、印で示す。0 件のときは印を出さない。読み上げる名前は、「要確認 3 件」のように件数を入れる。

**活性条件**: 常に活性

**表示条件**: 職員の管理の権限を持つ職員にだけ、ナビゲーションの「取り込み」と「連携」の間に出す。モックは、職員の管理の権限を持つ職員の画面を描く。

### インタラクション

#### 1. 押す

1. 確認が必要な予定の画面へ移る。プレビューの結果と選んだ取り込み方は捨てる。

## プレビューする

**概要**: 選んだ職員のカレンダーの、期間の予定を読み、取り込むとどうなるかを示す。プレビューでは予定を書かない。

**値のソース**: 「プレビューする」

## 全体動作

### 初期処理

- 開くと、ログインした職員の権限を読む。職員の管理の権限が無ければ、ほかの API を呼ばず、「権限が無い」の状態にする。
- 権限があれば、結び付けたカレンダーの一覧と職員の一覧を読み、読み終えるまで「読み込み中」の状態にする。
  - 結び付けたカレンダーが無ければ、「結び付けたカレンダーが無い」の状態にする。
  - 読めなかったときは、「読み込みの失敗」の状態にする。
- search params の `staff` に職員の ID があり、その職員にカレンダーが結び付いていれば、職員の欄でその職員を選ぶ。無ければ、名前の順で最初の職員を選ぶ。
- プレビューは自動では始めない。

### 権限の確認

画面の判定は表示のためだけにする。予定の API も、職員の管理の権限が無い職員のリクエストを 403 で拒む。画面を開いた後に権限を外された職員が操作したときは、失敗の文か読み込みの失敗の文の位置に、「この操作をする権限がありません。」を出す。

### 予定の読み替え

予定の API は、Google カレンダーの予定を次の規則で buddy の予定に読み替え、プレビューと確定の両方で同じ規則を使う。

- タイトルに `【` と `】` の両方を含む予定は、照合の API と同じ規則でサービス内容と利用者名を読み、訪問の予定にする。主訪問者は、カレンダーを結び付けた職員にする。
  - 利用者名で事業所の利用者を引き、1 人に決まらない予定は、確認が必要な予定にする。
- `【` と `】` を含まない予定は、タイトルをそのまま使った通常の予定にする。
- 毎週の曜日、毎月の日付、毎月の第何週の曜日で繰り返す予定は、繰り返しの予定のまま取り込む。Google カレンダーで取り消した回は除外する日に、1 回だけ変えた回は回の置き換えにする。
  - ADR-0009: [Google カレンダーとの連携](../../adr/0009-google-calendar-sync.md)
- ほかの形の繰り返し（隔週、複数の曜日、最終週など）は、期間の中の回ごとの予定にする。Google カレンダーで取り消した回は取り込まず、取り込まない件数にも数えない。
- [理由ごとの件数](#理由ごとの件数) の理由に当たる予定は取り込まず、日時と理由だけを出す。タイトルは利用者名を含むので出さない。
- 前の取り込みで取り込んだ Google の予定は、取り込み済みに数え、もう一度は取り込まない。

### 休職と退職の職員

休職と退職の職員には、新しい予定を割り振らない（ADR-0018）。

- ADR-0018: [職員の停止を、戻せる休職と、戻せない退職に分ける](../../adr/0018-staff-leave-and-retirement.md)

| 職員の状態 | この画面での動き |
| --- | --- |
| 休職 | 職員の選択肢に出る。新しい予定は、取り込む予定と確認が必要な予定にせず、「休職の職員の新しい予定」の取り込まない予定に出す。前の取り込みで繰り返しのまま取り込み、今もその職員に割り振った予定の、取り消した回と変えた回は、今と同じく取り込む。復職すると、結び付け直さずに新しい予定を取り込める |
| 退職 | 退職でカレンダーが外れるので、職員の選択肢に出ない。カレンダーのレコードと、前に取り込んだ予定は残る |

- 確定は職員の休職を読み直してから読み替える。確定が読み替えてから書くまでの間に職員が休職か復職になったときは、409 になり、「取り込みの失敗」の状態になる。職員が退職になったときは、確定で 404 になる。

### 同じ期間を 2 回取り込む

予定の API は、取り込んだ Google の予定と buddy の予定の対応を持つ。2 回目のプレビューでは、対応のある予定を取り込み済みに数え、確定しても書かない。
1 回目の取り込みの後に Google カレンダーで足した予定だけが、取り込む件数に出る。1 回目の後に Google カレンダーで変えた予定は、取り込み済みのまま、buddy の予定に当てない。

### プレビューと確定の食い違い

予定の API はプレビューの結果を保存しない。確定では Google カレンダーの予定を読み直し、プレビューと同じ規則で読み替える。
確認が必要な予定の取り込み方は、Google の予定の ID で送る。読み直した結果に、取り込み方を送っていない確認が必要な予定があるか、送った予定が確認が必要な予定でなくなっていたら、予定の API は何も書かずに 409 を返す。画面は「取り込みの失敗」の状態にする。

## 未決

- 1 回の取り込みで選べる職員は 1 人にした。取り込みの記録のテーブル（`import_runs`）がカレンダーごとであるためである。複数の職員をまとめて取り込むかは、使い始めた事業所の声を聞いて決める。
- 期間の上限の 1 年と、期間のデフォルトを次の月にすることは案である。
- 繰り返しのまま取り込む予定は、期間の外の回も規則ごと取り込む。期間で回を切ると、次の期間を取り込むときに同じ繰り返しが取り込み済みに数えられ、残りの回が入らないためである。期間の外の回を取り込まない形が要るかは、決めていない。
- 利用者を選んだ結果を、利用者の別名として覚えるかは決めていない。#141 のテーブルに別名のテーブルは無いので、次の期間を取り込むときも、同じ予定は確認が必要な予定になる。
- タイトルから読んだサービス内容を buddy のサービスコードに当てる表記のそろえ方は、照合の API と同じにする。サービスコードに無いときに、確認が必要な予定にして選ばせるかは決めていない。この画面では取り込まない予定にした。
- 同行者と訪問の区分はタイトルに無いので、取り込んだ訪問の予定では空になる。取り込んだ後に、予定の編集で足す。
- 取り込みに時間がかかるとき（予定が数千件あるとき）に、レスポンスを待たずに取り込みの記録を読み直す形にするかは、決めていない。予定が数千件のときの時間は測っていない。
- この画面に、Google カレンダーへの書き出しの状態を出すかは決めていない。Google カレンダーで直された予定と、書き出せなかった予定は、[確認が必要な予定](../schedule-review_確認が必要な予定/index.md) で確認する。
