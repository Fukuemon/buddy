# ADR-0038: 繰り返しの規則に、毎週の複数の曜日と間隔を足し、終わりは終了日だけで持つ

## Status

承認

## Context

訪問看護では、週に 2 回（月曜と木曜）と隔週の訪問がある。buddy の繰り返しの規則は、毎週の曜日 1 つ、毎月の日、毎月の第何週の曜日のどれかで、終わりは終了日だけである。週に 2 回の訪問は繰り返しの予定を 2 つ作る必要があり、隔週の訪問は表せない。

決定に関わる事実は次のとおり。

- 医療保険の訪問看護は、原則として週 3 日までである。別表第 7 の疾病の人、別表第 8 に当たる人、特別訪問看護指示書の交付を受けた人は、週 4 日以上の訪問ができる。特別訪問看護指示書の有効期間は 14 日（月 2 回交付できる人は 28 日）である。訪問看護の料金は「週 3 日目まで」と「週 4 日目以降」で分かれる。
  - 出典: [厚生労働省 第 259 回社会保障審議会介護給付費分科会 資料 3](https://www.mhlw.go.jp/content/12300000/001716095.pdf) の 4 ページと 55 ページ
- Google カレンダーと Outlook は、間隔、週の複数の曜日、回数での終了を持つ。RFC 5545 の `WKST`（週の始まり）は、毎週で間隔が 2 以上かつ曜日が複数のときに回を変える。
  - 出典: [RFC 5545 の 3.3.10](https://www.rfc-editor.org/rfc/rfc5545.txt)、[Microsoft Graph の recurrencePattern](https://learn.microsoft.com/en-us/graph/api/resources/recurrencepattern?view=graph-rest-1.0)
- 繰り返しの予定は回を保存せず、最初の日付と規則で回を決める。予定のカレンダーの週は日曜に始まる。
- 規則の変更は、適用の日で繰り返しの予定を分け、新しい予定の最初の日付を、適用の日以降で新しい規則が当たる最初の日にする（[ADR-0037](0037-recurring-rule-change.md)）。

## Decision

毎週の規則に、複数の曜日と間隔を足す。この範囲は、利用者が選んだ。

- 頻度は、今と同じく毎週と毎月だけにする。
  - 毎日は、7 つの曜日の毎週と終了日で表せる。特別訪問看護指示書の期間の毎日の訪問は、この形で作る。
  - 毎年の訪問は要らない。
- 毎週の規則は、1 つ以上の曜日と、1〜52 の間隔（週の数）を持つ。
  - 上限は、入力の誤りを拒むために置く。1 年を超える間隔の訪問は考えにくい。
- 毎月の規則は今のままにする。毎月の間隔、毎月の複数の日、最終の曜日は足さない。隔月と最終の曜日の訪問の例が見つからなかったためである。
- 隔週の週は、日曜に始まる週で数える。最初の日付を含む週を 1 週目とし、1 週目から間隔の倍数だけ後の週の、規則の曜日に回がある。予定のカレンダーの週と、職員が見る隔週の並びをそろえるためである。
- 規則の変更で新しい規則を数え始めるときは、数え始める日を含む週を 1 週目にする。数え始める日は、分けるときは適用の日、分けないときは元の最初の日付である。新しい予定の最初の日付は、1 週目から数えて新しい規則が当たる最初の日にする。
  - 画面は開いた回の日を適用の日にするので、開いた回の週が訪問の週のまま残る。新しい規則が当たる最初の日を 1 週目にすると、曜日を前に移したときに隔週の並びが 1 週ずれる。
- 繰り返しの終わりは、終了日だけで持つ。回数は保存しない。
  - 回数で作るときと、回数で終わる Google の予定を取り込むときは、最後の回の日付を終了日にする。回数は、除外する日を除く前の回で数える（RFC 5545）。
  - 規則の変更は、回数を数え直さず、ADR-0037 のとおりに終了日で分ける。回数を持つと、分けた後の残りの回数に、除外する日、置き換えた回、キャンセルした回を数えるかの決まりが要るためである。
- 規則は、RRULE の文字列ではなく項目で持つ。毎週の曜日は配列で、間隔はデフォルト値 1 で持つ。既にある毎週の繰り返しの予定は、間隔 1 と、今の曜日（値が無ければ最初の日付の曜日）の 1 つの要素の配列に移す。既にある予定の回は変わらない。

## Considered Options

| 選択肢 | 強み | 弱み |
| --- | --- | --- |
| **採用:** 毎週の複数の曜日と 1〜52 の間隔を足し、終わりは終了日だけで持つ | 週に 2 回と隔週の訪問を 1 つの予定にできる。毎日も表せる。規則の変更の決まりがそのまま当たる | 毎月の複数の日と第 1 と第 3 の曜日は表せない。作った後は回数ではなく終了日で出る |
| 間隔を毎週と隔週だけにする | 画面の選択が 2 つで済む | 3 週ごと、4 週ごとの Google の予定を取り込めない。実装の手間は任意の間隔と変わらない |
| 回数を規則に持つ | Google と Outlook の回数をそのまま持てる | 規則の変更で分けた後の残りの回数の決まりが要る |
| 毎日、毎年、毎月の間隔も足す | Google と Outlook の頻度を全て持てる | 訪問で要る例が無い。毎日は毎週で表せる |
| 月曜に始まる週で隔週を数える | RFC 5545 の `WKST` のデフォルトと同じになる | 予定のカレンダーの週とずれる |
| 規則を RRULE の文字列で持つ | Google の規則をそのまま持てる | 検証、回を求める処理、画面の規則の欄が全て RRULE を読む必要がある |

## Consequences

### Positive

- 週に 2 回と隔週の訪問を、1 つの繰り返しの予定で作り、変えられる。
- 既にある繰り返しの予定の回と照合の結果は変わらない。

### Negative

- 予定の API の `RecurringRule` の形が変わる。毎週の曜日が配列になり、画面と同時に変える必要がある。
- 回数で作った予定も、作った後は終了日で出る。回を除いても終了日は延びない。
- 毎月の第 1 と第 3 の火曜のような訪問は、繰り返しの予定を 2 つ作る。
- 複数の曜日と間隔を足す前のバージョンへ切り戻すと、そのバージョンは複数の曜日と隔週の予定を、最初の日付の曜日の毎週として出す。この制約は、利用者が許した。
  - DB の制約で書き込みは失敗しない。前のバージョンが規則を書き換えた行は、元のままの曜日の並びと間隔を外す。
  - 前のバージョンが親の予定を Google カレンダーに書き出し直すと、Google の RRULE も最初の日付の曜日の毎週に戻ることがある。切り戻した後は、複数の曜日と隔週の予定の回を確認し、必要なら作り直す。
- #892 で規則の変更の画面が複数の曜日と間隔を選べるようになるまでは、画面は曜日を 1 つだけ選び、間隔は元の規則のまま送る。隔週の月曜と木曜で木曜を選ぶと、隔週の木曜になる。選択肢の文言は送る規則に合わせ、「隔週 木曜日」「3 週ごと 木曜日」と、今の規則の「隔週 月曜日、木曜日」を出す。この制約は、利用者が決めた。
