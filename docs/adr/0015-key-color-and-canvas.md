# ADR-0015: キーの色を light-blue にし、画面の地だけ DADS に無い値を持つ

## Status

承認

## Context

buddy のもともとのデザイン案は、くすんだ青（`#4d89c0`）を主の色にし、画面の地をわずかに温かい白（`#fdfcfb`）にしている。  
[ADR-0004](0004-design-system.md) は、意味のトークンを DADS の基本のトークンへの参照だけにし、主の色を DADS のキーの色の blue-800 にした。  
主の色を、もともとのデザイン案の印象に寄せることにした。この ADR は、ADR-0004 の次の 2 つの判断を置き換える。

- 意味のトークンには値を書かない。
- 主の色を、キーの色の blue-800 にする。

決定に関わる事実は次のとおり。

- もともとのデザイン案の青は、白の文字を載せると 4.5:1 に届かない。
- DADS は、キーの色をサービスごとに選ぶ前提で `--color-key-*` を置き、何も選ばなければ blue の階調を当てている。
  - 出典: [DADS のカラー](https://design.digital.go.jp/dads/foundations/color/)
- DADS の light-blue-800 は、もともとのデザイン案の青と色相がほぼ同じで、白の文字で 4.5:1 以上になる。
- DADS の基本のトークンには、温かい白の値が無い。白の次に明るい灰色は solid-gray-50 で、白との差が `#fdfcfb` より大きい。

## Decision

### キーの色を light-blue に当て直す

`semantic.css` で、DADS の `--color-key-50` から `--color-key-1200` を、同じ段の light-blue に当て直す。  
`primary` と `primary-surface` は、今までどおり key の 800 と 50 を参照する。  
キーの色を参照するほかの箇所（文書のサイトのアクセントの色）も、同じ色相にそろう。

### 画面の地の `surface-canvas` だけ、DADS に無い値を持つ

`surface-canvas` に `#fdfcfb` を直に書き、`body` の地にする。カード、表、入力欄、ダイアログ、ヘッダーは `surface`（白）のままにする。  
白との差は小さく、文字と線のコントラストは白の上とほぼ変わらない。`contrast.test.ts` で、canvas の上の文字と線の組を確かめる。  
値を直に持つトークンは `surface-canvas` だけにし、ほかの意味のトークンは ADR-0004 のとおり参照だけにする。

## Considered Options

| 選択肢 | 強み | 弱み |
| --- | --- | --- |
| **採用:** キーの色を light-blue に当て直し、canvas だけ値を持つ | もともとのデザイン案の色相と地に近い。キーの色を参照する箇所がそろって変わる | 意味のトークンに値を持つ例外が 1 つできる |
| `primary` だけ light-blue の原色を参照し、キーの色は blue のまま | 変更が `primary` の 2 行で済む | キーの色を参照する文書のサイトのアクセントが blue のまま残り、ホバーで色相が変わる |
| もともとのデザイン案の `#4d89c0` をそのまま使う | もともとのデザイン案と同じ色になる | 白の文字で 4.5:1 に届かず、ボタンの文字に使えない |
| 地を白か solid-gray-50 にする | DADS の値だけで済む | 白はもともとのデザイン案の地と違う。solid-gray-50 は灰色が強く、カードとの差が大きすぎる |

## Consequences

### Positive

- 主のボタン、リンク、選択、文書のサイトのアクセントが、もともとのデザイン案と同じ色相にそろう。
- 主の色のコントラストは、白の文字で 4.5:1 以上を保つ。

### Negative

- DADS の値を変えても、`surface-canvas` は追従しない。DADS のバージョンを上げるときに、canvas の上のコントラストを確かめる。
- 背景を指定しない要素は canvas の色になる。白にする要素には `bg-surface` を付ける。
