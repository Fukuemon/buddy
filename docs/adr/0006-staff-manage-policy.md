# ADR-0006: 職員と利用者の登録と、職員の権限と役職を変える操作を、職員の管理の権限で許す

## Status

承認

## Context

ADR-0002 は、職員が扱える予定の範囲を 7 つの権限で決め、管理者が職員ごとに権限を足し外せると決めた。誰が権限を足し外せるか、誰が役職を変えられるかは決めていない。

- PRD は、利用者と職員の登録と編集を、役職がマネージャーの職員だけに許すとしている（仮決定）。
- 権限の context は、判定に役職を直接使わず、職員の権限（`user_policies`）だけを読むと決めている。
- 権限を足し外す操作と役職を変える操作は、職員が自分に権限を足すことを許すと、予定の判定の意味が無くなる。

## Decision

8 つ目の権限として、職員の管理（`staff.manage`）を `policies` に足す。対象を指定しない権限（`needs_target` が false）で、マネージャーの役職の既定にする。職員と利用者の登録、役職の作成、職員の権限を足し外す操作、役職を変える操作は、この権限を持つ職員だけに許す。役職の作成を含めるのは、役職に既定の権限を付けると、その役職の職員に権限を配れるためである。

- 役職ではなく権限で判定するので、権限の context の禁止に合う。
- 予定の権限とは範囲が違うので、予定の 7 つの権限の判定の規則は変えない。ただし、職員の管理の権限を持つ職員は、自分を含む職員に任意の権限を足せるので、事実上の最上位の権限である。自分への付与は止めない。

## Considered Options

| 選択肢 | 強み | 弱み |
| --- | --- | --- |
| **採用:** 職員の管理の権限を足す | 判定が `user_policies` だけを読むまま、マネージャー以外にも職員ごとに許せる | 権限が 8 つになり、PRD の表と既定を直す |
| 役職がマネージャーの職員に許す | 表を変えない | 判定に役職を使い、権限の context の禁止に反する。役職の名前は事業所ごとに違う |
| 事業所の全ての予定の編集の権限を持つ職員に許す | 権限を足さない | 予定の権限を、職員の管理という別の範囲に流用する |
| 事業所の職員なら誰でも許す | 判定が要らない | 職員が自分に全ての権限を足せる |

## Consequences

### Positive

- 職員の管理を、役職によらず職員ごとに与えられる。

### Negative

- 事業所で職員の管理の権限を持つ最後の職員が、それを失うと、その事業所で権限を足し外せる職員がいなくなる。外す操作のほか、その職員の役職を変えて既定を写し直したときにも起きる。止めないので、戻すには DB で `user_policies` に行を足す。
