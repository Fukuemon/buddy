# ADR-0037: 繰り返しの予定の規則の変更を、適用の日以降の回にだけ当て、繰り返しの予定を適用の日で分ける

## Status

承認

## Context

職員は、繰り返しの予定の規則（頻度、曜日、日、週、終了日）を buddy の画面から変える必要がある。
予定の API には、繰り返しの予定の作成と、1 回だけの置き換えの操作しか無い。

決定に関わる事実は次のとおり。

- 繰り返しの予定は、最初の日付と規則で回を決め、回を保存しない。最初の日付は規則の回に当たる必要がある。
- 照合の API は、Google カレンダーの回を読む。`buddy_primary` の事業所でも、書き出した Google の予定を読む。過去の回を変えると、過去の月の照合の入力が変わる。
- 1 回だけ変えた回と取り消した回（例外の回）は、`buddy_primary` では除外の日と単発の予定で、`google_primary` では Google の例外の回で持つ（[ADR-0029](0029-google-calendar-sync.md)）。
- Google の公式の文書は、親の予定の `recurrence` を変えたときに例外の回がどうなるかを書いていない。「これ以降」の変更を回ごとの変更で行わないようにとだけ書く。
  - 出典: [Recurring events の Access instances](https://developers.google.com/workspace/calendar/api/guides/recurringevents)

## Decision

規則の変更は、職員が選んだ日（適用の日）以降の回にだけ当てる。両方の正本のモードで同じ規則にする。この規則は、利用者が選んだ。

- 適用の日は、今日（Asia/Tokyo）以降に限る。過去の回と、その照合の入力を変えないためである。
- 元の繰り返しの予定の終了日を適用の日の前の日にし、適用の日以降に新しい規則の繰り返しの予定を作る。
  - 新しい繰り返しの予定の最初の日付は、適用の日以降で新しい規則が当たる最初の日にする。
  - 時刻、職員、訪問の情報は、元の繰り返しの予定から写す。規則のほかの項目は、この操作では変えない。
- 元の繰り返しの予定に、適用の日より前の回が無いときは、分けずに規則と最初の日付を書き換える。
  - `google_primary` では、新しい親の予定を作って元の親の予定を消すので、ID が変わる。元の親の RRULE を書き換えたときに Google が取り消した例外の回を残すかは公式の文書に無く、残すと新しい規則の回が隠れるためである。
- 終了日だけを変えるときは、分けずに終了日を書き換える。新しい終了日は、今日の前の日以降にする。
- 適用の日以降（終了日だけの変更では新しい終了日の後）の例外の回は、次のとおりに扱う。
  - 置き換えた回とキャンセルした回の単発の予定は、単発の予定として残す。職員が日時を移した訪問を失わないためである。
  - 取り消した回は、新しい規則に引き継がない。取り消しは元の規則の日に付いたものである。
  - `google_primary` では、変えた例外の回を、同じカレンダーの単発の予定に作り直してから消す。Google が例外の回を残すか消すかによらず、同じ結果にするためである。
- 繰り返しの予定の全体の取り消しは持たない。ある日以降の訪問をやめるのは、終了日の変更で行う。

## Considered Options

| 選択肢 | 強み | 弱み |
| --- | --- | --- |
| **採用:** 適用の日以降の回に当て、繰り返しの予定を適用の日で分ける | 過去の回と照合の入力が変わらない。Google カレンダーの画面の「これ以降の予定」と同じ形になる | 繰り返しの予定が 2 つになり、新しい方は新しい ID を持つ。`google_primary` では親の予定を 2 つ書く |
| 全ての回に当て、同じ繰り返しの予定の規則を書き換える | 1 つの行と 1 つの親の予定を書き換えるだけで済む | 過去の回が変わり、過去の月の照合の入力が変わる |
| 2 つの案を職員が選ぶ | 誤って作った規則も直せる | 画面と API の分岐が増え、全ての回に当てる案の弱みが残る |
| 適用の日以降の例外の回を全て捨てる | 結果が新しい規則だけで決まる | 職員が移した訪問と、回で変えた訪問の情報が消える |
| 適用の日以降に例外の回があれば拒む | 職員が知らないうちに消える回が無い | 例外の回を 1 つずつ取り消してからでないと規則を変えられない |

## Consequences

### Positive

- 規則を変えても、今日より前の回と照合の結果は変わらない。
- `google_primary` の例外の回の扱いが、Google の未確認の動きに左右されない。

### Negative

- 規則を変えた繰り返しの予定は、適用の日で 2 つの繰り返しの予定になる。画面は、変更の応答の ID で新しい繰り返しの予定を読む。
- 終了日を早めて訪問をやめるとき、新しい終了日の後の置き換えた回は単発の予定として残り、職員がキャンセルする。
- 誤って作った繰り返しの予定の過去の回は、この操作では直せない。
