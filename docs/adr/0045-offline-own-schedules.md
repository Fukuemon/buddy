# ADR-0045: 電波の無い場所では、画面が IndexedDB に残したログインした職員の最後の週の予定だけを出し、セッションの期限、ログアウト、401 で消す

## Status

承認

## Context

外で訪問する職員が、電波の無い場所でも、最後に開いた週の予定を確認できるようにする。ログアウトした後は、端末に予定と利用者の名前を残さない（#837）。

- service worker は、データを含まないファイルだけを保存し、予定のデータを持たない。
  - ADR-0044: [web を、マニフェストと手で書いた service worker でホーム画面から開ける web アプリにし、service worker にはデータを含まないファイルだけを保存させる](0044-home-screen-web-app.md)
- web のセッションは、ログインから 12 時間で切れ、refresh でも延びない。上流の IdP で止めたアカウントを 12 時間で切るためである。
  - ADR-0001: [認証を OIDC のブローカーと BFF のサーバー側のセッションにし、職員の身元をブローカーが、権限と業務のデータを予定の API が持つ](0001-auth.md)
- 休職と退職では、ブローカーが Hydra のセッションと refresh token を取り消す。
  - ADR-0004: [職員の停止を、戻せる休職と、戻せない退職に分ける](0004-staff-leave-and-retirement.md)
- 予定は、日をまたいで翌日の朝まで続くことがある。
  - ADR-0033: [日をまたぐ予定を、開始の日の予定に「終了が翌日か」の印を付けて持ち、取り込み、カレンダー、照合で扱う](0033-overnight-schedule.md)
- 今のログアウトは、サーバーのセッションと cookie を消すだけで、端末には何も残していない。画面は、セッションの期限を知らない。
- 予定には、利用者の名前と、予定の説明が入る。

## Decision

画面が、ログインした職員の最後に開いた週の予定を IndexedDB に残し、電波の無いときにそれだけを出す。

- 残すのは、ログインした職員が職員である予定だけにする。予定の一覧を職員の 1 人に絞って取ったときと同じ予定である。ほかの職員の予定は、チームで絞って開いていても残さない。端末に残る利用者の名前を減らすためである。
- 予定の説明は残さない。時刻、種類、タイトル、利用者の名前のように、予定の一覧に出す項目だけを残す。
- 残す週は、職員が予定の画面で最後に開いた週である。週を移るたびに置き換え、1 週分だけを持つ。
- 残した予定は、ログインした職員、残した時刻、web のセッションの期限と一緒に持つ。
- 次のときに消す。
  - web のセッションの期限を過ぎたとき。電波の無いときも、端末の時計で期限を過ぎたものは出さずに消す。
  - 職員がログアウトするとき。画面が消してから `POST /auth/logout` を送り、ログアウトの応答にも `Clear-Site-Data: "storage"` を付ける。
  - BFF から 401 を受けたとき。
  - 残した職員と、ログインした職員が違うとき。
- 画面がセッションの期限を知れるよう、ログインした職員の値に web のセッションの期限を足す。
- 電波の無いときは、残した職員を root の route の `beforeLoad` の職員として使い、ADR-0044 の HTML の殻から予定の画面を開く。予定の作成、変更、キャンセルは出さない（#837 の範囲外）。

## Considered Options

| 選択肢 | 強み | 弱み |
| --- | --- | --- |
| **採用:** web のセッションの期限まで残す | ADR-0001 の 12 時間とそろう。休職と退職で止めた職員の端末に、長く残らない | 前の日に開いた予定は、次につながるまで出ない |
| ログアウトするまで残す | 前の日の予定も出る | ログアウトしない職員の端末に、利用者の名前が残り続ける。止めた職員の端末にも残る |
| 端末の日付が変わったら消す | 分かりやすい | 日をまたぐ予定（ADR-0033）が、途中で消える |
| 電波の無いときだけの専用の画面に出す | 今の画面に手を入れない | 予定の一覧の描き方が 2 つになる |

## Consequences

### Positive

- 電波の有無で、予定の画面が同じ見た目になる。
- 端末に残る利用者の名前は、職員自身の 1 週分の予定に限られ、長くても 12 時間で消える。

### Negative

- ログアウトせずにセッションが切れたときと、休職と退職でセッションを取り消したときは、端末の予定が期限まで残る。電波の無い端末を、サーバーから消せないためである。
- root の route の `beforeLoad` と、401 でログインへ移す処理に、電波の無いときの分岐が要る。
- iOS の Safari が `Clear-Site-Data` を IndexedDB に当てるかは確認していない。画面が先に消すので、当たらなくても消える。
