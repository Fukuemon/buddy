# ADR-0045: 電波の無い場所では、画面が IndexedDB に残したログインした職員の最後の週の予定だけを出し、セッションの期限、ログアウト、401 で消す

## Status

承認

## Context

外で訪問する職員が、電波の無い場所でも、最後に開いた週の予定を確認できるようにする。ログアウトした後は、端末に予定と利用者の名前を残さない（#837）。

- service worker は、データを含まないファイルだけを保存し、予定のデータを持たない。
  - ADR-0044: [web を、マニフェストと手で書いた service worker でホーム画面から開ける web アプリにし、service worker にはデータを含まないファイルだけを保存させる](0044-home-screen-web-app.md)
- web のセッションは、web でログインしてから 12 時間で切れ、refresh でも延びない。上流の IdP で止めたアカウントを 12 時間で切るためである。
  - ADR-0001: [認証を OIDC のブローカーと BFF のサーバー側のセッションにし、職員の身元をブローカーが、権限と業務のデータを予定の API が持つ](0001-auth.md)
- 休職と退職では、ブローカーが Hydra のセッションと refresh token を取り消す。
  - ADR-0004: [職員の停止を、戻せる休職と、戻せない退職に分ける](0004-staff-leave-and-retirement.md)
- 予定の API は、翌日に終わる予定に `ends_next_day` を付けて返す。
- セッションの期限は Valkey のキーの期限にだけあり、セッションの値はログインの時刻を持たない。今のログアウトは、サーバーのセッションと cookie を消すだけで、端末には何も残していない。
- 狭い幅の予定の画面は、日の表示から始まる。
- 予定には、利用者の名前と、予定の説明が入る。

## Decision

画面が、ログインした職員の最後に開いた週の予定を IndexedDB に残し、ネットワークに届かないときにそれだけを出す。

- 残すのは、ログインした職員が職員である予定だけにする。予定の一覧を職員の 1 人に絞って取ったときと同じ予定である。ほかの職員の予定は、チームで絞って開いていても残さない。端末に残る利用者の名前を減らすためである。
- キャンセルした予定は残さない。予定の画面が、ふだんキャンセルした予定を出さないためである。
- 残す項目は、予定の画面に出す項目から、予定の説明を除いたものにする。
- 残す週は、職員が予定の画面で最後に開いた日を含む週である。日、週、月のどの表示で開いても、その日を含む週を取って残す。週が変わるたびに置き換え、1 週分だけを持つ。
- 残した予定は、ログインした職員、残した時刻、web のセッションの期限と一緒に持つ。
- 次のときに消す。
  - web のセッションの期限を過ぎたとき。ネットワークに届かないときも、端末の時計で期限を過ぎたものは出さずに消す。
  - 職員がログアウトするとき。画面が消してから `POST /auth/logout` を送り、ログアウトの応答にも `Clear-Site-Data: "storage"` を付ける。
  - BFF（予定の API と照合の API のどちらの呼び出しでも）から 401 を受けたとき。
  - 残した職員と、ログインした職員が違うとき。
- 画面がセッションの期限を知れるよう、web のセッションにログインの時刻を持たせ、ログインした職員の値に期限を足す。
- ネットワークに届かないときは、残した職員を root の route の `beforeLoad` の職員として使い、ADR-0044 の HTML の殻から予定の画面を開く。予定の作成、変更、キャンセルの操作は出さない（#837 の範囲外）。
- 共用の端末のために、端末に残さない設定は作らない。共用の端末では、ログアウトで消える。

## Considered Options

| 論点 | 選択肢 | 強み | 弱み |
| --- | --- | --- | --- |
| 残す場所 | **採用:** 画面が IndexedDB に残す | service worker が業務のデータを持たない。消す処理を画面の 1 か所に置ける | 画面に、残す、出す、消す処理が要る |
| 残す場所 | service worker が API の応答を残す | 画面に手を入れない | 画面のデータの呼び出しは POST で、Cache API に残せない。server function の ID はビルドごとに変わる |
| 残す期間 | **採用:** web のセッションの期限まで | ADR-0001 の 12 時間とそろう。休職と退職で止めた職員の端末に、長く残らない | 前の日に開いた予定は、次につながるまで出ない |
| 残す期間 | ログアウトするまで | 前の日の予定も出る | ログアウトしない職員の端末に、利用者の名前が残り続ける。止めた職員の端末にも残る |
| 残す期間 | 端末の日付が変わるまで | 分かりやすい | 翌日に終わる予定が、途中で消える |
| 出す画面 | **採用:** 今の予定の画面 | 電波の有無で同じ画面になる | root の route の `beforeLoad` と 401 の処理に、ネットワークに届かないときの分岐が要る |
| 出す画面 | 電波の無いときだけの専用の画面 | 今の画面に手を入れない | 予定の一覧の描き方が 2 つになる |

## Consequences

### Positive

- 電波の有無で、予定の画面が同じ見た目になる。
- 端末に残る利用者の名前は、職員自身の 1 週分の予定に限られ、最後に web でログインしてから 12 時間で消える。

### Negative

- 期限より前にサーバーでセッションが消えたとき（Hydra が refresh token を拒んだとき、休職、退職）も、ネットワークに届かない端末の予定は期限まで残る。ネットワークに届かない端末を、サーバーから消せないためである。
- 期限は端末の時計で判定するので、端末の時計を戻すと長く出せる。
- Hydra がログインを覚えている間に web だけでログインし直すと、新しいセッションの期限まで、さらに 12 時間残る。
- ログアウトの `Clear-Site-Data: "storage"` は、IndexedDB と一緒に service worker と殻も消す。次にネットワークに届いたときに入れ直す。
- iOS の Safari が `Clear-Site-Data` を IndexedDB に当てるか、リダイレクトの応答で処理するかは確認していない。画面が先に消すので、当たらなくても消える。
