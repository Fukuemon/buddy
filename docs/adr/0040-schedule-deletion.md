# ADR-0040: 誤って入れた予定を、キャンセルと別の削除で消し、開始の日が今日以降の有効な予定に限り、監査の記録だけを残す

## Status

承認

## Context

職員は、誤って入れた予定を、業務上の取り消し（キャンセル）と別の操作で消す必要がある。
今の予定の API には、理由を付けて戻せないキャンセルしか無く、誤って入れた予定もキャンセルで消している。
`buddy_primary` の事業所では、キャンセルした予定とその理由の一覧に、業務上の取り消しと入力の誤りが並び、区別できない。

決定に関わる事実は次のとおり。

- 予定の編集の可否は、予定の職員に対する編集の権限（`schedule.self.edit`、`schedule.user.edit`、`schedule.team.edit`、`schedule.all.edit`）で判定する。キャンセルも同じ判定である。
  - ADR-0007: [権限を役職のデフォルトと職員ごとの上書きで持ち、職員の管理と照合も権限で許す](0007-pbac.md)
- 予定のテーブルにもキャンセルのテーブルにも、操作した職員の列が無い。誰が作ったか、誰がキャンセルしたかは残らない。
- 照合の API は、予定を予定の CSV か Google カレンダーから月ごとに読み、入力の CSV と照合の結果を保存しない。`buddy_primary` の事業所でも、書き出した Google の予定を読む。buddy は実績を持たないので、予定に実績が付いたか、照合に使ったかを判定できない。
- 繰り返しの規則の変更は、今日より前の回を変えない。照合が読む過去の回を変えないためである。
  - ADR-0037: [繰り返しの予定の規則の変更を、適用の日以降の回にだけ当て、繰り返しの予定を適用の日で分ける](0037-recurring-rule-change.md)
- 繰り返しの予定の全体は取り消さず、ある日以降の訪問をやめるのは終了日の変更で行う（ADR-0037）。
- `google_primary` の事業所のキャンセルは、Google の予定を消し、理由を保存せず、キャンセルした予定を一覧に出さない。キャンセルと入力の誤りを一覧で区別できない問題は、`buddy_primary` の事業所だけで起きる。
  - ADR-0029: [Google カレンダーとの連携を、事業所ごとの正本のモードで分ける](0029-google-calendar-sync.md)
- `buddy_primary` の事業所の予定の作成、変更、キャンセルは、書き出しで職員の Google カレンダーに書く。回のキャンセルは、親の予定の `EXDATE` にする（ADR-0029）。

## Decision

キャンセルと別に、予定の削除を足す。削除は「誤って入れた予定を、無かったことにする」操作で、理由を持たない。この ADR の 1〜7 の規則は、全て利用者が選んだ。

1. 削除できるのは、予定を編集できる職員である。判定はキャンセルと同じにする。誤入力を直す職員は予定を直す職員と同じで、作った職員の記録は今の予定に無いためである。押し間違いは、キャンセルと別の文言と別の確認で防ぐ。
2. 削除できるのは、開始の日が今日（Asia/Tokyo）以降の予定だけである。照合が読む過去の予定を変えないためで、ADR-0037 の規則の変更と同じ線にする。過去の誤入力は、キャンセルで残す。
3. 削除した予定は、予定の一覧、取得、照合、書き出しの対象に出さず、戻せない。誰が、いつ、どの予定を、消した時点のどの内容で消したかを、監査の記録に残す。監査の記録は画面に出さない。訪問の予定は利用者の訪問に関わり、後から経緯を問われることがあるためである。消せるのは今日以降の予定だけなので、戻す代わりに入れ直せば足りる。
4. 繰り返しの予定は、回を 1 回だけ削除できる。回の削除は、その日を除外する日に足すだけで、単発の予定を作らない。繰り返しの予定そのもの（ある日以降と全体）は削除しない。ある日以降をやめるのは、ADR-0037 の終了日の変更で行う。
5. `google_primary` の事業所では、削除の操作を出さず、予定の API も削除を拒む。今のキャンセルが Google の予定を消すまま残す。区別できない問題が起きず、Google の正本に無い区別を buddy にだけ持つと、Google で消した予定と buddy で消した予定の扱いが分かれるためである。事業所が `buddy_primary` に切り替えた後に、削除が使える。
6. キャンセルした予定は削除できない。消せるのは有効な予定だけである。キャンセルは戻せない業務の記録で、削除で消せるとキャンセルの一覧を信用できなくなるためである。回をキャンセルした単発の予定も同じである。
7. 回を置き換えた予定を削除しても、元の回に戻さない。その日は除外する日のまま残り、その日の予定が無くなる。削除を「予定を消す」の 1 つの意味にそろえるためで、変更の誤りは変更で直す。

`buddy_primary` の事業所では、書き出しが削除をキャンセルと同じく Google に書く。単発の予定の削除は Google の予定を消し、回の削除は親の予定の `EXDATE` にする。照合の API が書き出した Google の予定を読むので、消さないと削除した予定が照合に残るためである。

## Considered Options

### 誰が削除できるか

| 選択肢 | 強み | 弱み |
| --- | --- | --- |
| **採用:** 予定を編集できる職員 | 代わりに入れた事務やマネージャーも直せる。判定と画面の出し分けがキャンセルとそろう | 作った本人でない職員も消せる |
| 予定を作った職員だけ | 入れた本人の判断に限られる | 作った職員の列を足す必要があり、今ある予定に当てられない。本人が休職か退職すると誰も消せない |
| 職員の管理の権限を持つ職員だけ | 押し間違いが減る | 誤入力のたびに管理者に頼む |

### いつまでの予定を削除できるか

| 選択肢 | 強み | 弱み |
| --- | --- | --- |
| **採用:** 開始の日が今日以降の予定だけ | 照合で読む過去の予定が変わらない。今日の日付だけで判定できる | 過去の日付で誤って入れた予定は消せず、キャンセルで残る |
| 作ってから一定の時間の内 | 入れた直後の誤りは、過去の日付でも消せる | 時間を過ぎると未来の予定でも消せない。`google_primary` では作った時刻の数え方を決める必要がある |
| 期限を設けない | どの誤入力も消せる | 照合した月の予定も消せ、照合し直すと前の結果と食い違う |

「実績が付く前まで」と「照合に使う前まで」は、buddy が実績も照合の結果も保存しないので判定できず、選べない。

### 消した記録を残すか

| 選択肢 | 強み | 弱み |
| --- | --- | --- |
| **採用:** 監査の記録だけを残し、画面に出さず戻せない | 後で経緯を DB から答えられる。職員の画面は簡単なまま | 消し間違いは入れ直す |
| 期限付きで戻せる | 消し間違いを職員が戻せる | 戻すときに、同じ時間の予定、除外する日、Google の予定との整合を見直す操作が要る |
| 残さない | 最も単純 | 誰が消したかが後から分からない |

### 繰り返しの予定の扱い

| 選択肢 | 強み | 弱み |
| --- | --- | --- |
| **採用:** 回を 1 回だけ削除でき、繰り返しの予定そのものは削除しない | ADR-0037 の判断を変えない。回のキャンセルと同じく除外する日で表せる | 誤って作った繰り返しは、最初の回の削除と終了日の変更で消す |
| 単発の予定だけを削除でき、回は削除できない | 変更が最も小さい | 繰り返しの 1 回分の誤りがキャンセルで残る |
| 全ての回が今日以降の繰り返しの予定を、全体で削除できる | 誤って作った繰り返しをまとめて消せる | ADR-0037 の全体を取り消さない判断を、誤入力に限って変える |

### `google_primary` の事業所での扱い

| 選択肢 | 強み | 弱み |
| --- | --- | --- |
| **採用:** 削除の操作を出さず、今のキャンセルを残す | 区別できない問題が起きていない事業所の操作を変えない | 事業所のモードで、出る操作が違う |
| 削除を出し、Google の予定を消す。違いは buddy の監査の記録だけ | どの事業所でも同じ操作が出る | Google で直接消した予定は記録に残らず、記録が一部になる |
| 削除だけを出し、キャンセルを出さない | 今のキャンセルの動きに名前を合わせる | 今のキャンセルの操作を変える |

### キャンセルした予定と置き換えた回

| 選択肢 | 強み | 弱み |
| --- | --- | --- |
| **採用:** キャンセルした予定は削除できず、置き換えた回を削除しても元の回に戻さない | キャンセルの記録を削除で消せない。削除の意味が 1 つになる | 今までキャンセルで代わりに消した誤入力は片付けられない |
| キャンセルした予定も削除できる | 今までの誤入力を片付けられる | 業務上のキャンセルも消せる |
| 置き換えた回を削除すると、元の回に戻す | 変更の誤りを 1 回の操作で戻せる | 消したのに元の予定が出る |

## Consequences

### Positive

- `buddy_primary` の事業所のキャンセルした予定の一覧が、業務上の取り消しだけになる。
- 照合が読む過去の予定は、削除で変わらない。
- 誰が、いつ、何を消したかを、後から DB で答えられる。

### Negative

- 開始の日が今日の予定は、訪問を終えた後でも削除できる。今日の照合の前に消すと、その訪問は照合で「実績のみ」になる。
- 過去の日付の誤入力と、今までキャンセルで代わりに消した誤入力は、キャンセルとして残る。
- `google_primary` の事業所の職員には削除が出ず、事業所のモードで操作が違う。
- 予定の API は、監査の記録を新しく持つ。
