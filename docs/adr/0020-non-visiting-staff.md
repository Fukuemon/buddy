# ADR-0020: 訪問するかを職員に持ち、訪問しない職員を予定と担当から外す

## Status

承認

## Context

職員が訪問するかを、どこに持ち、訪問しない職員をどう扱うかを決める必要がある。

- 事業所で照合をするのは事務の職員で、事務の職員は訪問せず、照合の食い違いを予定表で直す。
- 役職は、職員に付ける権限のデフォルトだけを持つ。役職を変える操作は、役職のデフォルトの権限を職員にコピーし直す。
  - ADR-0002: [権限を役職のデフォルトと職員ごとの上書きで持ち、職員の管理と照合も権限で許す](0002-pbac.md)
- 予定の API は、休職と退職の職員への新しい割り振りを拒み、退職の前にその日以降の予定、繰り返しの予定、担当の利用者を一覧で示す。
  - ADR-0018: [職員の停止を、戻せる休職と、戻せない退職に分ける](0018-staff-leave-and-retirement.md)

## Decision

職員に「訪問するか」を持たせる。役職には持たせない。職員を登録するときの初期値は「訪問する」で、職員の管理の権限を持つ職員が変える。

- 理由: 役職のデフォルトにすると、役職を変える操作が、予定と担当の扱いを変える操作を兼ねる。役職を変える操作は、権限だけをコピーし直す。
- 訪問しない職員は、予定のカレンダーの職員の列と絞り込みに出さず、予定の職員、主訪問者、同行者、利用者の担当の候補に出さない。
- 予定の API は、訪問しない職員への新しい割り振り（予定の作成、職員の変更、主訪問者と同行者の変更、利用者の担当の変更）を拒む。休職と退職の職員への割り振りを拒む規則と同じ形にする。
  - 理由: カレンダーに列が出ないので、訪問しない職員に予定を持たせても、誰からも見えない。
- 「訪問する」から「訪問しない」へ変えるときは、その日以降の予定、繰り返しの予定、担当の利用者を一覧で返し、一覧が空になるまで拒む。一覧の範囲は、退職の確認（ADR-0018）と同じである。
  - 理由: 誰も行かない訪問を残さないためである。
- 過去の予定は、職員を変えずに残す。過去の予定と照合の結果で、誰が訪問したかを読めるようにする。
- 「訪問しない」から「訪問する」へは、確認なしで変えられる。

## Considered Options

| 論点 | 選択肢 | 強み | 弱み |
| --- | --- | --- | --- |
| 訪問するか | **採用:** 職員に持つ | 役職を変えずに、訪問するかだけを変えられる | 職員を登録するたびに選ぶ。事務の職員を登録するときに変え忘れると、候補に出る |
| 訪問するか | 役職に持つ | 役職を付ければ決まる | 役職の変更が予定と担当の扱いを兼ね、同じ役職で訪問する職員としない職員を分けられない |
| 訪問しない職員の予定 | **採用:** 予定の職員にも指せない | カレンダーに出ない予定が生まれない | 事務の職員が、会議などの通常の予定を buddy で持てない |
| 訪問しない職員の予定 | 通常の予定だけ持てる | 事務の職員が自分の予定を入れられる | カレンダーに列が出ないので、入れた予定が見えない |
| 訪問しないへの変更 | **採用:** 残る予定と担当があれば拒む | 誰も行かない訪問が残らない | 変える前に割り振り直す手順が要る |
| 訪問しないへの変更 | 拒まずに警告を返す | 操作が 1 回で済む | 列が出ない職員の予定が残り、気付けない |

## Consequences

### Positive

- 事務の職員が、予定のカレンダーの列と、予定と担当の候補に出ない。

### Negative

- 事務の職員は、会議などの通常の予定を buddy で持てない。
- 事務の職員を登録するときに「訪問しない」に変え忘れると、カレンダーの列と候補に出る。
