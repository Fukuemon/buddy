# attach-evidence

エビデンスを付ける変更、元のファイルの配置先、写してよいデータは、`context/testing/evidence.md` が持つ。  
このスキルは、撮る、変換する、添付する、本文に書くときの判断だけを持つ。

## 始める前に読むもの

- `context/testing/evidence.md` の「エビデンスを付ける変更」と「格納先」
- 対応する issue の完了の条件と、pull request の差分

## 撮る観点を決める

観点は、変更の受け入れ条件から作る。推測で足さない。

- 観点と要件の文は、スキル design-test-cases で作る。入っていなければ、issue の完了の条件の項目ごとに 1 つの観点にする。
- 手動検証のシナリオ（前提、もし、かつ、ならば の文）があれば、観点はシナリオに従う。
- 1 本の動画には 1 つの観点だけを撮る。レビューする人が、観点と動画を 1 対 1 で読み合わせられる。
- 撮る観点の一覧を、撮る前に利用者に見せる。

## 撮る

エビデンスは、`packages/e2e/kit` の録画を呼ぶ Playwright の spec で撮る。  
spec の配置先、出力の配置先、撮るコマンド、ログインとテストデータの作り方は、`context/testing/evidence.md` の「エビデンスの spec」にある。  
spec の書き方は write-verification-spec に、流し方と撮った後の確かめ方は run-verification-scenarios に従う。

| 変更 | 開くもの |
| --- | --- |
| 手動検証のシナリオがある | 検証環境かローカルの compose の画面 |
| 画面の操作から API までを通す、API だけ | ローカルの compose の画面。API だけの変更は、その API を呼ぶ画面の操作で撮る |
| 画面の UI と見た目 | Storybook の story |
| 画面仕様書とモック | 画面仕様書のモック |

- 開く URL の作り方とスマートフォンの幅の渡し方は、`context/testing/evidence.md` の「Storybook、モック、スマートフォンの幅」にある。幅はコメントに書く。
- 既にある spec で撮れる観点は、spec を流し直すだけにする。無ければ、機能の spec に test を足す。
- agent-browser では、エビデンスを撮らない。録画のフレームが落ちることがあり、撮り直すときに同じ操作を再現できない。spec を書く前に、画面の操作の位置を確かめるのには使ってよい。

## mp4 に変換する

kit は H.264 の mp4 を書き出すので、変換しない。kit 以外で撮った WebM（ブラウザや画面の録画のアプリ）を添付するときだけ、次で変換する。

```sh
ffmpeg -i <名前>.webm -vf "scale=trunc(iw/2)*2:trunc(ih/2)*2" -c:v libx264 -pix_fmt yuv420p -movflags +faststart <名前>.mp4
```

`yuv420p` の H.264 は、幅か高さが奇数だと変換に失敗する。`-vf` の `scale` で偶数にそろえる。

## 添付する

`--attach` は gh の 2.99 以降にある。  
先に `gh --version` を確かめる。  
2.99 より古ければ、リポジトリの `mise.toml` の gh を `mise install` で入れ、`mise which gh` で表示されたパスの gh を使う。

- 観点ごとに、pull request のコメントに 1 本ずつ添付する。本文は、観点と撮った場所を 1 文から 2 文で書く。

  ```sh
  gh pr comment <番号> -b "エビデンス: <観点の文>。<撮った場所。story の名前、画面、幅>で撮った。spec は <spec のパス>。" --attach .ai-out/evidence/<番号>/<名前>.mp4
  ```

- 画像は `--attach '<パス>#<代替テキスト>'` で代替テキストを付ける。動画には代替テキストを付けられないので、コメントの文で中身を説明する。
- 本文に同じパスへの参照（`![代替テキスト](./<名前>.png)`）を書くと、gh がその参照を添付したファイルの URL に置き換える。参照の無いファイルは本文の末尾に付く。
- issue に添付するのは、不具合の再現と改修前の動きのように、pull request より先に示すものだけにする。`gh issue comment <番号> --attach` を使う。
- 一部の添付だけが失敗すると、gh は 0 以外で終わる。失敗したファイルは、次のどちらかで付け直す。
  - 同じコメントに足す: `gh pr comment <番号> --edit-last -b "<元の文>" --attach <失敗したファイル>`。`--edit-last` は本文を置き換えるので、付いた動画の URL も `-b` の文に残す。
  - 消して出し直す: `gh pr comment <番号> --delete-last --yes` で消し、全部のファイルを付けて出し直す。

## 本文の「確認したこと」に書く

- 観点ごとに 1 項目にし、確かめた結果を 1 文で書く。項目の入れ子に、その観点のエビデンスのコメントへのリンクを置く。
- 自動のテストとチェック（コマンドと結果）は、エビデンスの動画と別の項目に書く。
- 撮らなかった観点は「未実施」と理由を書く。

## 終えたら

- 添付した動画をコメントで開き、再生できることを確かめる。
- `.ai-out/evidence/<番号>/` の元のファイル（`<名前>.mp4` と `<名前>/`）のうち、自分が作ったものを消す。
- 利用者に、撮った観点と本数、エビデンスのコメントの URL、撮らなかった観点を伝える。
